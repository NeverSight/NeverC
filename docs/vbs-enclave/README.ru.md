# DLL VBS-анклавов в Windows

NeverC умеет компоновать совместимые с Microsoft DLL VBS-анклавов для 64-разрядных целевых платформ Windows. Поддерживается следующий контракт компоновщика:

```text
/DLL /INCREMENTAL:NO /INTEGRITYCHECK /ENCLAVE /GUARD:MIXED
```

Передавайте параметры компоновщика Microsoft через драйвер Windows с помощью `-Xmslink` или `-Wl,`:

```powershell
neverc.exe --target=x86_64-pc-windows-msvc -fno-lto -shared -nostdlib `
  enclave.obj guarded.obj legacy.obj `
  -lvertdll -lbcrypt -llibcmt -llibvcruntime -lucrt `
  -Xmslink /INCREMENTAL:NO `
  -Xmslink /NODEFAULTLIB `
  -Xmslink /ENCLAVE `
  -Xmslink /INTEGRITYCHECK `
  -Xmslink /GUARD:MIXED `
  -Xmslink /DYNAMICBASE `
  -Xmslink /MACHINE:X64 `
  -o game-security-enclave.dll
```

В этом примере варианты библиотек MSVC CRT и UCRT для анклавов выбираются явно с помощью `-l`. Любой явно заданный `-vctoolsdir` или `-winsysroot` сохраняет обычный приоритет. Без этих переопределений при любой компоновке с `/ENCLAVE` в macOS, Linux или Windows библиотеки Windows разрешаются только из целевой среды выполнения, входящей в комплект NeverC; драйвер не обнаруживает автоматически и не использует как резервный вариант установленные на хосте набор инструментов Visual Studio или Windows SDK.

## Межхостовые сборки со встроенной средой выполнения

Компиляция и COFF-компоновка не зависят от хоста. После установки целевой среды выполнения одну и ту же команду можно запускать в macOS, Linux или Windows:

```text
neverc runtime install windows-x64
neverc runtime install windows-arm64
```

Целевой пакет содержит заголовки Windows, CRT для анклавов, UCRT для анклавов, `vertdll.lib`, `bcrypt.lib` и другие необходимые библиотеки импорта Windows. При разрешении через среду выполнения из комплекта NeverC переключается с обычных комплектных каталогов CRT/UCRT на каталоги CRT/UCRT для анклавов только при сочетании явно заданного `/ENCLAVE` с глобальным `/NODEFAULTLIB`. В этом режиме перед компоновкой драйвер проверяет наличие всех комплектных файлов: `libcmt.lib`, `libvcruntime.lib`, `ucrt.lib`, `vertdll.lib` и `bcrypt.lib`. Библиотеки по-прежнему выбираются явно с помощью `-l...`. Один лишь `/ENCLAVE` не включает каталоги CRT/UCRT для анклавов и не выбирает их библиотеки; продолжают использоваться обычные пути поиска комплектной среды выполнения.

На межхостовом этапе компоновки создаётся неподписанная и необработанная DLL анклава. Обработка VEIID, подписание с помощью SignTool и фактическая загрузка через `CreateEnclave`/`LoadEnclaveImage` по-прежнему выполняются только в Windows, поэтому для последних трёх этапов перенесите DLL, скомпонованную в macOS или Linux, на машину Windows для упаковки или тестирования. Сведения об установке и обнаружении сред выполнения см. в разделе [Целевые среды выполнения](../runtime/README.ru.md).

## Обязательные входные данные образа

При компоновке анклава необходимо предоставить оба следующих определения данных образа:

- `__enclave_config`, содержащее данные `IMAGE_ENCLAVE_CONFIG` образа.
- `_load_config_used` со структурой load-config, размер которой достаточен для хранения `EnclaveConfigurationPointer`.

NeverC сохраняет `__enclave_config` при удалении неиспользуемого кода, при необходимости извлекает его из архива и проверяет, что окончательно перемещённый указатель load-config равен виртуальному адресу этого объекта конфигурации. Отсутствующее, абсолютное, отброшенное, усечённое или неправильно перемещённое определение приводит к ошибке компоновки.

`/GUARD:MIXED` включает вывод CFG для смеси защищённых и устаревших объектных файлов. Он создаёт пятибайтовые записи GFID и GIAT: четырёхбайтовый RVA и один байт метаданных; для текущих обычных целей метаданные равны нулю. В `GuardFlags` устанавливаются биты CFG и размера записи. Устаревшие объекты добавляют цели, адрес которых был получен, посредством консервативного сканирования перемещений с исключением метаданных раскрутки стека.
При совместном использовании `/GUARD:MIXED` и `/GUARD:EHCONT` таблица целей продолжения EH также содержит пятибайтовые записи: четырёхбайтовый RVA и следующий за ним нулевой байт метаданных.

Явный запрос инкрементальной компоновки несовместим с `/ENCLAVE` и отклоняется. Используется последний действующий параметр `/INCREMENTAL`, включая параметры из директив объектных файлов.

`/ENCLAVE` не выбирает неявно вывод DLL, CFG, проверку целостности, библиотеки CRT для анклавов, обработку VEIID или подписание. Явно задавайте эти решения в конвейере сборки. В режиме комплектной среды выполнения описанные выше пути поиска CRT/UCRT для анклавов и проверка пяти библиотек включаются только при явно заданном глобальном `/NODEFAULTLIB`; без этого параметра продолжают использоваться обычные пути комплектной среды выполнения Windows. Явные переопределения пользовательской цепочки инструментов сохраняют обычный приоритет.

## Процесс сборки и развёртывания

1. Компилируйте критичные для безопасности исходные файлы с включённым CFG, например с `-fms-guard=cf`. Устаревшие объекты могут оставаться неинструментированными, если при окончательной компоновке используется `/GUARD:MIXED`.
2. Определите конфигурацию и точку входа анклава, затем выполните компоновку с CRT/UCRT для анклавов и необходимыми библиотеками импорта Vertdll и BCrypt.
3. Проверьте неподписанный PE-образ и его каталог load-config, таблицы CFG, указатель конфигурации анклава и базовые перемещения.
4. В Windows запустите средство VEIID из Windows SDK для готового образа.
5. В Windows подпишите обработанный VEIID образ с помощью SignTool. Подписание должно быть последним изменением файла.
6. В хосте Windows проверьте `IsEnclaveTypeSupported(ENCLAVE_TYPE_VBS)`, выделите анклав с помощью `CreateEnclave`, загрузите DLL через `LoadEnclaveImage` и вызовите `InitializeEnclave`.

В античит-системах анклав подходит для небольшого компонента проверки или обработки ключей, коду и закрытому состоянию которого нужна более строгая граница с обычным процессом игры. Сохраняйте интерфейс анклава узким и проверяйте все предоставленные хостом данные: хост по-прежнему контролирует входные данные, планирование, хранение и доступность. VBS-анклав дополняет серверный авторитет, телеметрию, защиту драйвера и обычное усиление процесса, а не заменяет их.

## Проверка

Workflow `VBS enclave differential CI` выполняется в Windows. Его статический барьер:

- собирает компоновщик NeverC и целевые тесты COFF;
- создаёт эквивалентные DLL анклавов, скомпонованные Microsoft и NeverC;
- сравнивает публичную семантику PE/load-config/CFG;
- запускает мутационные тесты для проверяющего PE-инструмента;
- подготавливает обработанные VEIID образы для дифференциальной проверки во время выполнения.

Проверка во время выполнения сначала запускает образ Microsoft. Если на размещённом runner отсутствует VBS или пригодная среда подписания, результат явно отмечается как пропуск из-за окружения. После успешной загрузки эталонного образа Microsoft сбой любого из кандидатов NeverC считается безусловной ошибкой теста. Настроенный собственный VBS-runner позволяет сделать успешное выполнение обязательным барьером.

Компоновщик поддерживает COFF-образы анклавов x86-64 и ARM64. Он проверяет опубликованный указатель конфигурации, затем на основе окончательного набора обычных DLL-импортов формирует непрерывную последовательность 80-байтовых записей `IMAGE_ENCLAVE_IMPORT`. Изначально записи содержат только имя импорта, а поля идентичности равны нулю для привязки VEIID; компоновщик записывает число, список и размер записи. Активные импорты с отложенной загрузкой отклоняются. Компоновщик не накладывает дополнительных политик на версионированные поля внутри `IMAGE_ENCLAVE_CONFIG`.
