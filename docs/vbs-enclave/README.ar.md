# ملفات DLL لجيوب VBS على Windows

يستطيع NeverC ربط ملفات DLL لجيوب VBS متوافقة مع Microsoft لأهداف Windows ذات 64 بت. عقد الرابط المدعوم هو:

```text
/DLL /INCREMENTAL:NO /INTEGRITYCHECK /ENCLAVE /GUARD:MIXED
```

مرّر خيارات رابط Microsoft عبر برنامج تشغيل Windows باستخدام `-Xmslink` أو `-Wl,`:

```powershell
neverc.exe --target=x86_64-pc-windows-msvc -fno-lto -shared -nostdlib `
  enclave.obj guarded.obj legacy.obj `
  -lvertdll -lbcrypt -llibcmt -llibvcruntime -lucrt `
  -Xmslink /INCREMENTAL:NO `
  -Xmslink /NODEFAULTLIB `
  -Xmslink /ENCLAVE `
  -Xmslink /INTEGRITYCHECK `
  -Xmslink /GUARD:MIXED `
  -Xmslink /DYNAMICBASE `
  -Xmslink /MACHINE:X64 `
  -o game-security-enclave.dll
```

يختار هذا المثال صراحةً نسخ الجيوب من مكتبتي MSVC CRT وUCRT باستخدام `-l`. يحتفظ أي اختيار صريح لـ `-vctoolsdir` أو `-winsysroot` بأسبقيته المعتادة. عند عدم وجود هذين التجاوزين، تحل جميع عمليات الربط التي تتضمن `/ENCLAVE` على macOS أو Linux أو Windows مكتبات Windows من حزمة وقت تشغيل الهدف المرفقة مع NeverC فقط؛ ولا يكتشف برنامج التشغيل تلقائيًا مجموعة أدوات Visual Studio أو Windows SDK المثبتين على المضيف ولا يعود إليهما كخيار احتياطي.

## البناء عبر المضيفين باستخدام runtime المرفقة

لا تعتمد عملية التجميع وربط COFF على المضيف. يمكن تشغيل الأمر نفسه على macOS أو Linux أو Windows بعد تثبيت runtime الخاصة بالهدف:

```text
neverc runtime install windows-x64
neverc runtime install windows-arm64
```

تحتوي حزمة الهدف على ترويسات Windows وCRT الجيب وUCRT الجيب و`vertdll.lib` و`bcrypt.lib` ومكتبات استيراد Windows الأخرى المطلوبة. عند استخدام حزمة وقت التشغيل المرفقة للحل، لا ينتقل NeverC من دليلي CRT/UCRT العاديين المرفقين إلى دليلي CRT/UCRT الخاصين بالجيب إلا عند الجمع بين `/ENCLAVE` الصريح و`/NODEFAULTLIB` العام. في هذا الوضع، يتحقق برنامج التشغيل قبل الربط من وجود الملفات المرفقة `libcmt.lib` و`libvcruntime.lib` و`ucrt.lib` و`vertdll.lib` و`bcrypt.lib` جميعًا. تظل المكتبات محددة صراحةً باستخدام `-l...`. لا يفعّل `/ENCLAVE` وحده دليلي CRT/UCRT الخاصين بالجيب ولا يختار مكتبتيهما؛ بل يستمر في استخدام مسارات البحث العادية لحزمة وقت التشغيل المرفقة.

تنتج مرحلة الربط عبر المضيفين ملف DLL للجيب غير موقّع وغير معالج. تظل معالجة VEIID والتوقيع باستخدام SignTool والتحميل الفعلي عبر `CreateEnclave`/`LoadEnclaveImage` مقصورة على Windows، لذا انقل ملف DLL مربوطًا على macOS أو Linux إلى جهاز Windows للتغليف أو الاختبار من أجل المراحل الثلاث الأخيرة. راجع [بيئات تشغيل الهدف](../runtime/README.ar.md) لمعرفة طريقة تثبيت runtime واكتشافها.

## مدخلات الصورة المطلوبة

يجب أن يوفّر ربط الجيب تعريفي بيانات الصورة التاليين:

- `__enclave_config`، ويحتوي بيانات `IMAGE_ENCLAVE_CONFIG` الخاصة بالصورة.
- `_load_config_used`، مع بنية load-config كبيرة بما يكفي لاحتواء `EnclaveConfigurationPointer`.

يحافظ NeverC على `__enclave_config` أثناء إزالة التعليمات غير المستخدمة، ويستخرجه من أرشيف عند الحاجة، ويتحقق من أن مؤشر load-config بعد إعادة التموضع النهائية يساوي العنوان الافتراضي لكائن الإعداد ذلك. يؤدي التعريف المفقود أو المطلق أو المستبعد أو المبتور أو المعاد تموضعه بصورة خاطئة إلى خطأ ربط.

يفعّل `/GUARD:MIXED` مخرجات CFG لمزيج من ملفات الكائنات المحمية والقديمة. وهو يضم الأهداف المأخوذة العناوين التي جُمعت بصورة محافظة وتحتاج إليها الكائنات غير المحمية؛ وليس وضع تجهيز مستقلًا في المترجم ولا بتًا جديدًا في `GuardFlags` ضمن PE.

طلب الربط التزايدي الصريح غير متوافق مع `/ENCLAVE` ولذلك يُرفض. يُستخدم آخر خيار `/INCREMENTAL` فعّال، بما في ذلك الخيارات الواردة من توجيهات ملفات الكائنات.

لا يختار `/ENCLAVE` ضمنيًا إخراج DLL أو CFG أو فحص التكامل أو مكتبات CRT الخاصة بالجيب أو معالجة VEIID أو التوقيع. أبقِ هذه الخيارات صريحة في مسار البناء. في وضع حزمة وقت التشغيل المرفقة، لا تُفعّل مسارات البحث عن CRT/UCRT الخاصين بالجيب والتحقق من المكتبات الخمس الموضحان أعلاه إلا مع `/NODEFAULTLIB` عام وصريح؛ ومن دون هذا الخيار تستمر مسارات وقت تشغيل Windows العادية المرفقة. تحتفظ تجاوزات سلسلة الأدوات الصريحة للمستخدم بأسبقيتها المعتادة.

## مسار البناء والنشر

1. جمّع المصادر الحساسة أمنيًا مع تمكين CFG، مثلًا باستخدام `-fms-guard=cf`. يمكن أن تبقى الكائنات القديمة غير مجهّزة عندما يستخدم الربط النهائي `/GUARD:MIXED`.
2. عرّف إعداد الجيب ونقطة الدخول، ثم اربط مع CRT/UCRT الخاصتين بالجيب ومكتبات استيراد Vertdll وBCrypt المطلوبة.
3. افحص صورة PE غير الموقعة وتحقق من دليل load-config وجداول CFG ومؤشر إعداد الجيب وعمليات إعادة التموضع الأساسية.
4. على Windows، شغّل أداة VEIID من Windows SDK على الصورة المكتملة.
5. على Windows، وقّع الصورة التي عالجتها VEIID باستخدام SignTool. يجب أن يكون التوقيع آخر تعديل للملف.
6. في مضيف Windows، افحص `IsEnclaveTypeSupported(ENCLAVE_TYPE_VBS)`، وخصّص الجيب باستخدام `CreateEnclave`، وحمّل ملف DLL باستخدام `LoadEnclaveImage`، ثم استدعِ `InitializeEnclave`.

في أنظمة مكافحة الغش، يناسب الجيب مكوّن تحقق صغيرًا أو مكوّنًا لمعالجة المفاتيح يحتاج رمزه وحالته الخاصة إلى حد أقوى يفصلهما عن عملية اللعبة العادية. أبقِ واجهة الجيب ضيقة وتحقق من كل البيانات التي يزوّدها المضيف: فما يزال المضيف يتحكم في المدخلات والجدولة والتخزين والتوافر. يكمّل جيب VBS سلطة الخادم والقياس عن بُعد ودفاعات برنامج التشغيل وتقوية العملية المعتادة؛ ولا يحل محلها.

## التحقق

يعمل سير العمل `VBS enclave differential CI` على Windows. بوابته الثابتة:

- تبني رابط NeverC واختبارات COFF المركّزة؛
- تنشئ ملفات DLL متكافئة للجيب مرتبطة بواسطة Microsoft وNeverC؛
- تقارن دلالات PE/load-config/CFG العامة؛
- تشغّل اختبارات التحوير على أداة التحقق من PE؛
- تجهّز صورًا عالجتها VEIID لاختبار تشغيل تفاضلي.

يشغّل اختبار وقت التشغيل صورة Microsoft أولًا. إذا افتقر runner المستضاف إلى VBS أو بيئة توقيع قابلة للاستخدام، تُصنّف النتيجة صراحةً كتخطٍ بسبب البيئة. بعد نجاح تحميل صورة Microsoft المرجعية، يُعد فشل أي من مرشحي NeverC فشل اختبار حاسمًا. يستطيع runner ذاتي الاستضافة ومهيأ لـ VBS أن يجعل نجاح وقت التشغيل بوابة إلزامية.

يدعم الرابط صور جيوب COFF لمعمارتي x86-64 وARM64. وهو يتحقق من مؤشر الإعداد المنشور، لكنه لا يفرض سياسة إضافية على الحقول ذات الإصدارات داخل `IMAGE_ENCLAVE_CONFIG`.
