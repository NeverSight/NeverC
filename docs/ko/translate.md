# C++를 NeverC로 변환

Core v2는 기본 sized delete 전달을 지원합니다. 소스에서 다시 선언되지 않은 암시적 전역 sized delete/delete[]는 대응하는 소스 정의 unsized 연산자를 호출할 수 있습니다. 명시적 sized 정의가 우선하며 원래 배열 cookie 레이아웃을 유지합니다. 기본 할당기나 예외 런타임은 추가하지 않으며 네이티브 검증에는 구현 버전의 CI가 필요합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#single-object-allocation-and-placement-reuse).

Core v2는 검증된 `__array_rank`와 `__array_extent`도 지원하며, 고정 배열 타입에 대한 템플릿 인덱스를 포함한 음이 아닌 상수 정수 인덱스를 처리합니다. 상수로 바꾸기 전에 타입과 인덱스 소스를 검사합니다. 지원하지 않는 배열 타입과 암시적 클래스 변환 인덱스는 제외되며, 네이티브 결과는 구현 리비전의 CI로 검증해야 합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#array-type-queries).

Core v2는 `__is_integral`, `__is_pointer`, `__is_same` 등의 검증된 내장 타입 분류를 추가합니다. C++ 타입의 동일성을 유지하고 불리언 값을 생성하기 전에 작성된 피연산자 타입을 검사합니다. 지원하지 않는 타입과 다른 타입 특성은 계속 제한됩니다. O0/O2 및 재배치 검증에는 구현 리비전의 CI가 필요하며 표준 헤더와 완전한 C++/STL 지원은 아직 미완성입니다. 지원되는 타입의 집합체, 빈 클래스, 표준 레이아웃, trivial, trivially-copyable, POD, 다형성／추상 속성과 `__is_base_of` 기반 클래스 관계도 조회할 수 있습니다. 표준 `final` 클래스와 `__is_final`, `__is_literal`, `__has_unique_object_representations` 조회도 지원합니다. 소스의 패딩, 빈 클래스 표현 및 C++17 리터럴 타입 규칙을 유지하며 다른 속성과 가상 메서드는 기존 제한을 따릅니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#builtin-type-classification).

Core v2는 지원되는 비클래스 타입의 생성, 대입, 변환 및 소멸 조회를 추가합니다. 참조, 고정 배열 및 지원되는 클래스의 포인터도 포함합니다. 작성된 타입과 선택된 기본 인자를 검사하며 피연산자의 부수 효과는 실행하지 않습니다. 클래스 값과 해당 참조·배열 조회에는 선택 과정의 소스 보존이 더 필요합니다. O0/O2, 재배치 및 8개 ABI 네이티브 검증은 구현 버전 CI를 기다리며 표준 헤더와 전체 C++/STL은 미완성입니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#non-record-operation-traits).

Core v2는 소스의 정확한 전역 C 선언을 통한 `malloc/calloc/free` 직접 호출을 지원합니다. 소스에서 정의한 C++ 할당자는 실제 네이티브 힙을 사용하며 독립된 C 호출자와 메모리를 할당하고 해제할 수 있습니다. 비트 폭, 호출 규약, 소스 및 IR 검사는 유지됩니다. O0/O2 검증은 구현 버전의 CI가 필요합니다. `realloc`, 예외를 던지는 기본 C++ 할당, 표준 헤더와 완전한 C++／STL은 아직 미완성입니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#native-c-heap-calls).

Core v2는 지원되는 정적 레코드, 배열과 수명이 연장된 임시 객체가 완전히 구성된 직후 각각의 소멸을 등록합니다. 상수 초기화된 객체의 값은 유지하며 지역 객체는 선언에 처음 도달할 때, 비지역 객체는 네이티브 시작 시 등록합니다. CRT가 종료와 모듈 언로드 순서를 관리합니다. O0/O2, 라이브러리 언로드와 동시 최초 사용 테스트는 구현 버전의 CI 검증이 필요합니다. TLS, 예외 스택 풀기, 기본 힙, 표준 헤더와 완전한 C++/STL은 미완성이며 수동/DynCode 로딩은 지원하지 않습니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#static-destruction).

Core v2는 구체화된 템플릿을 포함한 지원 객체와 참조의 비지역 동적 초기화를 구현합니다. 검증된 내부 네이티브 시작 함수가 0·상수 초기화 이후 main 전에 정의 순서로 실행하며, 각 초기화 식이 끝나면 일반 임시 객체를 정리합니다. 정적 지역 객체는 처음 사용할 때 초기화합니다. 프로그램과 별도 C 진입점의 O0/O2 테스트는 구현 버전 CI가 필요합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#nonlocal-dynamic-initialization).

런타임 길이 new[]는 placement 인수가 없는 소스 정의 noexcept 클래스 할당 함수도 지원합니다. 잘못된 길이는 할당 함수를 호출하기 전에 null을 반환하며, 유효한 요소는 루프로 생성하고 기본 인수 임시 객체를 요소마다 정리합니다. 명시적 초기화 접두부와 길이 변환의 임시 객체는 전체 표현식이 끝날 때까지 유지됩니다. 반복 집합체 초기화는 중첩 목록과 기존 객체 참조를 포함하여 추가 임시 객체 없이 실제 요소에 직접 기록할 수 있습니다. 추가 임시 객체가 필요한 초기화, 예외를 던지는 할당, 런타임 placement, 기본 힙과 완전한 C++/STL은 아직 미완성입니다. 네이티브 검증은 구현 버전 CI를 기다립니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#runtime-array-allocation).

Core v2는 검증된 소스 정의 할당 함수를 통한 단일 객체 new/delete를 지원하며 클래스와 템플릿 placement 오버로드, 저장 주소, 인수 정리를 보존합니다. 명시적 소멸과 placement 재구성 이후에도 자동 정리 의무가 유지됩니다. 네이티브 검증에는 구현 버전의 CI가 필요합니다. 기본 힙 런타임, 런타임 new[] 길이, 예외, 표준 헤더 및 완전한 C++/STL은 아직 미완성입니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#single-object-allocation-and-placement-reuse).

실험적인 `neverc translate`는 `cpp-core-v1`, `cpp-core-v2`, `cpp-project-v1`, `cpp-math-v1`으로 검토 가능한 `.nc` 소스를 생성합니다.

**현재 입력 언어로 C++만 구현되어 있습니다.** E Language(易语言, `.e`), Python, Go, Rust, TypeScript, JavaScript 지원은 향후 계획이며, 해당 언어의 변환기는 아직 제공되지 않습니다.

부분 특수화 선언은 내부 인수가 아직 종속적인 멤버 변수 특수화 복사본을 포함하여 기본 템플릿 인수 검사 결과를 보존합니다. 특수화가 선택되지 않아도 이미 해석된 매개변수 타입 소스를 검사합니다. 길이가 미정인 팩 확장은 검사된 앞부분과 실제 소스를 유지하며 인수 위치를 추측하지 않습니다. 미해결 클래스 내부 멤버 변수 완전 특수화도 같은 검사를 유지합니다. 전체 C++/STL은 아직 미완성입니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#partial-declaration-source-checks).

인수 검사 결과를 보존해도 부분 특수화가 자동으로 유효해지는 것은 아닙니다. 여전히 더 특수화되어야 하며 매개변수를 추론할 수 있어야 합니다. 잘못된 팩 패턴과 명시적 인스턴스화 정의 뒤의 extern 선언에는 계속 C++ 진단(`TR0202`)이 적용됩니다.

Core v2는 지원되는 제네릭 클래스 안의 이름 있는 일반 중첩 클래스, 구체적 복사본과 직접 작성한 멤버 클래스 명시적 특수화를 지원합니다. 일반 클래스 본문은 템플릿 매개변수 깊이를 늘리지 않습니다. 사용하지 않는 본문은 지연하고, 인스턴스화된 필드와 선택된 메서드, 멤버 템플릿, 수명 및 스칼라 정적 저장소의 정확한 소스와 소유자를 유지합니다. extern 및 효과 없는 반복을 포함해 명시적 인스턴스화 지시문의 한정자를 각각 검사합니다. 상속, 동적 할당과 전체 C++/STL은 미완성입니다. 입력은 C++만 구현되었고 E Language와 Python은 계획 중입니다. 외부 Clang 실행 파일 없이 내장 Clang 라이브러리를 사용합니다. 네이티브 결과는 구현 리비전의 CI로 확인해야 합니다. Core v2는 지원 레코드와 구체적인 클래스 인스턴스의 스칼라 정적 멤버 변수 템플릿을 지원하며 기본 인수, 제한된 팩, 부분·완전 특수화와 클래스 외부 정의를 포함합니다. 동등한 인스턴스는 저장소를 공유하고 내부·외부 인수가 다르면 별도 객체를 유지합니다. 검사된 비 inline const 값은 저장소 없이 읽을 수 있지만 평가되는 주소와 참조에는 정의가 필요합니다. 선언·정의의 소스 검사, 수신 객체의 부수 효과와 임시 객체 정리를 유지합니다. 의존하는 외부 클래스 내부의 완전 특수화는 원본 선언과 구체적인 선언의 소스를 보존합니다. 확정된 인수·기본값·매개변수 타입은 즉시 검사하고 외부 클래스에 의존하는 소스는 인스턴스화 후 검사합니다. 다른 결과 타입, 전체 C++/STL은 미완성입니다. 내장 Clang 라이브러리를 사용하며 외부 Clang은 필요하지 않습니다. C++ 입력만 구현했으며 E Language, Python 등은 예정되어 있습니다. 네이티브 검증은 구현 버전의 CI에서 확인합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-member-variable-templates).

Core v2는 일반 중첩을 포함하는 지원 레코드와 클래스 템플릿 인스턴스에서 멤버 별칭 템플릿을 지원합니다. 기본 인수와 제한된 팩은 외부 클래스 및 내부 별칭 매개변수를 사용할 수 있으며, 각 인수와 치환된 타입의 소스를 따로 검사합니다. 값·참조·배열·레코드의 의미를 유지하고 런타임 템플릿 객체를 만들지 않습니다. 비의존 선언은 사용하지 않아도 검사하며 의존 타입은 치환까지 지연합니다. 내장 Clang 라이브러리를 사용하므로 외부 실행 파일이 필요하지 않습니다. 네이티브 검증은 구현 버전의 CI에서 확인합니다. 전체 C++/STL은 미완성입니다. C++ 입력만 구현했으며 E Language, Python 등은 예정되어 있습니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-member-alias-templates).

Core v2는 지원하는 레코드와 클래스 템플릿 인스턴스의 구체적인 멤버 함수 템플릿을 지원합니다. 일반·정적 메서드, 연산자, 생성자, 변환 함수, 제한된 팩, 기본 인수, 클래스 외부 정의와 특수화를 포함합니다. 내부와 외부 인수의 식별자를 구분하고 동등한 호출은 코드와 정적 저장소를 공유합니다. 선택된 호출·기본값·인스턴스화한 본문의 소스와 수명을 검사합니다. 번역은 내장 Clang 라이브러리를 사용하며 외부 Clang 실행 파일을 호출하지 않습니다. 네이티브 결과는 구현 버전의 CI로 확인합니다. 상속, 동적 할당과 전체 C++/STL은 미완성입니다. C++ 입력만 구현했으며 E Language, Python 등은 예정되어 있습니다. 멤버 템플릿 선언의 구체적인 외부 한정자는 본문을 인스턴스화하지 않아도 소스를 검사합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-member-function-templates).

Core v2는 정수, bool 또는 enum 결과를 갖는 네임스페이스 변수 템플릿을 지원합니다. 추론된 auto, 선택된 부분 특수화, 완전 특수화, 기본 인수와 크기가 제한된 타입·스칼라 팩을 포함합니다. ## 설치와 스칼라 변환

일반 NeverC 설치와 표준 리소스를 사용하면 됩니다. C++ 프런트엔드와 승인된 SDK 헤더가 내장되어 있어 Clang을 별도로 설치할 필요가 없습니다. 빌드 세부 사항은 [프런트엔드 안내](../../utils/translate-frontends/cpp/README.md)를 참고하세요.

`cpp-core-v1`은 include가 없는 독립적인 C++17 소스 하나를 받습니다. `int`, `unsigned int`, `bool`, `void`, 단순 집합체 타입, 비멤버 함수, 네임스페이스, 오버로드와 문서화된 제어 흐름을 지원합니다. 사용하지 않는 코드를 포함하여 입력에 포함된 모든 선언을 검사합니다.

core v2는 고정 길이 지역 배열과 배열 필드, 다차원 인덱싱, 배열 포인터와 참조도 지원합니다. 부분 초기화는 생략된 스칼라 요소를 0으로 초기화하고 레코드 요소에는 선택된 초기화를 적용하며 요소 초기화 순서와 별칭 관계를 유지합니다. 배열 길이와 초기화 확장량에는 상한이 있습니다. 전역 배열과 가변 길이 배열은 아직 지원하지 않습니다.

core v2는 C++17 초기화 문, 분기 이어 실행 및 검증된 `[[fallthrough]]` 표기를 포함한 `switch`/`case`/`default`를 지원합니다. 선택식은 한 번만 평가하며 중첩 switch와 루프의 `break`/`continue` 대상이 유지됩니다. GNU case 범위와 다른 문 속성은 허용하지 않습니다.

core v2는 부호 있는 8／16／32／64비트 정수와 부호 없는 정수, 문자 타입과 리터럴, 상수 `sizeof`／`alignof` 질의를 지원합니다. 소스의 정수 승격과 오버로드 결정을 먼저 수행한 뒤 비트 폭을 정규화하며 `long`, `wchar_t`, 크기 타입은 타깃을 따릅니다. 열거형의 기반 타입에도 작은 정수와 큰 정수를 사용할 수 있습니다. 표준 라이브러리는 개발 중입니다.

core v2는 객체 포인터의 오프셋, 차이, 증감 및 복합 대입을 지원하며 배열 순회와 다차원 배열의 간격을 유지합니다. 생성된 보조 함수는 C++17에서 널 포인터에 0을 더하거나 빼는 동작과 널 포인터끼리의 차이를 보존합니다. 객체 포인터 대소 비교도 구현했으며 네이티브 x86/AArch64에서는 독립적으로 검증한 부호 없는 주소 표현을 사용합니다. 네이티브 결과는 해당 커밋의 CI 검증이 필요합니다. 소스의 포인터와 정수 간 변환 및 완전한 STL 지원은 아직 미완료입니다.

core v2는 소스 타입의 크기와 ABI 정렬을 NeverC 자체 타깃 모델과 대조하며, 구조체 크기와 필드 오프셋도 검증합니다. 생성 코드의 컴파일 시점 단언으로 메모리 배치를 다시 확인하고 해당 정보를 매니페스트에 기록합니다.

Core v2는 지원되는 레코드 타입의 이름 있는 비가상 멤버 함수를 지원합니다. const 오버로드, lvalue 한정 메서드, 정적 메서드 및 `this`를 포함합니다. 호출은 원래 객체의 동일성을 유지하며 인수보다 먼저 수신 객체를 평가합니다.

Core v2는 표준 레이아웃과 지원되는 복사 연산을 갖는 레코드의 일반 사용자 정의 생성자도 지원합니다. 지역 객체, 필드와 배열 요소는 최종 저장 위치에 직접 생성되며 필드는 선언 순서대로 초기화됩니다. 예외로 인한 스택 해제는 아직 지원하지 않습니다.

Core v2는 값으로 전달되는 각 레코드 매개변수에 독립된 객체를 만들고 반환값을 호출자의 저장소에 직접 기록합니다. 생성자와 메서드에도 같은 규칙을 적용하며 필요한 복사와 참조의 별칭 관계를 유지합니다. 조건을 만족하는 자명한 타입에서는 다른 C++17 구현이 인수나 반환값을 추가로 복사할 수 있습니다.

Core v2는 일반 사용자 정의 소멸자와 정상 종료 시의 암시적 멤버 소멸을 지원합니다. 지역 객체, 필드와 배열 요소는 역순으로 소멸하며, 임시 객체는 필요한 값을 저장한 뒤 전체 표현식이 끝날 때 정리합니다. 반환, 분기, 반복문, break와 continue에서 필요한 정리를 수행합니다. 값 매개변수는 피호출 함수가 종료될 때 소멸하고 반환 객체는 호출자가 관리합니다. 예외 스택 풀기는 아직 지원하지 않습니다.

Core v2는 원본 매개변수가 `R&` 또는 `const R&`인 일반 사용자 정의 복사 생성자와 복사 대입 연산자를 지원합니다. 실제 대상에서 복사하며 부수 효과와 반환 참조를 유지합니다. 대입 연산자 구문은 오른쪽 피연산자를 먼저 평가하고, 명시적 `operator=` 호출은 수신 객체를 먼저 평가합니다.

Core v2는 컴파일러가 생성하거나 default로 지정한 기본 생성자와 default 소멸자도 지원하며 중첩 레코드 및 배열 멤버를 처리합니다. 실제 대상에서 선언 순서대로 초기화하고, 값 초기화는 C++ 규칙이 요구할 때만 0 초기화를 수행합니다. 클래스 밖의 default 지정에 따른 초기화 차이도 유지합니다. 사용하지 않거나 평가되지 않는 식에만 나타나는 생성자에 별도 함수 본문을 요구하지 않습니다.

Core v2는 암시적 및 default 복사 생성자를 지원하며 중첩 레코드와 다차원 배열도 처리합니다. 선택된 멤버 복사 생성자를 실제 대상에서 선언 및 요소 순서대로 호출하고 원본 배열 주소는 한 번만 평가합니다. 자명한 복사는 저장된 포인터 값을 그대로 유지합니다. 값 전달과 원본 객체 반환은 복사 부수 효과를 유지하며 순수 우측값의 직접 전달에는 추가 복사가 없습니다.

Core v2는 암시적 및 default 복사 대입도 지원합니다. 멤버와 배열 요소의 선택된 대입 연산 및 순서를 유지하며 생성된 자명한 배열 복사는 외부 메모리 복사 호출 없이 타입이 있는 요소 대입으로 변환합니다. 자명한 대입은 저장된 포인터를 유지하고 실제 수신 객체의 참조를 반환합니다. 연산자 구문에서는 원본 참조를 먼저, 명시적 멤버 호출에서는 수신 객체를 먼저 확정한 후 부수 효과가 끝나면 원본 값을 읽습니다. 대입 때문에 객체를 추가로 생성하거나 소멸하지 않습니다.

Core v2는 허용된 필드의 기본 멤버 초기화를 지원하며 앞선 멤버 접근, 일반 호출, 중첩 레코드와 배열을 처리합니다. 선택된 기본값의 `this`는 실제 소유 객체를 가리키고 명시적 집합체 초기화 항목은 호출자의 `this`를 유지합니다. 명시적 초기화는 해당 멤버의 기본값을 대체합니다. 암시적 또는 default 복사와 대입은 기본값을 다시 실행하지 않지만 사용자 복사 생성자는 생략한 멤버의 기본값을 사용할 수 있습니다. 생성자 멤버 초기화와 집합체 초기화는 각자의 임시 객체 정리 경계를 유지합니다. 템플릿과 전체 STL은 개발 중입니다.

Core v2는 이미 살아 있는 객체의 오른값 참조를 지원합니다. 스칼라, 포인터, 레코드와 배열의 별칭, 참조 매개변수와 반환값, 조건식 xvalue 및 일반 `&&` 한정 메서드를 포함합니다. `static_cast<R&&>(live)`는 같은 객체를 유지하며 이름이 있는 오른값 참조 변수는 여전히 왼값입니다. 오버로드와 기존 복사 동작은 Clang의 선택을 따릅니다. 참조는 추가 정리 소유자를 만들지 않습니다.

Core v2는 살아 있는 `R&&` 또는 `const R&&`를 받는 일반 사용자 정의 이동 생성자와 이동 대입을 실행합니다. 생성은 실제 대상 저장소를 사용하며 대입은 원본 변경, 피연산자 평가 순서와 반환된 `R&` 별칭을 보존합니다. `&`／`&&` 한정 대입도 지원합니다. 이름이 있는 오른값 참조는 왼값 오버로드를 선택하고 명시적 생성자는 초기화 규칙을 따릅니다. 이동은 원본 수명을 끝내지 않으며 원본과 대상은 각각 정상 소멸됩니다.

Core v2는 중첩 레코드와 다차원 배열을 포함한 암시적 및 명시적 default 이동 생성과 대입도 지원합니다. 멤버는 선언 및 요소 순서에 따라 C++가 선택한 복사나 이동을 실행합니다. 생성된 이동은 기본 멤버 초기화를 반복하지 않으며 trivial 연산은 저장된 포인터 값을 보존합니다. 원본은 정상 소멸되고 사용하지 않거나 trivial인 생성 연산에는 가상의 본문이 필요하지 않습니다.

Core v2는 해석이 완료된 표준 `noexcept`, `noexcept(true/false)`, C++17 `throw()` 선언과 상수 `noexcept(expression)` 질의를 지원합니다. 질의는 선택된 함수와 소멸자의 예외 명세를 반영하며 피연산자를 실행하지 않습니다. 사용하지 않는 코드를 포함해 모든 피연산자와 작성된 명세를 소스 검사합니다. 예외 발생·포착, 스택 풀기, 템플릿과 전체 STL은 계속 개발 중입니다.

Core v2는 산술, 비교, 첨자, 역참조, 증가, 함수 객체와 일반 대입 시그니처를 포함한 일반 멤버 및 비멤버 연산자 오버로드를 지원합니다. 선택된 함수, 참조 별칭과 객체 결과를 유지합니다. 연산자 표기는 C++17 평가 순서를 따르며 오버로드된 논리 연산자는 두 피연산자를 모두 평가합니다. 비멤버 대입 연산자는 매개변수를 오른쪽부터 초기화한 뒤 역순으로 소멸시킵니다. 템플릿, 메모리 할당과 전체 STL은 계속 개발 중입니다.

Core v2는 살아 있는 객체의 일반 변환 함수도 지원합니다. 암시적·명시적 정수, 열거형, 포인터 변환과 조건식의 명시적 `bool`, 참조 및 객체 반환을 처리합니다. 변환마다 선택된 멤버 함수를 한 번 호출합니다. 참조는 별칭을 유지하고 객체 prvalue는 실제 목적지를 직접 초기화하며, 참조에서 값으로 변환할 때는 선택된 복사나 이동을 수행합니다. const 및 참조 한정자, constexpr, noexcept는 C++17 선택 규칙을 따릅니다.

Core v2는 빈 표준 레이아웃 클래스와 상태 없는 함수 객체 및 변환 객체를 지원합니다. 빈 객체는 C++의 1바이트 크기와 정렬, 언어가 요구하는 별도 저장 공간, 선택된 생성자·연산자 호출과 정상적인 소멸을 유지합니다. 단순 복사도 피연산자를 평가하며 배열과 포함 레코드의 빈 요소도 저장 한도에 포함됩니다. 생성된 NC는 내부 저장 바이트를 사용하고 원본 필드 목록은 빈 상태로 유지합니다. 상속, 템플릿과 완전한 STL은 개발 중입니다.

Core v2는 void 변환, `void()`, `void{}`를 지원하며 지원되는 void 별칭, 호출, 반환, 쉼표 식과 조건 분기에 사용할 수 있습니다. 비 volatile 좌값을 버릴 때 저장 값을 읽지 않고 수신 객체와 첨자 계산의 부수 효과를 유지합니다. 버리는 임시 객체도 생성되며 원래 전체 표현식 경계에서 소멸합니다. void 변수나 값 저장 공간은 생성하지 않습니다. 상수 식과 noexcept 피연산자도 검사합니다. volatile 객체, 미지원 타입, 템플릿과 완전한 STL은 이번 범위에 포함되지 않습니다.

Core v2는 지원되는 함수, 메서드, 호출 연산자와 사용자 생성자의 기본 인수를 지원합니다. 사용자 복사 및 이동 생성자의 후행 기본 인수도 포함됩니다. 이름은 선언 위치에서 해석하고 인수를 생략하는 호출마다 식을 평가합니다. 참조와 값의 동일성 및 소멸 규칙을 유지합니다. 초기화가 생략된 배열 요소와 생성된 배열 복사는 다음 요소 전에 기본 인수 임시 객체를 소멸시키며, 명시적 배열 초기화 항목은 바깥 전체 표현식까지 유지합니다. 사용하지 않거나 명시적 인수로 대체한 기본 식도 검사합니다. 템플릿과 완전한 STL은 아직 미완성입니다.

## 여러 파일로 구성된 프로젝트

컴파일 데이터베이스에서 번역 단위를 명시적으로 선택하고 프로젝트 루트 디렉터리를 지정합니다. 내장 프런트엔드는 각 단위를 따로 분석하며 병합기는 정의의 완전성, 링크 속성과 공유 타입을 검사하고 단일 정의 규칙(ODR) 준수 여부를 보수적으로 검증합니다.

```sh
neverc translate --from cpp --profile cpp-project-v1 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/a.cpp src/b.cpp --out-dir generated
```

프로젝트 출력은 `translated.nc`와 `translated.h`입니다. 해당 루트 안의 프로젝트 헤더만 허용됩니다. 한 파일에 구성이 여러 개면 `--compdb-entry src/a.cpp=4`로 데이터베이스의 0부터 시작하는 인덱스를 선택합니다. 저장된 컴파일 명령은 데이터로만 분석하며 실행하지 않습니다.

## 제한된 배정밀도 수학 지원

`cpp-math-v1`은 프로젝트에 `double`, 문서에 명시된 변환과 비교, 정확한 시그니처의 `std::fabs(double)` 및 `std::floor(double)`을 추가합니다. 내장된 Clang 20.1.8 / libc++ 200100 / macOS 15.5 헤더 모음을 사용하며 macOS 15.0 대상(arm64 또는 x86_64)을 명시해야 합니다. 일반적인 부동소수점 산술은 지원하지 않습니다. 예외 트랩은 마스킹하고 비정규수를 0으로 만드는 모드는 꺼야 합니다. 네 가지 표준 반올림 모드를 테스트했습니다.

```sh
neverc translate --from cpp --profile cpp-math-v1 \
  --target arm64-apple-macosx15.0.0 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/math.cpp --out-dir generated-math
```

수학 변환은 설치된 NeverC 수학 헤더, 내장 구현의 식별 정보와 실제 링크도 검증합니다. 생성된 수학 모듈은 NeverC 런타임을 사용합니다. `-fno-builtin-std`를 지정하면 최종 출력에 `fabs`/`floor` 매핑이 필요한 경우에만 파일을 쓰기 전에 변환이 실패합니다. 이 매핑이 필요 없는 수학 코드는 계속 변환할 수 있습니다.

## 검증과 출력

출력 옵션 대신 `--check`를 사용하면 같은 분석, 생성, 구문 및 오브젝트 검증을 수행하고 생성 파일을 남기지 않습니다. `--report PATH`는 구조화된 진단을 기록합니다. 변환 과정은 원본 프로그램을 실행하지 않습니다.

출력과 부속 파일은 덮어쓰지 않습니다. `--out-dir`는 기존 부모 디렉터리 아래 새 디렉터리를, `-o`는 새 `.nc` 경로를 요구합니다. 매니페스트는 대상 요구 사항, 입출력 해시와 컴파일 절차를 기록하며 소스 맵은 생성된 행을 원래 위치에 연결합니다.

CI 결과, 실행 및 설치 검증, 건너뛴 테스트는 플랫폼별로 기록합니다. 네이티브 macOS arm64와 Rosetta에서 구동하는 macOS x86_64는 서로 다른 검증 환경으로 구분합니다. 전체 C++／STL, 예외, 템플릿, 문자열과 `std::vector`는 공개된 지원 범위에 포함되지 않습니다.
