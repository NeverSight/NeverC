# C++를 NeverC로 변환

Core v2는 컴파일 시간 형식 별칭과 정수·열거형 상수를 위해 내장된 고정 버전 `<type_traits>`를 지원합니다. `std::remove_cv_t`, `std::is_same_v`, 지원되는 생성·소멸 traits와 `std::integral_constant::value`는 기존 코어 형식과 리터럴로 변환됩니다. 드라이버는 지원되는 macOS, Linux, Windows 대상에서 사용된 libc++／resource 헤더 101개의 해시를 검증하고 기록합니다. 런타임 trait 지원은 아래에 설명된 검증된 함수 포인터 `integral_constant` 형태로 제한됩니다. 다른 trait 객체와 trait 저장소 식별은 아직 지원되지 않습니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#compile-time-type_traits).

Core v2는 내장된 고정 버전 `<cstdint>`도 지원합니다. 고정폭, least, fast, 포인터 폭, 최대 폭 형식 별칭과 표준 한계·상수 매크로는 선택한 대상의 C++17 형식과 값을 유지합니다. 드라이버는 단독 사용 시 9개 헤더의 폐쇄 집합을 기록하고 따옴표 형식과 C 헤더 형식을 거부합니다. `<cstdint>`와 `<type_traits>`는 어느 순서로든 함께 사용할 수 있습니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#fixed-width-integers-from-cstdint).

Core v2는 고정 버전 `<limits>`도 지원합니다. 지원되는 정수, `float`, `double`의 `numeric_limits` 정수·열거형 데이터 멤버와 표준 무인수 질의는 무한대와 NaN을 포함한 정확한 리터럴로 접힙니다. 16개 파일 폐쇄 집합은 모든 대상에서 인증되며 런타임 객체, 저장소 또는 메서드 식별, 객체 한정 호출과 `long double`은 지원되지 않습니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#numeric-bounds-from-limits).

Core v2는 고정 버전 `<cstddef>`도 지원합니다. 대상별 `size_t`, `ptrdiff_t`, `nullptr_t` 별칭, `NULL`, 검사된 `offsetof`, `max_align_t` 레이아웃 질의는 libc++ 없이 변환됩니다. `std::byte` 저장소, 비트／시프트 연산과 `to_integer`는 스칼라 연산으로 직접 변환됩니다. 29개 파일 폐쇄 집합은 모든 대상에서 인증되며 따옴표／C 헤더 형식, 원시 내장식과 표준 함수 주소는 거부됩니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#fundamental-types-and-bytes-from-cstddef).

Core v2는 고정 버전 `<new>`도 지원합니다. 37개 파일 폐쇄 집합은 지원되는 모든 대상에서 동일하며 플랫폼 의존 요소가 없습니다. `std::nothrow_t`, `std::align_val_t`와 C++17 간섭 크기 상수는 컴파일 시간 또는 스칼라 메타데이터로 유지되며, 지원되는 비 volatile 객체 포인터에 대한 정확한 `std::launder` 호출은 직접 변환되고 인수를 한 번만 평가합니다. 정확한 표준 단일 객체 및 상수 길이 배열 placement new 식도 캡처한 저장소를 런타임 호출 없이 재사용합니다. 할당 함수 직접 호출, nothrow 객체, 함수 주소와 기본 힙 연산은 계속 제외됩니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#new-header-from-new).

순수 `std::launder` 타입 및 `noexcept` 조회는 한정된 타입, 중첩된 타입, 소스 레코드를 참조하는 정확한 `std::reference_wrapper` 레이아웃과 소스 함수의 포인터 매개변수를 지원합니다. 포인터를 읽거나 SDK 본문 및 객체 수명을 선택하지 않습니다. 원래 피연산자, 별칭, 템플릿 인수, 기본 인수와 소스 본문은 계속 검사하며 사용자 대체 선언과 독립적인 SDK 함수 주소는 거부합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#new-header-from-new).

Core v2의 고정 버전 `<memory>` 표면은 이제 정확한 원시 포인터 `pointer_traits`, `std::allocator<T>`, `std::allocator_traits<std::allocator<T>>`의 식별, 중첩 별칭, rebind와 trait 상수를 컴파일 시간 메타데이터로 해석합니다. 정확한 `uses_allocator<T, std::allocator<U>>` 식별, 상속된 별칭과 호환 값도 해석됩니다. 정확한 단일 객체 `std::default_delete<T>`와 경계 없는 배열 `std::default_delete<T[]>`는 완전한 유한 내부 차원을 포함해 검사된 1바이트 무상태 캐리어를 사용하며 기본 생성, 복사·이동 생성과 지원되는 cv 변환 생성을 제공합니다. 호출 연산자는 수신자와 포인터를 한 번만 평가하고, 완전한 객체를 소멸시키거나 배열 요소를 역순으로 소멸시킨 뒤, Clang이 선택하고 검사한 소스 정의 스칼라 또는 배열 클래스·전역 delete를 호출합니다. 정확한 단일 객체 `std::unique_ptr<T, std::default_delete<T>>`와 경계 없는 배열 `std::unique_ptr<T[], std::default_delete<T[]>>`는 다차원 소유자를 포함해 포인터 크기의 인증된 캐리어를 사용합니다. 같은 소유자는 소스 소유의 값 전달 사용자 정의 삭제자도 허용합니다. 단, 삭제자는 자명한 특수 멤버를 가진 비어 있는 표준 레이아웃의 자명한 1바이트 레코드여야 하며, 소스에 정의된 `void operator()(pointer) noexcept`를 정확히 하나만 가져야 합니다(`const`는 선택 사항이고 참조 한정자는 없음). 기본, null, 원시 포인터 생성, 정확한 삭제자 왼값 또는 오른값 매개변수에 바인딩되는 삭제자 인수를 더한 일치하는 원시 포인터·null 생성, 같은 형식의 이동 생성과 const를 추가하는 기본 삭제자 변환 이동 생성, 대응하는 이동 대입, `nullptr` 대입, `get`, 가변·const `get_deleter`, 명시적 불리언 변환, `release`, `reset`, 멤버 및 자유 `swap`, 삭제자 특수화와 관계없이 스칼라·배열 범주가 같고 한정자가 호환되는 원시 포인터를 가진 지원 소유자 간의 여섯 가지 비교 전체, 양방향 `nullptr` 비교 여섯 가지 전체와 자동 소멸은 직접 변환됩니다. 단일 객체 소유자는 `operator->`와 역참조도 지원하고, 배열 소유자는 `operator[]`를 지원합니다. 변환은 수신자·인수 평가 순서를 유지합니다. 기본 삭제자는 Clang이 선택한 정확하고 검사된 소스 정의 스칼라 또는 배열 클래스 delete를 호출하며, 조회가 전역으로 남으면 일치하는 검사된 전역 delete/delete[]를 호출합니다. 지원되는 사용자 정의 삭제자는 null이 아닌 포인터에 대해 한 번 호출되며 전역 delete 정의가 필요하지 않습니다. 지원되는 각 비정적 멤버는 객체 수신자 또는 해당 소유자를 가리키는 정확한 원시 포인터를 받을 수 있으며, 포인터 수신자는 가리키는 대상의 `const`를 유지하고 한 번만 실행됩니다. 정확한 단일 객체 `std::make_unique<T>(args...)`와 경계 없는 배열 `std::make_unique<T[]>(count)`도 직접 변환됩니다. 여기서 `T`는 완전한 유한 내부 차원을 가질 수 있고, 개수는 0부터 65536까지의 정수 상수 식이어야 합니다. 이들은 고정 버전 팩토리와 선택된 할당을 인증합니다. 스칼라 팩토리는 Clang이 선택한 정확한 소스 정의 전역 또는 클래스별 `operator new`를 호출하고 소유자의 일치하는 스칼라 delete 경로를 사용합니다. 배열 팩토리는 Clang이 선택한 정확한 소스 정의 전역 또는 클래스별 `operator new[]`를 호출하고 일치하는 배열 delete[] 경로를 사용합니다. 팩토리는 스칼라 요소를 값 초기화하거나 정확한 소스 소유 비템플릿 `noexcept` 레코드 생성자를 호출하고, 결과 포인터를 해당 소유자에 설치합니다. 다차원 생성은 바깥 개수와 고정된 내부 차원을 사용하고, 검사된 new[]/delete[] 쿠키 경로는 평탄화된 기본 요소를 추적합니다. 런타임 배열 개수는 계속 거부됩니다. 제공된 생성자 인수와 인증된 소스 소유 후행 기본값은 각각 한 번만 평가됩니다. 배열 팩토리는 평탄화된 기본 요소마다 이 기본값을 따로 평가합니다. 기존 주소 연산, 스칼라 및 소스 레코드 소멸, 스칼라 또는 자명한 소스 레코드의 초기화되지 않은 생성, 예외를 던지지 않는 매개변수 없는 소스 레코드 기본·값 생성 연산은 직접 변환됩니다. 초기화되지 않은 복사, 채우기, 이동도 완전한 소스 소유 레코드에 대해 인증된 libc++ 도우미가 선택한 정확한 소스 소유 비템플릿 `noexcept` 복사 또는 이동 생성자를 호출합니다. 정확한 런타임 할당자 객체는 검사된 1바이트 무상태 캐리어를 사용하며 기본·복사·이동·변환 생성, 같은 형식 대입, 이종 비교, C++17 `address`와 `max_size`를 지원합니다. 정확한 C++17 할당자 및 allocator-traits `construct` 호출은 쓰기 가능한 스칼라를 값 초기화하거나 검사된 소스 소유 `noexcept` 레코드 생성자를 호출하며, 정확한 다중 인수·복사·이동 선택과 인증된 소스 소유 후행 기본값을 포함합니다. 제공된 인수와 기본값은 각각 한 번만 평가됩니다. 할당 개수가 `max_size` 이내로 증명되고 일치하는 전역 new/delete 정의가 소스 소유일 때, 정확한 할당자 및 allocator-traits `allocate`/`deallocate` 전달 함수도 기본 new 정렬을 가진 완전한 요소에 대해 변환됩니다. 1바이트 요소는 대상 `size_t`로 변환한 뒤의 런타임 개수를 허용합니다. 더 큰 요소는 오버플로하지 않는 정수 상수 식 또는 전체 값 범위가 `max_size`에 들어가는 부호 없는 내장 형식에서의 암시적 변환을 허용합니다. 개수, 힌트, 수신자와 포인터는 한 번만 평가됩니다. 정확한 C++17 할당자 `destroy`와 `allocator_traits` 소멸, `max_size`, 복사 선택 전달은 libc++ 호출 없이 검사된 수명 및 무상태 할당자 경로를 재사용합니다. 인증된 267개 파일 폐쇄 집합은 지원되는 모든 대상에서 동일하며 플랫폼 의존 요소가 없습니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#memory-header-from-memory).

Core v2는 고정 버전 `<utility>`도 지원합니다. 스칼라 `move`, `forward`, `move_if_noexcept`, `as_const`, `exchange`, `swap`은 직접 변환됩니다. 소스 소유 레코드의 정확한 제네릭 swap은 선택되고 지원되는 이동 생성, 대입과 임시 객체 소멸을 호출합니다. 스칼라 또는 재귀적으로 허용되는 복합 `std::pair`의 생성, 대입, 교환, 비교, `make_pair`, `get`도 지원됩니다. 튜플 메타데이터와 `integer_sequence::size()`는 컴파일 시간 값으로 유지됩니다. 인증된 87개 파일 폐쇄 집합은 libc++ 런타임 의존성을 추가하지 않습니다. 표준 함수 주소는 계속 거부됩니다. 선택된 고정 버전 pair 초기화자가 이러한 각 필드를 소스 소유 복사 또는 이동 생성자로 생성하면, pair의 요소별 직접 생성과 `std::make_pair`는 소스 소유의 비자명한 표준 레이아웃 레코드 필드도 허용합니다. 팩토리의 전달 체인은 인증됩니다. pair 필드는 역순으로 소멸됩니다. 같은 형식 pair 전체의 복사·이동도 defaulted pair 생성자의 멤버 초기화자와 선택된 소스 소유 요소 생성자를 인증하며, 참조 필드는 바인딩을 유지합니다. 다른 허용된 pair로부터의 pair 변환 생성도 각 소유 필드의 소스 소유 복사 또는 이동 생성자를 선택하고 증명합니다. 값 소스와 참조 소스는 검사된 cv 한정과 값 범주를 유지하고, 대상 참조 필드는 바인딩을 유지합니다. 같은 형식 및 호환되는 이종 pair 대입도 고정 버전 pair 본문을 증명하고, 참조 필드를 통한 쓰기를 포함해 선택된 각 소스 소유 필드 대입을 순서대로 호출합니다. 고정 버전 swap이 지원되는 이동 생성과 대입을 선택하면 멤버 및 자유 pair swap도 비자명한 소스 소유 필드를 허용합니다. 이 swap은 각 swap 임시 객체를 소멸시키며, 참조 필드는 자기 swap을 포함해 바인딩을 유지합니다. `std::invoke`의 함수, 함수 포인터, 소스 함수 객체, 멤버 함수와 `mem_fn` 경로 및 직접 또는 invoke를 통한 `reference_wrapper` 호출은 `apply`와 같은 선택된 값 전달 생성과 추가 기본 인수 규칙을 사용합니다. 기본 인수의 임시 객체는 콜백과 매개변수 소멸 동안 유지되며 SDK 호출이 반환되기 전에 정리됩니다. 검증된 함수 포인터 trait 객체를 `vector` 요소로 사용할 수 있으며 지원되는 array, pair, optional, 중첩 vector 요소에도 포함할 수 있습니다. 기존 확장, 복사와 이동, 삽입, 삭제, 범위 연산은 독립적인 요소 저장소와 검증된 소스 콜백을 유지합니다. bool vector, 사용자 정의 할당자, 승인되지 않은 요소 비교, SDK `value` 저장소 별칭에는 기존 제한이 적용됩니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#function-pointer-trait-constants).

`make_unique`는 검증된 함수 포인터 trait 객체의 기본, 복사, 이동 생성과 상수 길이 배열을 지원합니다. 선택된 고정 SDK 생성자와 정확한 전달 경로를 검증합니다. 호출자 인수의 평가 횟수를 유지하며 할당과 해제의 소스 정의 및 정리가 필요합니다. const 소스, release/reset, vector 소유권은 기존 검증 경로를 사용합니다. 실행 중 배열 길이, 지원하지 않는 trait 시그니처, SDK `value` 저장소 별칭에는 제한이 유지됩니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#function-pointer-trait-constants).

`vector::emplace`와 `emplace_back`은 지원되는 pair 요소의 한 필드 또는 두 필드에 타입이 정확히 일치하는 검증된 trait 값을 받습니다. const, lvalue, rvalue, 검증된 소스 함수 결과는 독립적인 pair 저장소를 사용합니다. 기존 스칼라 변환, 인수 평가, 확장 시 별칭, 반환된 요소 참조를 유지합니다. 암시적 사용자 변환, 관련 없는 SDK 객체, trait에서 콜백으로의 변환에는 기존 독립 검증이 필요합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#function-pointer-trait-constants).

vector emplace로 생성되는 pair 필드는 검증된 일반 함수 포인터와 함수 참조, 호환되는 `noexcept` 제거, `nullptr`도 받습니다. 직접 변환은 콜백 시그니처, 소스 정의, 독립적인 pair 저장소를 유지합니다. 모든 호출자 인수의 전달 바인딩을 캡처한 뒤 필드 값을 읽으므로 뒤쪽 인수가 참조된 값을 갱신해도 너무 이른 스냅샷이 사용되지 않습니다. 암시적 사용자 또는 trait 변환, volatile 포인터, SDK 함수 주소에는 기존 제한이 적용됩니다. 용량을 늘릴 때는 검증된 소스 할당이 끝난 뒤 기존 요소를 이동하기 전에 필드 값을 읽습니다. 여유 용량이 있으면 할당 없이 생성합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#function-pointer-trait-constants).

중첩 `vector` 요소는 검증된 상수 개수 `0..65536`과 선택적인 정확한 타입의 채움 값 또는 지원되는 스칼라·콜백 변환으로 `emplace` 및 `emplace_back`에서 직접 생성할 수 있습니다. 내부 버퍼는 독립적입니다. 타입이 같은 채움 값의 참조는 할당 중에도 유지되며, 변환된 값은 외부 할당 후 내부 할당 전에 저장됩니다. 개수가 0이어도 채움 인수를 평가하지만 내부 버퍼는 할당하지 않습니다. 동적이거나 부작용이 있는 개수, 사용자 정의 채움 값 변환, 사용자 지정 할당자는 기존 제한을 따릅니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#vector-header-and-metadata-from-vector).

중첩 `vector`의 범위 삽입은 복사 가능한 내부 요소에 대해 정확한 원시 포인터, 배열의 포인터 변환, 인증된 래퍼 반복자도 지원합니다. 끝점 바인딩은 한 번만 캡처하고, 끝점 값은 외부 할당 후 내부 할당 전에 읽습니다. 빈 범위는 내부 버퍼를 할당하지 않습니다. 대상 컨테이너에 속한 원본 범위도 사용할 수 있으며 복사한 자원은 독립적으로 유지됩니다. 변환이 필요한 범위, 역방향 또는 임의의 반복자, 이동만 가능한 요소는 기존 제한을 따릅니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#vector-header-and-metadata-from-vector).

중첩 `vector` 요소는 정확히 일치하는 `std::initializer_list<T>`에서도 생성할 수 있으며 직접 임시 목록, const 목록, 빈 목록을 지원합니다. 목록 포인터와 크기는 외부 할당 후 읽고 내부 할당 전에 저장합니다. 자원 요소는 기존 복사 연산을 사용하며 직접 SDK 콜백 상수는 값으로 복사합니다. 임시 기반 배열의 필요한 수명이 유지됩니다. 사용자 정의 목록 변환과 SDK 저장소 별칭은 기존 제한을 따릅니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#vector-header-and-metadata-from-vector).

## 설치와 스칼라 변환

일반 NeverC 설치와 표준 리소스를 사용하면 됩니다. C++ 프런트엔드와 승인된 SDK 헤더가 내장되어 있어 Clang을 별도로 설치할 필요가 없습니다. 빌드 세부 사항은 [프런트엔드 안내](../../utils/translate-frontends/cpp/README.md)를 참고하세요.

```sh
neverc translate --from cpp input.cpp -o output.nc
neverc output.nc -c -o output.o
```

`cpp-core-v1`은 include가 없는 독립적인 C++17 소스 하나를 받습니다. `int`, `unsigned int`, `bool`, `void`, 단순 집합체 타입, 비멤버 함수, 네임스페이스, 오버로드와 문서화된 제어 흐름을 지원합니다. 사용하지 않는 코드를 포함하여 입력에 포함된 모든 선언을 검사합니다.

`--profile cpp-core-v2`를 선택하면 검증된 `typedef`/`using` 타입 별칭, 지원하는 정수 타입을 기반으로 하는 열거형, `static_assert`, 제한된 객체 포인터와 좌측값 참조를 추가로 변환할 수 있습니다. 참조 매개변수와 반환 참조는 원래 객체를 가리키며, 다중 포인터의 `const`와 널 포인터를 지원합니다. 단일 소스와 include 금지 제한은 유지됩니다. [core v2 지원 범위](../../utils/translate-frontends/docs/cpp-core-v2.md)를 참고하세요.

core v2는 고정 길이 지역 배열과 배열 필드, 다차원 인덱싱, 배열 포인터와 참조도 지원합니다. 부분 초기화는 생략된 스칼라 요소를 0으로 초기화하고 레코드 요소에는 선택된 초기화를 적용하며 요소 초기화 순서와 별칭 관계를 유지합니다. 배열 길이와 초기화 확장량에는 상한이 있습니다. 전역 배열과 가변 길이 배열은 아직 지원하지 않습니다.

core v2는 C++17 초기화 문, 분기 이어 실행 및 검증된 `[[fallthrough]]` 표기를 포함한 `switch`/`case`/`default`를 지원합니다. 선택식은 한 번만 평가하며 중첩 switch와 루프의 `break`/`continue` 대상이 유지됩니다. GNU case 범위와 다른 문 속성은 허용하지 않습니다.

core v2는 부호 있는 8／16／32／64비트 정수와 부호 없는 정수, 문자 타입과 리터럴, 상수 `sizeof`／`alignof` 질의를 지원합니다. 소스의 정수 승격과 오버로드 결정을 먼저 수행한 뒤 비트 폭을 정규화하며 `long`, `wchar_t`, 크기 타입은 타깃을 따릅니다. 열거형의 기반 타입에도 작은 정수와 큰 정수를 사용할 수 있습니다. 표준 라이브러리는 개발 중입니다.

core v2는 객체 포인터의 오프셋, 차이, 증감 및 복합 대입을 지원하며 배열 순회와 다차원 배열의 간격을 유지합니다. 생성된 보조 함수는 C++17에서 널 포인터에 0을 더하거나 빼는 동작과 널 포인터끼리의 차이를 보존합니다. 객체 포인터 대소 비교도 구현했으며 네이티브 x86/AArch64에서는 독립적으로 검증한 부호 없는 주소 표현을 사용합니다. 네이티브 결과는 해당 커밋의 CI 검증이 필요합니다. 소스의 포인터와 정수 간 변환 및 완전한 STL 지원은 아직 미완료입니다.

core v2는 소스 타입의 크기와 ABI 정렬을 NeverC 자체 타깃 모델과 대조하며, 구조체 크기와 필드 오프셋도 검증합니다. 생성 코드의 컴파일 시점 단언으로 메모리 배치를 다시 확인하고 해당 정보를 매니페스트에 기록합니다.

Core v2는 지원되는 레코드 타입의 이름 있는 비가상 멤버 함수를 지원합니다. const 오버로드, lvalue 한정 메서드, 정적 메서드 및 `this`를 포함합니다. 호출은 원래 객체의 동일성을 유지하며 인수보다 먼저 수신 객체를 평가합니다.

Core v2는 표준 레이아웃과 지원되는 복사 연산을 갖는 레코드의 일반 사용자 정의 생성자도 지원합니다. 지역 객체, 필드와 배열 요소는 최종 저장 위치에 직접 생성되며 필드는 선언 순서대로 초기화됩니다. 예외로 인한 스택 해제는 아직 지원하지 않습니다.

Core v2는 값으로 전달되는 각 레코드 매개변수에 독립된 객체를 만들고 반환값을 호출자의 저장소에 직접 기록합니다. 생성자와 메서드에도 같은 규칙을 적용하며 필요한 복사와 참조의 별칭 관계를 유지합니다. 조건을 만족하는 자명한 타입에서는 다른 C++17 구현이 인수나 반환값을 추가로 복사할 수 있습니다.

Core v2는 일반 사용자 정의 소멸자와 정상 종료 시의 암시적 멤버 소멸을 지원합니다. 지역 객체, 필드와 배열 요소는 역순으로 소멸하며, 임시 객체는 필요한 값을 저장한 뒤 전체 표현식이 끝날 때 정리합니다. 반환, 분기, 반복문, break와 continue에서 필요한 정리를 수행합니다. 값 매개변수는 피호출 함수가 종료될 때 소멸하고 반환 객체는 호출자가 관리합니다. 예외 스택 풀기는 아직 지원하지 않습니다.

Core v2는 원본 매개변수가 `R&` 또는 `const R&`인 일반 사용자 정의 복사 생성자와 복사 대입 연산자를 지원합니다. 실제 대상에서 복사하며 부수 효과와 반환 참조를 유지합니다. 대입 연산자 구문은 오른쪽 피연산자를 먼저 평가하고, 명시적 `operator=` 호출은 수신 객체를 먼저 평가합니다.

Core v2는 컴파일러가 생성하거나 default로 지정한 기본 생성자와 default 소멸자도 지원하며 중첩 레코드 및 배열 멤버를 처리합니다. 실제 대상에서 선언 순서대로 초기화하고, 값 초기화는 C++ 규칙이 요구할 때만 0 초기화를 수행합니다. 클래스 밖의 default 지정에 따른 초기화 차이도 유지합니다. 사용하지 않거나 평가되지 않는 식에만 나타나는 생성자에 별도 함수 본문을 요구하지 않습니다.

Core v2는 암시적 및 default 복사 생성자를 지원하며 중첩 레코드와 다차원 배열도 처리합니다. 선택된 멤버 복사 생성자를 실제 대상에서 선언 및 요소 순서대로 호출하고 원본 배열 주소는 한 번만 평가합니다. 자명한 복사는 저장된 포인터 값을 그대로 유지합니다. 값 전달과 원본 객체 반환은 복사 부수 효과를 유지하며 순수 우측값의 직접 전달에는 추가 복사가 없습니다.

Core v2는 암시적 및 default 복사 대입도 지원합니다. 멤버와 배열 요소의 선택된 대입 연산 및 순서를 유지하며 생성된 자명한 배열 복사는 외부 메모리 복사 호출 없이 타입이 있는 요소 대입으로 변환합니다. 자명한 대입은 저장된 포인터를 유지하고 실제 수신 객체의 참조를 반환합니다. 연산자 구문에서는 원본 참조를 먼저, 명시적 멤버 호출에서는 수신 객체를 먼저 확정한 후 부수 효과가 끝나면 원본 값을 읽습니다. 대입 때문에 객체를 추가로 생성하거나 소멸하지 않습니다.

Core v2는 허용된 필드의 기본 멤버 초기화를 지원하며 앞선 멤버 접근, 일반 호출, 중첩 레코드와 배열을 처리합니다. 선택된 기본값의 `this`는 실제 소유 객체를 가리키고 명시적 집합체 초기화 항목은 호출자의 `this`를 유지합니다. 명시적 초기화는 해당 멤버의 기본값을 대체합니다. 암시적 또는 default 복사와 대입은 기본값을 다시 실행하지 않지만 사용자 복사 생성자는 생략한 멤버의 기본값을 사용할 수 있습니다. 생성자 멤버 초기화와 집합체 초기화는 각자의 임시 객체 정리 경계를 유지합니다. 템플릿과 전체 STL은 개발 중입니다.

Core v2는 이미 살아 있는 객체의 오른값 참조를 지원합니다. 스칼라, 포인터, 레코드와 배열의 별칭, 참조 매개변수와 반환값, 조건식 xvalue 및 일반 `&&` 한정 메서드를 포함합니다. `static_cast<R&&>(live)`는 같은 객체를 유지하며 이름이 있는 오른값 참조 변수는 여전히 왼값입니다. 오버로드와 기존 복사 동작은 Clang의 선택을 따릅니다. 참조는 추가 정리 소유자를 만들지 않습니다.

Core v2는 살아 있는 `R&&` 또는 `const R&&`를 받는 일반 사용자 정의 이동 생성자와 이동 대입을 실행합니다. 생성은 실제 대상 저장소를 사용하며 대입은 원본 변경, 피연산자 평가 순서와 반환된 `R&` 별칭을 보존합니다. `&`／`&&` 한정 대입도 지원합니다. 이름이 있는 오른값 참조는 왼값 오버로드를 선택하고 명시적 생성자는 초기화 규칙을 따릅니다. 이동은 원본 수명을 끝내지 않으며 원본과 대상은 각각 정상 소멸됩니다.

Core v2는 중첩 레코드와 다차원 배열을 포함한 암시적 및 명시적 default 이동 생성과 대입도 지원합니다. 멤버는 선언 및 요소 순서에 따라 C++가 선택한 복사나 이동을 실행합니다. 생성된 이동은 기본 멤버 초기화를 반복하지 않으며 trivial 연산은 저장된 포인터 값을 보존합니다. 원본은 정상 소멸되고 사용하지 않거나 trivial인 생성 연산에는 가상의 본문이 필요하지 않습니다.

Core v2는 해석이 완료된 표준 `noexcept`, `noexcept(true/false)`, C++17 `throw()` 선언과 상수 `noexcept(expression)` 질의를 지원합니다. 질의는 선택된 함수와 소멸자의 예외 명세를 반영하며 피연산자를 실행하지 않습니다. 사용하지 않는 코드를 포함해 모든 피연산자와 작성된 명세를 소스 검사합니다. 예외 발생·포착, 스택 풀기, 템플릿과 전체 STL은 계속 개발 중입니다.

Core v2는 산술, 비교, 첨자, 역참조, 증가, 함수 객체와 일반 대입 시그니처를 포함한 일반 멤버 및 비멤버 연산자 오버로드를 지원합니다. 선택된 함수, 참조 별칭과 객체 결과를 유지합니다. 연산자 표기는 C++17 평가 순서를 따르며 오버로드된 논리 연산자는 두 피연산자를 모두 평가합니다. 비멤버 대입 연산자는 매개변수를 오른쪽부터 초기화한 뒤 역순으로 소멸시킵니다. 템플릿, 메모리 할당과 전체 STL은 계속 개발 중입니다.

Core v2는 살아 있는 객체의 일반 변환 함수도 지원합니다. 암시적·명시적 정수, 열거형, 포인터 변환과 조건식의 명시적 `bool`, 참조 및 객체 반환을 처리합니다. 변환마다 선택된 멤버 함수를 한 번 호출합니다. 참조는 별칭을 유지하고 객체 prvalue는 실제 목적지를 직접 초기화하며, 참조에서 값으로 변환할 때는 선택된 복사나 이동을 수행합니다. const 및 참조 한정자, constexpr, noexcept는 C++17 선택 규칙을 따릅니다.

Core v2는 임시 객체 수신자와 전체 표현식이 끝날 때까지 살아 있는 스칼라·레코드 임시 참조 인수를 지원하며 생성자, 메서드, 연산자 및 변환 함수에 적용됩니다. 평가마다 실제 저장 공간을 사용하고 객체 결과의 최종 목적지와 참조 별칭을 유지합니다. 호출과 피호출 함수의 매개변수 소멸이 끝난 뒤 생성 역순으로 임시 객체를 정리하며 조건 분기와 루프의 반복 평가도 처리합니다. 임시 레코드의 배열 하위 객체도 지원합니다.

Core v2는 `const T& r{T{...}}`와 `T&& r = T{...}`를 포함한 일반 자동 지역 참조의 임시 객체 수명 연장을 지원합니다. 스칼라, 열거형, 포인터 및 레코드 임시 값에 실제 저장 공간을 사용하며 C++에서 수명 연장을 허용하는 멤버·배열 요소 참조는 전체 레코드를 유지합니다. 중괄호 및 등호와 중괄호 초기화도 같은 객체를 보존합니다. 조건, 루프, 조기 종료를 포함해 참조 범위가 끝날 때 소멸하며 초기화 식의 다른 임시 값은 각 전체 표현식이 끝날 때 정리됩니다. 별칭은 소유자를 추가하지 않고 이후 복사와 이동은 선택된 연산을 유지합니다. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#reference-members).

Core v2는 호출, 포인터 변환과 인덱싱, 값을 버리는 표현식, 자동 지역 참조에서 독립된 고정 크기 임시 배열을 지원합니다. 배열마다 실제 목적지 하나를 사용하고 스칼라 저장, 레코드 생성자, 생략된 요소의 기본 초기화를 순서대로 각 요소에 직접 적용합니다. 별도의 요소 소유자는 만들지 않습니다. C++가 수명 연장을 허용하면 다차원 배열의 행·요소 참조가 전체 배열을 유지합니다. 전체 표현식이나 참조 범위가 끝날 때 요소를 역순으로 소멸합니다. 형식이 있는 주소와 기존 크기·저장 공간·확장 제한을 유지합니다. 전체 C++/STL은 개발 중입니다.

Core v2는 빈 표준 레이아웃 클래스와 상태 없는 함수 객체 및 변환 객체를 지원합니다. 빈 객체는 C++의 1바이트 크기와 정렬, 언어가 요구하는 별도 저장 공간, 선택된 생성자·연산자 호출과 정상적인 소멸을 유지합니다. 단순 복사도 피연산자를 평가하며 배열과 포함 레코드의 빈 요소도 저장 한도에 포함됩니다. 생성된 NC는 내부 저장 바이트를 사용하고 원본 필드 목록은 빈 상태로 유지합니다. 상속, 템플릿과 완전한 STL은 개발 중입니다.

Core v2는 void 변환, `void()`, `void{}`를 지원하며 지원되는 void 별칭, 호출, 반환, 쉼표 식과 조건 분기에 사용할 수 있습니다. 비 volatile 좌값을 버릴 때 저장 값을 읽지 않고 수신 객체와 첨자 계산의 부수 효과를 유지합니다. 버리는 임시 객체도 생성되며 원래 전체 표현식 경계에서 소멸합니다. void 변수나 값 저장 공간은 생성하지 않습니다. 상수 식과 noexcept 피연산자도 검사합니다. volatile 객체, 미지원 타입, 템플릿과 완전한 STL은 이번 범위에 포함되지 않습니다.

Core v2는 지원되는 함수, 메서드, 호출 연산자와 사용자 생성자의 기본 인수를 지원합니다. 사용자 복사 및 이동 생성자의 후행 기본 인수도 포함됩니다. 이름은 선언 위치에서 해석하고 인수를 생략하는 호출마다 식을 평가합니다. 참조와 값의 동일성 및 소멸 규칙을 유지합니다. 초기화가 생략된 배열 요소와 생성된 배열 복사는 다음 요소 전에 기본 인수 임시 객체를 소멸시키며, 명시적 배열 초기화 항목은 바깥 전체 표현식까지 유지합니다. 사용하지 않거나 명시적 인수로 대체한 기본 식도 검사합니다. 템플릿과 완전한 STL은 아직 미완성입니다.

## 여러 파일로 구성된 프로젝트

컴파일 데이터베이스에서 번역 단위를 명시적으로 선택하고 프로젝트 루트 디렉터리를 지정합니다. 내장 프런트엔드는 각 단위를 따로 분석하며 병합기는 정의의 완전성, 링크 속성과 공유 타입을 검사하고 단일 정의 규칙(ODR) 준수 여부를 보수적으로 검증합니다.

```sh
neverc translate --from cpp --profile cpp-project-v1 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/a.cpp src/b.cpp --out-dir generated
```

프로젝트 출력은 `translated.nc`와 `translated.h`입니다. 해당 루트 안의 프로젝트 헤더만 허용됩니다. 한 파일에 구성이 여러 개면 `--compdb-entry src/a.cpp=4`로 데이터베이스의 0부터 시작하는 인덱스를 선택합니다. 저장된 컴파일 명령은 데이터로만 분석하며 실행하지 않습니다.

## 제한된 배정밀도 수학 지원

`cpp-math-v1`은 프로젝트에 `double`, 문서에 명시된 변환과 비교, 정확한 시그니처의 `std::fabs(double)` 및 `std::floor(double)`을 추가합니다. 내장된 Clang 20.1.8 / libc++ 200100 / macOS 15.5 헤더 모음을 사용하며 macOS 15.0 대상(arm64 또는 x86_64)을 명시해야 합니다. 일반적인 부동소수점 산술은 지원하지 않습니다. 예외 트랩은 마스킹하고 비정규수를 0으로 만드는 모드는 꺼야 합니다. 네 가지 표준 반올림 모드를 테스트했습니다.

```sh
neverc translate --from cpp --profile cpp-math-v1 \
  --target arm64-apple-macosx15.0.0 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/math.cpp --out-dir generated-math
```

수학 변환은 설치된 NeverC 수학 헤더, 내장 구현의 식별 정보와 실제 링크도 검증합니다. 생성된 수학 모듈은 NeverC 런타임을 사용합니다. `-fno-builtin-std`를 지정하면 최종 출력에 `fabs`/`floor` 매핑이 필요한 경우에만 파일을 쓰기 전에 변환이 실패합니다. 이 매핑이 필요 없는 수학 코드는 계속 변환할 수 있습니다.

## 검증과 출력

출력 옵션 대신 `--check`를 사용하면 같은 분석, 생성, 구문 및 오브젝트 검증을 수행하고 생성 파일을 남기지 않습니다. `--report PATH`는 구조화된 진단을 기록합니다. 변환 과정은 원본 프로그램을 실행하지 않습니다.

출력과 부속 파일은 덮어쓰지 않습니다. `--out-dir`는 기존 부모 디렉터리 아래 새 디렉터리를, `-o`는 새 `.nc` 경로를 요구합니다. 매니페스트는 대상 요구 사항, 입출력 해시와 컴파일 절차를 기록하며 소스 맵은 생성된 행을 원래 위치에 연결합니다.

CI 결과, 실행 및 설치 검증, 건너뛴 테스트는 플랫폼별로 기록합니다. 네이티브 macOS arm64와 Rosetta에서 구동하는 macOS x86_64는 서로 다른 검증 환경으로 구분합니다. 전체 C++／STL, 예외, 제한 없는 템플릿, 문서화된 하위 집합을 벗어나는 문자열·vector 동작은 공개된 지원 범위에 포함되지 않습니다. [지원 표](../../utils/translate-frontends/docs/support-matrix.md), [프로토콜 및 복구 규칙](../../utils/translate-frontends/docs/protocol.md), [프로젝트 예제](../../tests/neverc/Inputs/translate/cpp/project)를 참고하세요.
