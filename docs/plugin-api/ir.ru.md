# IR API плагинов NeverC

Первый публичный ABI плагинов предоставляет LLVM IR через стабильные таблицы C.
Плагины не подключают заголовки LLVM и не должны приводить дескрипторы NeverC к
объектам LLVM.

## Интерфейсы

Запрашивайте интерфейсы из `neverc_plugin_entry` через
`NevercBootstrapAPI.QueryInterface`:

- `NEVERC_INTERFACE_IR_CORE` — запросы о модулях, типах, значениях, CFG,
  метаданных, атрибутах, константах и сериализации.
- `NEVERC_INTERFACE_IR_BUILDER` — транзакционное построение и изменение IR.
- `NEVERC_INTERFACE_IR_ANALYSIS` — встроенные и определяемые плагином анализы.
- `NEVERC_INTERFACE_IR_PASS` — проходы Module, CGSCC, Function и Loop.
- `NEVERC_INTERFACE_IR_GEN` — замена понижения из SemanticUnit в IR.
- `NEVERC_INTERFACE_IR_OPTIMIZATION` — полная замена конвейера оптимизаций.

Всегда запрашивайте пару major/minor из заголовка и проверяйте, что возвращённый
`StructSize` доходит до последнего указателя на функцию, который использует
плагин. Более новый хост может добавлять поля; плагин обязан игнорировать
неизвестный «хвост».

## Дескрипторы и владение

Дескрипторы IR — это непрозрачные пары `{Owner, Value}`, ограниченные задачей.
Всеми объектами, на которые они ссылаются, владеет хост.

- Никогда не сохраняйте дескриптор области задачи после завершения его обратного
  вызова или задачи.
- Никогда не используйте дескриптор в другой сессии или задаче.
- Зафиксированная замена обесценивает дескрипторы заменённых объектов.
- Прерванное изменение делает созданные им дескрипторы устаревшими.
- API сообщают `NEVERC_STATUS_STALE_HANDLE`, `WRONG_OWNER` или `WRONG_TYPE`
  вместо того, чтобы раскрывать указатель LLVM.

Строки и байтовые представления, возвращаемые запросами, одолжены, если только
API явно не возвращает освобождаемый буфер.

## Чтение IR

`NevercIRCoreAPI` предоставляет:

- идентификатор модуля, triple, размещение данных и встроенный ассемблер;
- стабильные курсоры значений для функций, глобалов, блоков, инструкций,
  использований и операндов;
- стабильные идентификаторы типов и опкодов;
- свойства функций, глобалов, инструкций, метаданных и атрибутов;
- целочисленные, вещественные, агрегатные, null-, poison- и undef-константы;
- экспорт и импорт биткода и проверенные артефакты модуля.

Курсоры коллекций ограничены: передайте ёмкость вывода и повторяйте сбор, пока
возвращаемое количество не станет нулевым.

## Транзакционные изменения

Любое структурное изменение выполняется через `NevercIRBuilderAPI`:

1. Начать изменение модуля или функции.
2. Создать построитель, привязанный к этому изменению.
3. Задать точку вставки и строить инструкции, функции или блоки.
4. Зафиксировать изменение.
5. Уничтожить построители и дескриптор изменения.

Фиксация проверяет IR-кандидат и публикует его атомарно. При отказе верификатора
хост откатывает изменение и сохраняет прежний модуль. `AbortMutation` всегда
откатывает подготовленные правки.

Не заявляйте `NEVERC_IR_PRESERVE_ALL` после изменения IR. Адаптер проходов
проверяет поколение модуля и отвергает несогласованное заявление о сохранении.

## Уровни проходов и фазы

`NevercIRPassDescriptor.Level` поддерживает:

- `NEVERC_IR_PASS_LEVEL_MODULE`
- `NEVERC_IR_PASS_LEVEL_CGSCC`
- `NEVERC_IR_PASS_LEVEL_FUNCTION`
- `NEVERC_IR_PASS_LEVEL_LOOP`

Стабильные фазы вставки — `PRE_OPT`, `PIPELINE_START`, `OPTIMIZER_LAST`,
`POST_OPT` и `PRE_CODEGEN`. Вызов содержит только дескрипторы, действительные для
своего уровня. Проходы уровня функции и цикла могут выполняться параллельно,
поэтому изменяемое состояние плагина обязано следовать объявленному контракту
параллелизма.

Хост всегда выполняет финальный запечатанный верификатор IR. Плагин не может
заменить, перехватить или пропустить этот шлюз.

## Анализы

Идентификаторы встроенных анализов покрывают граф вызовов, дерево доминаторов,
дерево постдоминаторов, сведения о циклах, скалярную эволюцию, MemorySSA и анализ
псевдонимов.

Анализы плагина объявляют зависимости и обратные вызовы жизненного цикла.
Результаты кешируются на каждый вызов и обесцениваются согласно результату
сохранения прохода. Рекурсивные циклы зависимостей и изменения из обратного вызова
анализа отвергаются.

## Полные поставщики

Поставщик генерации IR может заменить встроенное понижение и опубликовать
проверенный артефакт модуля. Поставщик оптимизации может заменить весь встроенный
конвейер оптимизаций. Оба пути:

- потребляют явный вход фазы;
- публикуют через API хоста, а не возвращают указатель LLVM;
- проверяют совместимость с целью и корректность модуля;
- атомарно сохраняют старый модуль, если публикация не удалась.

После поставщика оптимизации финальный верификатор остаётся обязательным.

## Минимальный пример

`pluginsdk/examples/FunctionPass.c` — проход уровня функции только для чтения.
`pluginsdk/examples/ExamplePlugin.c` показывает перечисление модуля, а
`pluginsdk/examples/CustomCallConvPlugin.c` демонстрирует атрибуты и свойства
точек вызова.

Собрать и загрузить пример:

```sh
cmake --build build-neverc --target neverc-plugin-example-function-pass
build-neverc/bin/neverc \
  -fplugin=build-neverc/neverc/pluginsdk/examples/host/FunctionPass.so \
  -O2 -c input.c -o input.o
```

Используйте суффикс модуля, который CMake создаёт для вашей платформы.

## Правила отказов

Возвращайте `NevercStatus` из каждого обратного вызова. Отказы плагина становятся
структурированными диагностиками; не выпускайте исключения через границу C.
Инициализируйте каждый заголовок выходной таблицы и зарезервированное поле и
возвращайте `INVALID_ARGUMENT` при отсутствии обязательного указателя.

Нормативные объявления ABI, политики фаз и свидетельства тестов см. в
`PluginIR.h`, `PluginPhaseSchema.h` и `coverage.json`.
