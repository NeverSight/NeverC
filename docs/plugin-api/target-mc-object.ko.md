# 타깃, MC, 어셈블리, 오브젝트 플러그인

NeverC 첫 릴리스의 플러그인 ABI는 C 플러그인이 타깃을 기술하고, 코드 생성 경로를
교체하고, 기계어 방출을 관찰하고, 어셈블리를 파싱하거나 출력하고, 오브젝트 파일을
읽고 쓸 수 있게 합니다. 공개 경계는 순수 C ABI입니다. 플러그인은 LLVM의 C++ 객체,
STL 타입, 예외, 그리고 수명이 API 테이블에 명시되지 않은 호스트 소유 포인터를 경계
너머로 주고받아서는 안 됩니다.

## 호환성 계층

타깃 독립적 디스크립터, 단계 ID, 산출물 ID, MC 컨테이너, ObjectGraph 컨테이너, 출력
트랜잭션, 콜백 계약은 첫 릴리스의 STABLE ABI입니다. 타깃 고유의 명령코드, 레지스터,
오퍼랜드, fixup, 재배치, 호출 규약 스키마는 LOCKSTEP입니다. 플러그인은 LOCKSTEP 값을
사용하기 전에 타깃 스키마 ID와 다이제스트를 비교해야 합니다. NeverC는 프로바이더를
호출하기 전에 일치하지 않는 스키마를 거부합니다.

## 타깃과 코드 생성 경로 등록

등록 중에 `NevercTargetAPI`를 질의하고, 하나 이상의 `NevercTargetDescriptor` 레코드를
등록한 뒤, 타깃 머신 디스크립터와 코드 생성 간선을 붙이십시오. 경로는 정규 타깃
키에서 선택됩니다: 타깃 ID, 트리플, CPU, 기능, ABI, 재배치 모델, 코드 모델, 오브젝트
형식, 스키마 다이제스트.

세분화된 경로는 `IR -> MIR -> MC -> ObjectGraph -> ObjectImage`를 사용합니다. 굵은
간선은 `IR -> ObjectImage` 경로 전체를 교체할 수 있습니다. 굵은 출력이라도 호스트가
강제하는 산출물 검증기와 트랜잭션 출력 커밋을 통과합니다. 프로바이더는 어느 게이트도
우회할 수 없습니다.

## MC 구축과 관찰

`NevercMCAPI`는 태스크 지역 `MCUnit` 변경을 소유합니다. 변경을 시작하고 섹션,
프래그먼트, 심벌, 식, 명령어, 오퍼랜드를 만든 다음 커밋하거나 폐기하십시오. 핸들은
태스크 범위이며 세대 검사를 받습니다.

타깃 독립적 방출 스트림은 섹션 전환, 레이블, 명령어, 정렬, 심벌 속성, CFI, 디버그
위치, 데이터에 대한 순서 있는 이벤트를 제공합니다.
`neverc.mc.emission.pre_instruction`은 교체 가능하며 나머지 이벤트 단계는 읽기 전용
관찰 지점입니다. `pluginsdk/examples/MCObserverPlugin.c`를 참고하십시오.

인코딩, 디코딩, 레이아웃 프로바이더는 동일한 타깃 키와 스키마 다이제스트 위에서
동작합니다. 레이아웃은 완화(relaxation)를 담당하고 증명 다이제스트를 냅니다. 레이아웃
이후의 어떤 변경이든 그 증명을 무효화하며, 오브젝트를 쓰기 전에 재레이아웃을
강제합니다.

## 어셈블리 문법 교체

어셈블리 파서 프로바이더는 소스 바이트를 소비해 `MCUnit`을 게시합니다. 어셈블리
프린터는 `MCUnit`을 소비하며, 제공된 출력 트랜잭션을 통해서만 씁니다. 전처리된
어셈블리(`.S`)는 파서 프로바이더보다 먼저 일반 프런트엔드 전처리기를 거치고, 순수
어셈블리(`.s`)는 곧바로 파서로 들어갑니다.

프로바이더는 먼저 출력을 스테이징합니다. 파싱/출력 검증과 호스트 커밋 게이트는
바이트가 보이기 전에 실행되므로, 실패해도 부분 출력이 남지 않습니다.

## 오브젝트 읽기, 재작성, 쓰기

`NevercObjectAPI`는 재배치 가능 파일을 정규화된 ObjectGraph로 표현합니다. 섹션, 심벌,
재배치, 그룹/COMDAT, 임포트/익스포트, TLS 메타데이터, 되감기 레코드, 디버그 레코드가
포함됩니다. 내장 어댑터는 ELF, COFF, Mach-O를 다루며, 플러그인은 추가 형식을 등록할
수 있습니다.

오브젝트 파이프라인은 다음과 같습니다.

1. 탐지하여 바이트를 ObjectGraph로 읽어 들입니다;
2. `object.pre_write` 그래프 인터셉터를 실행합니다;
3. 레이아웃한 뒤 `object.post_layout`을 실행합니다(변경 후에는 재레이아웃);
4. 한도가 있는 후보 이미지를 씁니다;
5. `object.post_write` 바이너리 인터셉터를 실행합니다;
6. 봉인된 최종 검증기와 원자적 호스트 커밋을 수행합니다.

옵저버는 읽기 전용 브리지를 받습니다. 옵저버에서 변경을 시도하면
`NEVERC_STATUS_POLICY_VIOLATION`으로 거부됩니다. 작성기와 post-write 인터셉터는 한도가
있는 트랜잭션 빌더에만 접근할 수 있습니다. 오버플로, 콜백 실패, 검증 실패는 스테이징을
중단시킵니다. `pluginsdk/examples/ObjectRewritePlugin.c`를 참고하십시오.

## 동시성과 실패 규칙

- 가변 상태는 호스트가 제공하는 process/session/task 상태에 두십시오.
- 콜백이 반환된 뒤 태스크 핸들이나 빌려온 뷰를 캐시하지 마십시오.
- 인터셉터 연속은 콜백 스레드에서 최대 한 번만 호출하십시오.
- 원래의 `NevercStatus`를 반환하고, 부분 산출물을 게시하지 마십시오.
- 가장 좁으면서 사실에 맞는 동시성 및 재진입 모드를 선언하십시오.

실행 가능한 커버리지 계약은 `docs/plugin-api/coverage.json`입니다. 각 안정 단계를
긍정, 부정, 교체, 읽기 전용 옵저버, 봉인 게이트 테스트에 매핑합니다.
