# API плагинов для Source и ввода-вывода

Первый публичный ABI плагинов предоставляет исходные входы, виртуальные файлы,
зависимости и выходы компилятора через `PluginSource.h`. Все пути — это
нормализованные пути VFS, а все дескрипторы ограничены текущей задачей
`TranslationUnit`.

## Фазы source

Стабильный конвейер source таков:

1. `neverc.source.resolve_input` проверяет и нормализует запрошенный вход.
2. `neverc.source.open` открывает его через составную VFS хоста и плагинов.
3. `neverc.source.after_open` публикует событие только для чтения о проверенном
   `SourceUnit`.

`resolve_input` наблюдаема и перехватываема; `open` вдобавок заменяема. Хост
проверяет каждую замену, прежде чем опубликовать её как `SourceUnit`. Плагин не
может заменить `after_open`.

## Поставщики VFS

Запросите `NevercIOAPI` во время регистрации плагина и вызовите
`RegisterVFSProvider`. Поставщик сначала отвечает на `MatchesPath`, затем
реализует операции, за которые отвечает. Возврат
`NEVERC_VFS_RESULT_NOT_HANDLED` передаёт управление следующему поставщику;
возврат `HANDLED` превращает некорректный статус или содержимое в жёсткую
ошибку вместо тихого отката к запасному пути.

Буферы, возвращённые поставщиком, одолжены только на время обратного вызова.
NeverC копирует принятые байты в хранилище, принадлежащее задаче. Поставщики
обязаны объявить, детерминирован ли их результат и можно ли его кешировать.

Собираемый пример
[`VirtualHeaderPlugin.c`](../../pluginsdk/examples/VirtualHeaderPlugin.c)
предоставляет заголовок в памяти, не обходя VFS хоста.

## Приёмники вывода и зависимости

Файловый вывод и вывод в память используют один и тот же транзакционный
приёмник:

- записать в кандидата;
- вызвать finish, чтобы он стал пригоден для проверки;
- дать запечатанному шлюзу хоста проверить его;
- атомарно зафиксировать при успехе задачи или прервать при любой ошибке либо
  отмене.

Плагин никогда не публикует результат прямой записью по конечному пути.
Потоковые назначения, которые нельзя откатить, отвергают преобразования,
требующие атомарного кандидата. Записи о зависимостях используют нормализованные
идентичности VFS, поэтому у собственных файлов и файлов от плагинов одинаковые
происхождение и семантика кеширования.

## Правила безопасности

- Не сохраняйте дескрипторы source, файла, буфера, приёмника или задачи после
  обратного вызова.
- Считайте `NevercStringView` и `NevercByteView` представлениями с явной длиной.
- Используйте аллокатор хоста, если данные должны пережить обратный вызов.
- Не используйте файловые API хоста в обход контракта VFS.
- Проверяйте отмену перед дорогостоящей работой поставщика.
