# NeverC プラグイン MIR API

最初の公開プラグイン ABI は、`PluginMIR.h` を通じて Machine IR を公開します。この
API は安定した C の識別子と不透明ハンドルを使い、プラグインが LLVM のクラス
レイアウト、列挙値、C++ ABI に依存することはありません。

## ネゴシエーション

`NevercMIRAPI` は `NEVERC_INTERFACE_MIR` から、`NevercMIRPassAPI` は
`NEVERC_INTERFACE_MIR_PASS` から取得します。関数ポインタを使う前に返されたテーブル
サイズを確認し、新しいホストが追加したフィールドは無視してください。

スキーマダイジェストは、使用中の安定 ID からホストへの正確な対応付けを識別します。
`GetEntityInfo`、`GetOperandKindInfo`、`GetGenericOpcodeInfo`、
`GetMachinePropertyInfo` は、正規名と、その操作にターゲットスキーマが必要かどうかを
示します。

## 安定モデル

不透明ハンドルが表すのは次のものです。

- マシン関数とベーシックブロック。
- マシン命令とオペランド。
- 変更トランザクション。
- 解析結果。
- 定数プールのエントリ、フレームオブジェクト、ジャンプテーブル、メモリオペランド、
  ターゲット参照。

ハンドルは 1 つのコード生成タスクに属します。消去されたエンティティ、ロールバック
されたエンティティ、変更によって無効化された解析結果は失効します。

汎用スキーマは、ターゲット非依存のオペコード、オペランド種別、マシンプロパティ、
低レベル型、命令フラグ、レジスタ割り当て、フレームオブジェクト、定数、ジャンプ
テーブル、メモリポインタ形式、アトミック順序を扱います。ターゲット固有のオペコード
には、明示的にネゴシエートされたターゲットスキーマが必要です。

## MIR の読み取り

`NevercMIRAPI` がサポートするのは次のとおりです。

- マシン関数のプロパティとブロックの走査。
- 先行・後続ブロック、live-in、命令、オペランドの列挙。
- 命令のオペコードとフラグの問い合わせ。
- 公開されているすべてのマシンオペランド形式。
- 仮想レジスタと物理レジスタの情報。
- フレーム、定数プール、ジャンプテーブル、メモリオペランドの状態。

カウントと問い合わせの組、および上限付き出力バッファを使ってください。返されるビュー
は、特に文書化されていない限り現在のコールバックの間だけ借用されます。

## トランザクショナルな変更

MIR の変更は変更リースの下で行います。

1. マシン関数に対して `BeginMutation`。
2. ブロックと命令の作成、移動、消去。
3. オペランドと CFG エッジの追加または更新。
4. 必要な証明を添えたマシンプロパティの変更適用。
5. `CommitMutation` または `AbortMutation`。

コミットは構造の事前検査と Machine IR の検証を行います。不正なオペランド、CFG、
汎用オペコードの使用、プロパティの主張はアトミックにロールバックされます。アボート
はブロック順序、命令、オペランド、CFG エッジ、マシンプロパティを復元します。

プロパティの変更には `NevercMIRPropertyProof` を使います。証明は、前提が成り立た
なくなったプロパティを無効化するか、プロパティを確立する前に構造検査を要求するかの
いずれかでなければなりません。

## パスとフェーズ

`NevercMIRPassDescriptor.Level` は MachineModule、MachineFunction、
MachineBasicBlock の各アダプタをサポートします。安定したフックは次のとおりです。

- 命令選択の後。
- 正当化（legalization）の後。
- スケジューラの前後。
- レジスタ割り当ての前後。
- プロローグ／エピローグの後。
- pre-emit。
- 最後のプラグインスロット。

関数パスは並列なコード生成パーティションで実行される場合があります。モジュール
レベルのパスは直列化されたパイプラインバリアで実行されます。プラグインが宣言した
並行性と再入可能性の契約は引き続き適用されます。

すべてのコード生成パイプラインは、最後のプラグインスロットの後にホスト所有の
`MachineVerifier` で終わります。これは封印されたゲートであり、プラグインが無効化
することはできません。

## 解析

解析テーブルは、生存変数、生存区間、スロットインデックス、支配木、ループ情報、
レジスタ圧力を公開します。利用可否は選択したフックに依存します。LLVM の解析には、
ネイティブのパイプライン段階の前後には存在しないものがあるためです。

必要な解析と保存する解析をパス記述子で宣言してください。コミットされた変更は影響を
受ける結果ハンドルを無効化します。変更後に preserve-all を主張することは拒否されま
す。

## 最小の例

`pluginsdk/examples/MachinePass.c` は、安定した pre-emit フックに読み取り専用の
マシン関数パスを登録します。

```sh
cmake --build build-neverc --target neverc-plugin-example-machine-pass
build-neverc/bin/neverc \
  -fplugin=build-neverc/neverc/pluginsdk/examples/host/MachinePass.so \
  -O2 -fno-lto -c input.c -o input.o
```

CMake が生成するプラットフォーム固有のモジュール拡張子を使ってください。

## 安全要件

- コールバック後にタスクハンドル、MIR ハンドル、借用したビューを保持しない。
- ハンドル値や LLVM のオペコード番号を捏造しない。
- リースの外で変更しない。
- テーブルヘッダと予約領域を初期化する。
- C の境界を越えてはステータスを返す。C++ 例外を越えさせない。

規範的な宣言とカバレッジの証拠は、`PluginMIR.h`、`MIRSchema.json`、
`PluginPhaseSchema.h`、`coverage.json` を参照してください。
