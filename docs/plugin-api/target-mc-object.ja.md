# ターゲット・MC・アセンブリ・オブジェクトのプラグイン

NeverC の初回リリースのプラグイン ABI では、C のプラグインがターゲットを記述し、
コード生成経路を置き換え、機械語の発行を観測し、アセンブリを解析または出力し、
オブジェクトファイルを読み書きできます。公開境界は純粋な C ABI です。プラグインは
LLVM の C++ オブジェクト、STL 型、例外、および API テーブルで寿命が明示されていない
ホスト所有のポインタを、境界越しにやり取りしてはいけません。

## 互換性のティア

ターゲット非依存の記述子、フェーズ ID、成果物 ID、MC コンテナ、ObjectGraph
コンテナ、出力トランザクション、コールバック契約は、初回リリースの STABLE ABI です。
ターゲット固有のオペコード、レジスタ、オペランド、fixup、再配置、呼び出し規約の
スキーマは LOCKSTEP です。プラグインは LOCKSTEP の値を利用する前に、ターゲット
スキーマ ID とダイジェストを比較しなければなりません。NeverC はプロバイダを呼び出す
前に、一致しないスキーマを拒否します。

## ターゲットとコード生成経路の登録

登録時に `NevercTargetAPI` を照会し、1 つ以上の `NevercTargetDescriptor` レコードを
登録して、ターゲットマシン記述子とコード生成エッジを結び付けます。経路は正準の
ターゲットキー、すなわちターゲット ID、トリプル、CPU、機能、ABI、再配置モデル、
コードモデル、オブジェクト形式、スキーマダイジェストから選択されます。

細粒度の経路は `IR -> MIR -> MC -> ObjectGraph -> ObjectImage` を使います。粗粒度の
エッジは `IR -> ObjectImage` の経路全体を置き換えられます。粗粒度の出力であっても、
ホストが必須とする成果物検証器とトランザクショナルな出力コミットを通過します。
プロバイダはどちらのゲートも迂回できません。

## MC の構築と観測

`NevercMCAPI` はタスクローカルな `MCUnit` の変更を所有します。変更を開始し、
セクション、フラグメント、シンボル、式、命令、オペランドを作成してから、コミット
または破棄します。ハンドルはタスクスコープで、世代チェックが行われます。

ターゲット非依存の発行ストリームは、セクション切り替え、ラベル、命令、アラインメント、
シンボル属性、CFI、デバッグ位置、データについて順序付きイベントを公開します。
`neverc.mc.emission.pre_instruction` は置換可能で、残りのイベントフェーズは読み取り
専用の観測点です。`pluginsdk/examples/MCObserverPlugin.c` を参照してください。

エンコード、デコード、レイアウトの各プロバイダは、同じターゲットキーとスキーマ
ダイジェストの上で動作します。レイアウトは緩和（relaxation）を担い、証明ダイジェスト
を発行します。レイアウト後の変更はその証明を無効化し、オブジェクト書き出し前の再
レイアウトを強制します。

## アセンブリ構文の置き換え

アセンブリパーサのプロバイダはソースバイトを消費して `MCUnit` を発行します。
アセンブリプリンタは `MCUnit` を消費し、与えられた出力トランザクション経由でのみ
書き出します。前処理付きアセンブリ（`.S`）はパーサプロバイダの前に通常のフロント
エンドプリプロセッサを通り、素のアセンブリ（`.s`）は直接パーサに入ります。

プロバイダはまず出力をステージングします。解析／出力の検証とホストのコミットゲートは
バイトが可視になる前に実行されるため、失敗しても部分的な出力は残りません。

## オブジェクトの読み取り・書き換え・書き出し

`NevercObjectAPI` は再配置可能ファイルを正規化された ObjectGraph として表現します。
セクション、シンボル、再配置、グループ／COMDAT、インポート／エクスポート、TLS
メタデータ、巻き戻しレコード、デバッグレコードが含まれます。組み込みアダプタは ELF、
COFF、Mach-O を対象とし、プラグインはさらに別の形式を登録できます。

オブジェクトのパイプラインは次のとおりです。

1. 検査してバイト列を ObjectGraph に読み込む;
2. `object.pre_write` のグラフインターセプタを実行する;
3. レイアウトし `object.post_layout` を実行する（変更後は再レイアウト）;
4. 上限付きの候補イメージを書き出す;
5. `object.post_write` のバイナリインターセプタを実行する;
6. 封印された最終検証器とアトミックなホストコミットを実行する。

オブザーバは読み取り専用のブリッジを受け取ります。オブザーバから変更を試みると
`NEVERC_STATUS_POLICY_VIOLATION` で拒否されます。ライタと post-write インターセプタ
がアクセスできるのは、上限付きのトランザクショナルビルダだけです。オーバーフロー、
コールバックの失敗、検証の失敗はステージングを中止させます。
`pluginsdk/examples/ObjectRewritePlugin.c` を参照してください。

## 並行性と失敗の規則

- 可変状態はホストが供給する process/session/task の状態に保持する。
- コールバックから戻った後にタスクハンドルや借用ビューをキャッシュしない。
- インターセプタの継続はコールバックスレッド上で最大 1 回だけ呼び出す。
- 元の `NevercStatus` を返す。部分的な成果物を発行しない。
- 並行性と再入可能性は、最も狭くかつ真実であるモードを宣言する。

実行可能なカバレッジ契約は `docs/plugin-api/coverage.json` です。各安定フェーズを、
肯定、否定、置換、読み取り専用オブザーバ、封印ゲートの各テストに対応付けます。
