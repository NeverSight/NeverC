# API плагинов для AST, парсера и семантики

`PluginAST.h` и `PluginSema.h` дают ограниченный задачей доступ на чистом C к
дереву фронтенда и семантическому конвейеру. Стабильные идентификаторы узлов,
свойств и дочерних слотов порождаются из конкретных определений AST в NeverC;
плагин никогда не получает C++-указатель на `Decl`, `Stmt`, `Type` или `Sema`.

## Чтение и построение узлов AST

Используйте `NevercASTAPI`, чтобы запрашивать сведения об узлах, свойства схемы,
детей, родителей, контексты объявлений, типы, атрибуты и подробности
распространённых конкретных узлов. Пакетные API требуют явно указывать число
элементов, ёмкость и шаг.

`NevercASTBuilder` строит только те разновидности узлов, которые объявлены в
схеме. Обязательные свойства и дочерние слоты проверяются при фиксации. Успешная
фиксация публикует узел, принадлежащий задаче; неудачная не оставляет частично
видимых узлов. Уничтожайте каждый построитель после фиксации или отказа.

## Атомарное изменение

Изменения AST выполняются через `BeginASTMutation`, подготовленные операции и
`CommitASTMutation`. Прежде чем менять дерево, хост проверяет принадлежность,
совместимость слотов, кратность, родительские связи, циклы и семантические
инварианты. `AbortASTMutation` отбрасывает все подготовленные операции.
Уведомления нативного `TreeMutationListener` отправляются только после успешной
фиксации.

Собираемый пример
[`ASTRewritePlugin.c`](../../pluginsdk/examples/ASTRewritePlugin.c) показывает
перехватчик парсера, который вызывает встроенный парсер, строит целочисленный
литерал и атомарно заменяет инициализатор переменной.

## Замена парсера и Sema

`neverc.syntax.parse` отображает проверенный поток токенов в `ASTUnit`.
`neverc.sema.analyze` отображает продукт AST в `SemanticUnit`. У обеих фаз есть
типизированные перехватчики и поставщики. Мелкогранулярные фазы расширения —
объявление, оператор, выражение, имя типа, атрибут, поиск имён, преобразование и
ключевое слово — остаются доступными, если заменяется лишь часть фронтенда.

Встроенный слитный путь парсера и Sema публикует ровно те же контракты
артефактов, что и замена. Семантическое воспроизведение принимает только те
разновидности узлов, для которых NeverC может восстановить область видимости,
поиск имён, повторное объявление и состояние проверки типов. При встрече с
неподдерживаемой конкретной разновидностью возвращается
`NEVERC_STATUS_UNSUPPORTED_AST_KIND`; частично воспроизведённое дерево никогда не
помечается как семантически полное.

## Жизненный цикл и очистка

Наблюдатели жизненного цикла AST и Sema доставляются в порядке исходного текста
через мост `TreeConsumer` хоста. События начала и конца остаются парными при
синтаксических ошибках, ошибках плагина и отмене. Дескрипторы задачи становятся
недействительными только после того, как отработают заключительные события
только для чтения и обратные вызовы очистки.

## Проверка

```sh
python3 utils/plugin-api/gen-ast-schema.py --check
ctest --test-dir build-neverc \
  -R 'Plugin(AST|Parser|Sema|Frontend)' --output-on-failure
```

При `NEVERC_ENABLE_PLUGIN_FUZZERS=ON` `plugin-ast-mutation-fuzzer` охватывает
декодирование свойств, некорректные построители, поддельные дескрипторы и откат
изменений.
