# 將 C++ 轉譯為 NeverC

Core v2 現支援內建且固定版本的 `<type_traits>`，用於編譯期型別別名以及整數／列舉常數。`std::remove_cv_t`、`std::is_same_v`、已支援的建構／解構 traits 與 `std::integral_constant::value` 會降為現有核心型別及常值。驅動程式會驗證並記錄 101 個 libc++／resource 標頭雜湊，涵蓋支援的 macOS、Linux 與 Windows 目標。執行期 trait 支援僅限下文列出的、經過驗證的函式指標 `integral_constant` 形式；其他 trait 物件與 trait 儲存身分仍不受支援。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#compile-time-type_traits).

Core v2 也支援內建且固定版本的 `<cstdint>`。固定、least、fast、指標和最大寬度型別別名，以及標準上下界與常數巨集，都會保留所選目標的 C++17 型別和值。驅動程式會記錄獨立使用時的 9 個標頭閉包，拒絕引號形式與 C 標頭形式，並允許 `<cstdint>` 與 `<type_traits>` 以任意順序組合。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#fixed-width-integers-from-cstdint).

Core v2 也支援固定版本的 `<limits>`。已支援整數、`float` 和 `double` 的 `numeric_limits` 整數／列舉資料成員與標準零參數查詢會折疊為精確常值，包括無窮值和 NaN。16 個檔案的閉包會在所有目標上通過驗證；執行期物件、儲存或方法身分、物件限定呼叫及 `long double` 仍不受支援。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#numeric-bounds-from-limits).

Core v2 也支援固定版本的 `<cstddef>`。目標相關的 `size_t`、`ptrdiff_t` 與 `nullptr_t` 別名、`NULL`、經檢查的 `offsetof` 及 `max_align_t` 版面查詢不需 libc++ 即可降低；`std::byte` 儲存、位元／移位運算與 `to_integer` 會直接降低為純量運算。29 個檔案的閉包會在所有目標上通過驗證；引號／C 標頭形式、原始內建式與標準函式位址仍會被拒絕。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#fundamental-types-and-bytes-from-cstddef).

Core v2 也支援固定版本的 `<new>`。其 37 個檔案的閉包在所有支援的目標上完全一致，且不含平台相關內容。`std::nothrow_t`、`std::align_val_t` 與 C++17 干擾大小常數保持為編譯期或純量中繼資料；對已接納的非 volatile 物件指標進行的精確 `std::launder` 呼叫會直接降低，且引數只求值一次。精確的標準單物件及常數長度陣列 placement new 運算式也會重用已擷取的儲存，不需執行期呼叫。直接呼叫配置函式、nothrow 物件、函式位址與預設堆積操作仍不在支援範圍內。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#new-header-from-new).

純 `std::launder` 型別與 `noexcept` 查詢現在可準備精確的限定、巢狀及來源記錄 `std::reference_wrapper` 配置，也支援來源函式的指標參數；查詢不讀取指標，也不選取 SDK 函式本體或物件生命週期。原始運算元、別名、模板引數、預設引數及來源函式本體仍會檢查；使用者替換宣告與獨立 SDK 函式位址仍遭拒絕。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#new-header-from-new).

巢狀 `vector` 的範圍置入也支援可複製內層元素的精確原始指標、陣列退化和已驗證包裝迭代器。端點綁定只擷取一次；端點值在外層配置後、內層配置前讀取。空範圍不配置內層緩衝區。來源範圍可以來自目標容器，複製後的資源保持獨立。需轉換的範圍、反向或任意迭代器及只能移動的元素仍受既有限制。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#vector-header-and-metadata-from-vector).

巢狀 `vector` 元素也可從精確匹配的 `std::initializer_list<T>` 置入，支援直接暫存列表、常數列表和空列表。列表指標和大小在外層配置後讀取，並在內層配置前儲存。資源元素沿用既有複製操作，直接 SDK 回呼常數按值複製。暫存底層陣列保持所需生命週期；使用者定義的列表轉換和 SDK 儲存別名仍受既有限制。 [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#vector-header-and-metadata-from-vector).

## 安裝與純量轉譯

使用正常安裝的 NeverC 及其標準資源即可。C++ 前端與核准的 SDK 標頭均已內建，無需另行安裝 Clang。建置細節見[前端說明](../../utils/translate-frontends/cpp/README.md)。

```sh
neverc translate --from cpp input.cpp -o output.nc
neverc output.nc -c -o output.o
```

`cpp-core-v1` 接受一個不含 include 的獨立 C++17 原始檔，支援 `int`、`unsigned int`、`bool`、`void`、簡單聚合型別、自由函式、命名空間、多載及文件列出的控制流程。所有輸入宣告都會檢查，包括未使用的程式碼。

使用 `--profile cpp-core-v2` 可增加經過檢查的 `typedef`／`using` 型別別名、底層型別為受支援整數型別的列舉、`static_assert`，以及限定範圍的物件指標與左值參考。參考保留別名關係，包括參數和回傳參考；支援多層指標的 `const` 與空指標。仍限單一原始檔，且不允許 include。詳見 [core v2 支援範圍](../../utils/translate-frontends/docs/cpp-core-v2.md)。

core v2 也增加了固定長度的區域陣列與陣列欄位、多維下標存取，以及陣列指標和參考。部分初始化將省略的純量元素設為零，紀錄元素依所選的初始化方式處理；元素初始化保留原始碼順序與別名關係。陣列長度與初始化展開量有上限。 全域陣列與變長陣列仍未支援。

core v2 支援 `switch`／`case`／`default`，包括 C++17 初始化陳述式、分支貫穿及經過驗證的 `[[fallthrough]]` 標註。選擇器只求值一次；巢狀 switch 與迴圈保留各自的 `break`／`continue` 目標。GNU case 範圍及其他陳述式屬性仍被拒絕。

Core v2 現支援有號與無號的 8／16／32／64 位整數、字元型別與常值，以及常數 `sizeof`／`alignof` 查詢。先依來源 C++ 規則完成整數提升與多載解析，再將位元寬度標準化；`long`、`wchar_t` 與大小型別遵循目標平台。列舉也支援窄整數與寬整數作為底層型別。標準函式庫仍在開發中。

Core v2 另支援物件指標偏移、差值、遞增／遞減及複合賦值，可用於走訪陣列並保留多維陣列的步長。產生的輔助函式保留 C++17 空指標加減零及空指標相減的行為。物件指標大小比較也已接入，在原生 x86／AArch64 目標上使用獨立驗證的無符號位址表示；原生結果仍需對應提交的 CI 驗證。原始碼指標／整數轉換與完整 STL 仍未完成。

Core v2 會用 NeverC 自身的目標模型核對來源型別的大小與 ABI 對齊，包括結構體大小和欄位偏移。產生的程式碼透過編譯期斷言再次檢查配置，清單也會記錄這些驗證依據。

Core v2 支援已接納的紀錄型別中的具名非虛擬成員函式，包括 const 多載、左值限定方法、靜態方法和 `this`。呼叫保留原物件身分，並在引數之前求值接收物件。

Core v2 也支援具有標準布局及受支援複製操作的紀錄型別的一般使用者建構函式。區域物件、紀錄欄位與陣列元素直接在最終儲存位置建構，欄位依宣告順序初始化。例外展開仍未支援。

Core v2 為每個以值傳遞的紀錄參數建立獨立物件，並將紀錄回傳值直接寫入呼叫者的目標位置。建構函式與成員函式採用相同規則；原始碼要求的複製與參考別名仍會保留。對於符合條件的平凡紀錄型別，其他 C++17 實作可能增加參數或回傳值的複製。

Core v2 支援一般使用者解構函式，以及正常離開時的隱含成員解構。區域物件、紀錄欄位與陣列元素以反向順序解構；暫存物件在完整運算式結束時清理，先保存需要使用的值。回傳、分支、迴圈、break 與 continue 均執行對應清理。以值傳遞的參數在被呼叫函式結束時解構，回傳物件由呼叫者管理。例外展開仍未支援。

Core v2 支援來源參數為 `R&` 或 `const R&` 的一般使用者複製建構與複製指定函式。複製直接作用於實際目標，保留函式的副作用與回傳參考。指定運算子語法先求值右運算元，明確呼叫 `operator=` 時先求值接收物件。

Core v2 也支援編譯器產生或明確 default 的預設建構函式，以及 default 解構函式，包括巢狀紀錄與陣列成員。預設建構使用實際目標位置，並依宣告順序初始化成員；值初始化只執行 C++ 規則要求的清零。類別外 default 保留其不同的初始化規則。未使用或僅出現在未求值運算式中的 default 建構不要求額外產生函式本體。

Core v2 支援隱含及明確 default 的複製建構，包括巢狀紀錄與多維陣列。選定的成員複製建構依宣告及元素順序在實際目標位置執行，來源陣列位址只計算一次。平凡複製保留已儲存的指標欄位原值。按值傳參與從來源物件回傳保留複製副作用，直接轉送純右值不會額外複製。

Core v2 也支援隱含及明確 default 的複製指定。成員與陣列元素保留選定的指定操作及其順序，產生的平凡陣列複製轉為具型別的元素指定，無需外部記憶體複製呼叫。平凡指定保留指標欄位原值並回傳實際接收物件。運算子語法先擷取來源參考，明確成員呼叫先擷取接收物件；來源值在這些副作用完成後讀取，指定不會額外建構或解構物件。

Core v2 支援已准入欄位的預設成員初始化器，包括存取先前成員、一般呼叫、巢狀記錄與陣列。選中的預設值使用實際所屬物件作為 `this`，明確的聚合初始化項保留呼叫者的 `this`；明確初始化會覆蓋對應成員的預設值。隱含或 default 複製及指定不重跑預設值，使用者複製建構函式可為省略的成員選用預設值。建構成員初始化與聚合初始化各自保留暫存物件的清理邊界。樣板與完整 STL 仍在開發中。

Core v2 支援指向既有存活物件的右值參考，包括純量、指標、記錄與陣列別名、參考參數／回傳值、條件亡值及一般 `&&` 限定方法。`static_cast<R&&>(live)` 等轉換保留同一個物件，具名右值參考變數仍是左值。多載與既有複製行為遵循 Clang 的選擇，參考不會增加清理擁有者。

Core v2 支援以存活的 `R&&` 或 `const R&&` 為來源的一般使用者移動建構與移動指定。建構使用實際目標；指定保留來源修改、運算元求值順序與回傳的 `R&` 別名，並支援 `&`／`&&` 限定的接收物件。具名右值參考仍選擇左值多載，明確建構函式保留其初始化規則。移動不會結束來源物件的生命週期，來源與目標仍各自正常解構。

Core v2 也支援隱含及明確 default 移動建構與移動指定，包括巢狀記錄與多維陣列。成員依宣告與元素順序執行 C++ 選中的複製或移動。產生的移動不重跑預設成員初始化器，平凡操作保留已儲存的指標值。來源物件仍正常解構，未使用或平凡的產生操作不需要虛構函式主體。

Core v2 支援已解析的標準 `noexcept`、`noexcept(true/false)`、C++17 `throw()` 宣告，以及常數 `noexcept(expression)` 查詢。查詢保留選定函式與解構函式的例外規格，不執行運算元。所有運算元與手寫規格仍接受原始碼檢查，包括未使用的程式碼。擲出、捕捉、堆疊展開、樣板與完整 STL 仍在開發中。

Core v2 支援一般成員及自由多載運算子，包括算術、比較、下標、解參考、遞增、函式物件與一般指定簽章。呼叫保留選定函式、參考別名及物件結果。運算子語法遵循 C++17 求值順序，多載邏輯運算子會求值兩個運算元。自由指定運算子統一由右向左初始化參數，再依反向順序解構。樣板、記憶體配置與完整 STL 仍在開發中。

Core v2 也支援現存物件上的一般轉換函式：隱式與顯式整數、列舉及指標轉換，條件中的顯式 `bool`，以及參考或物件結果。每次轉換執行一次選定的成員函式。參考保留別名；物件純右值直接初始化實際目標，從參考初始化值則保留選定的複製或移動。const／參考限定、constexpr 與 noexcept 遵循 C++17 選擇規則。

Core v2 現支援暫存物件接收者，以及存活到完整運算式結束的純量／記錄暫存參考引數，涵蓋建構函式、方法、運算子與轉換函式。每次求值都有實際儲存，物件結果保留最終目標，參考保留別名。呼叫及被呼叫函式的參數解構完成後，暫存物件依建構反向順序清理，並正確處理條件分支與迴圈中的重複求值。暫存記錄物件的陣列子物件也受支援。

Core v2 現支援普通自動區域參考延長暫存物件的生命週期，包括 `const T& r{T{...}}` 與 `T&& r = T{...}`。純量、列舉、指標及記錄暫存值使用實際儲存；C++ 規定延長生命週期時，指向成員或陣列元素的參考會保留完整記錄物件。大括號及等號加大括號初始化保留同一個物件。物件在參考所屬範圍結束時解構，涵蓋條件、迴圈與提前離開；初始化器內其他暫存物件仍在各自完整運算式結束時清理。別名不增加擁有者，後續複製或移動保留選定操作。[C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#reference-members).

Core v2 也支援獨立固定長度陣列暫存值，可用於呼叫、退化／下標存取、捨棄運算式及自動區域參考。每個陣列使用一個實際目標；純量寫入、記錄建構與共用預設填補依序直接初始化各元素，不增加元素擁有者。C++ 規定延長生命週期時，多維陣列的列／元素參考會保留完整陣列。元素在完整運算式或參考範圍結束時依反向順序解構。陣列參考保留有型別的位址，仍遵守既有維度、儲存與展開限制。完整 C++／STL 仍在開發中。

Core v2 支援空的標準配置類別及無狀態的函式物件／轉換物件。空物件保留 C++ 的一位元組大小與對齊、語言要求的獨立儲存、選定建構／運算子呼叫及正常解構。平凡複製仍會求值運算元；陣列及含空成員的記錄會計入儲存限制。產生的 NC 使用一個內部儲存位元組，來源欄位仍為空。繼承、範本與完整 STL 仍在開發中。

Core v2 支援轉為 void、`void()` 和 `void{}`，可結合受支援的 void 別名、呼叫、回傳、逗號運算式及條件分支。捨棄非 volatile 左值時保留接收者／下標的副作用而不讀取其儲存值；捨棄暫存物件仍會建構物件，並在原有完整運算式邊界解構。不會產生 void 變數或值載體。常量與 noexcept 的運算元仍完整檢查。volatile 物件、不支援的運算元型別、範本及完整 STL 不在本次增量範圍內。

Core v2 支援允許的函式、方法、呼叫運算子及使用者建構函式的預設引數，包括使用者複製／移動建構函式的尾隨預設引數。名稱依宣告位置解析，預設運算式在每次省略引數的呼叫中求值。參考和值參數保留原有身分與清理規則。陣列遺漏元素及產生的陣列複製會在下一個元素前清理預設引數暫存物件；明確的陣列初始化項保留外層完整運算式壽命。未使用或被明確引數覆蓋的預設值仍會檢查。範本與完整 STL 尚未完成。

## 多檔案專案

從編譯資料庫明確選擇翻譯單元，並指定專案根目錄。內建前端逐一分析翻譯單元，合併器檢查定義完整性、連結屬性及共用型別，並保守驗證單一定義規則（ODR）。

```sh
neverc translate --from cpp --profile cpp-project-v1 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/a.cpp src/b.cpp --out-dir generated
```

專案輸出為 `translated.nc` 與 `translated.h`，僅允許該根目錄內的專案標頭檔。檔案有多種組態時，以 `--compdb-entry src/a.cpp=4` 選擇編譯資料庫的零起始索引。儲存的編譯命令僅作為資料解析，絕不執行。

## 有限的雙精度數學支援

`cpp-math-v1` 在專案支援上增加 `double`、文件列出的轉換／比較，以及精確簽章 `std::fabs(double)` 和 `std::floor(double)`。它使用內建的 Clang 20.1.8／libc++ 200100／macOS 15.5 標頭集合，要求明確的 macOS 15.0 目標（arm64 或 x86_64）。暫不支援通用浮點算術。浮點環境要求遮罩例外陷阱且停用非正規數歸零模式；四種標準捨入模式均已測試。

```sh
neverc translate --from cpp --profile cpp-math-v1 \
  --target arm64-apple-macosx15.0.0 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/math.cpp --out-dir generated-math
```

數學轉譯還會驗證已安裝的 NeverC 數學標頭、嵌入實作的身分，並實際執行連結探測。產生的數學模組使用 NeverC 執行階段函式庫。使用 `-fno-builtin-std` 時，僅當最終輸出需要 `fabs`／`floor` 映射才會在寫入前失敗；無需這些映射的數學程式碼仍可轉譯。

## 驗證與輸出

以 `--check` 取代輸出選項，可執行相同的分析、產生、語法與目的碼驗證，但不保留產生的檔案。`--report PATH` 寫入結構化診斷。轉譯過程不會執行原始程式。

輸出及附屬檔案不會覆寫既有檔案。`--out-dir` 要求父目錄存在且目標目錄不存在；`-o` 要求新的 `.nc` 路徑。清單記錄目標需求、輸入／輸出雜湊及編譯方式，原始碼映射將產生行對應至原始位置。

CI 結果、執行與安裝驗證以及測試跳過項目依平台分別記錄。原生 macOS arm64 與透過 Rosetta 執行的 macOS x86_64 仍是不同的驗證環境。完整 C++／STL、例外、不受限制的範本，以及超出文件所述子集的字串／vector 行為，均不在已公布的支援範圍內。請參閱[支援矩陣](../../utils/translate-frontends/docs/support-matrix.md)、[協定與復原規則](../../utils/translate-frontends/docs/protocol.md)及[專案範例](../../tests/neverc/Inputs/translate/cpp/project)。
