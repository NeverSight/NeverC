# `neverc run`

Компилирует программу на C или NeverC во **временный исполняемый файл**, запускает его на **локальном хосте**, возвращает код выхода и затем удаляет артефакт. Поток намеренно похож на `go run`.

Чтобы сохранить бинарник, распространять его или отлаживать, используйте обычный вызов компилятора (`neverc ... -o output`).

## Синтаксис

```text
neverc run [флаги компилятора] file.c [file2.nc ...] [аргументы программы...]
neverc run [аргументы компилятора...] -- [аргументы программы...]
```

`neverc run --help` также показывает встроенную сводку.

## Разбор аргументов

`neverc run` делит аргументы на **вызов компилятора** и необязательные **аргументы программы** по одному из двух правил.

### Разделение по умолчанию (в стиле Go)

1. Сканировать слева направо до первого аргумента, оканчивающегося на `.c` или `.nc` и не начинающегося с `-`.
2. **Все аргументы до конца непрерывной серии `.c`/`.nc` включительно** (вместе с тем, что перед первым исходником) передаются компилятору.
3. **Всё после** серии передаётся в `argv` временной программы.

Примеры:

```bash
neverc run -O2 -fbuiltin-string hello.c
neverc run -O2 main.c helper.nc -- --verbose two words
neverc run -DGENERATED=.c -O2 main.c argument
```

Примечания:

- Источниками run считаются только `.c` и `.nc`. Флаг `-DGENERATED=.c` остаётся на стороне компилятора.
- Несколько исходников собираются в один временный бинарник, как при обычной многфайловой линковке.

### Явный разделитель `--`

Когда компилятору нужны аргументы **после** списка исходников (флаги линковки, неисходные входы, `-x c -` и т. п.), поставьте `--` между хвостом компилятора и аргументами программы:

```bash
neverc run hello.c helper.o -lm -- arg.c -x
neverc run hello.c -O1 -- x
```

Всё до `--` передаётся в `neverc` (плюс внутренний `-o <temp>`). Всё после `--` становится аргументами программы.

## Поведение во время выполнения

| Тема | Поведение |
|------|-----------|
| Рабочий каталог | Временная программа запускается в **текущем каталоге** |
| Окружение | Наследует текущее окружение (`PATH`, экспортированные переменные и т. д.) |
| Стандартный ввод/вывод | stdin/stdout/stderr подключены к временному процессу |
| Код выхода | При успехе — код **программы**; при ошибке компиляции — код **компилятора** без запуска программы |
| Временные файлы | Исполняемый файл в `neverc-run-*`; каталог удаляется после выполнения. Сбой очистки сообщается отдельно. |

## Примеры

```bash
neverc run -O2 -fbuiltin-string hello.c
neverc run -fbuiltin-string greet.c -- Alice "two words"
neverc run -O2 main.c util.nc -- --port 8080
neverc run app.c extra.o -lm -- --config prod.json
```

## Ограничения и замечания

- **Только локальный запуск.** Флаги кросс-компиляции (`-target ...`) могут скомпилировать, но временный бинарник всегда выполняется на хосте.
- **Нет постоянного артефакта.** Бинарник удаляется по завершении — для отладки используйте `neverc ... -o out`.
- **Тот же toolchain, что у `neverc`.** Команда повторно вызывает тот же бинарник `neverc`.
- **Исходники `.nc`.** Те же правила, что для `.c`; расширения NeverC применяются автоматически.

## Связанные команды

| Команда | Когда использовать |
|---------|-------------------|
| `neverc file.c -o out` | Сохранить бинарник, кросс-компиляция, скрипты сборки |
| `neverc build` / `neverc make` | Проектная сборка с `neverc.toml` |
| `neverc run --help` | Встроенная сводка |
