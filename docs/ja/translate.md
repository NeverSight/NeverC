# C++ を NeverC に変換する

実験的な `neverc translate` は `cpp-core-v1`、`cpp-core-v2`、`cpp-project-v1`、`cpp-math-v1` でレビュー可能な `.nc` ソースを生成します。

**現在、入力言語として実装されているのは C++ のみです。** E Language（易言語、`.e`）、Python、Go、Rust、TypeScript、JavaScript への対応は今後の計画であり、これらの変換機能はまだ利用できません。

## 準備とスカラー変換

通常の NeverC と標準リソースをインストールすれば利用できます。C++ フロントエンドと承認済み SDK ヘッダーは内蔵されており、Clang の別途インストールは不要です。ビルドの詳細は[フロントエンドの説明](../../utils/translate-frontends/cpp/README.md)を参照してください。

```sh
neverc translate --from cpp input.cpp -o output.nc
neverc output.nc -c -o output.o
```

`cpp-core-v1` は include のない単一の C++17 ソースを受け付けます。`int`、`unsigned int`、`bool`、`void`、単純な集成体型、非メンバー関数、名前空間、オーバーロード、および文書化された制御フローをサポートします。未使用のコードを含め、入力に含まれるすべての宣言を検査します。

`--profile cpp-core-v2` を選択すると、検査済みの `typedef`／`using` 型エイリアス、対応する整数型を基底型とする列挙型、`static_assert`、限定されたオブジェクトポインターと左辺値参照を追加で変換できます。参照引数と参照戻り値は元のオブジェクトを参照し、多段ポインターの `const` とヌルポインターにも対応します。単一ソースと include 禁止の制限は継続します。[core v2 の対応範囲](../../utils/translate-frontends/docs/cpp-core-v2.md)を参照してください。

core v2 は固定長のローカル配列と配列フィールド、多次元の添字アクセス、配列へのポインターと参照にも対応します。部分初期化では省略されたスカラー要素をゼロ初期化し、レコード要素には選択された初期化を適用します。要素の初期化順序とエイリアス関係を保持します。配列長と初期化の展開量には上限があります。 グローバル配列と可変長配列は未対応です。

core v2 は C++17 の初期化文、フォールスルー、検証済みの `[[fallthrough]]` 注釈を含む `switch`／`case`／`default` に対応します。条件値の評価は一度だけ行い、入れ子の switch とループでも `break`／`continue` の対象を保持します。GNU の case 範囲とその他の文属性は未対応です。

core v2 は符号付き・符号なしの 8／16／32／64 ビット整数、文字型と文字リテラル、定数の `sizeof`／`alignof` に対応します。ソースの整数昇格とオーバーロード解決の後にビット幅を正規化し、`long`、`wchar_t`、サイズ型は対象環境に従います。列挙型の基底型にも狭い整数と広い整数を使用できます。実行時文字列と STL は開発中です。

core v2 はオブジェクトポインターの加減算、差分、インクリメント／デクリメント、複合代入にも対応し、配列の走査と多次元配列の要素間隔を維持します。生成する補助関数は C++17 のヌルポインターへのゼロの加減算とヌルポインター同士の差分を保持します。ポインターの大小比較、ポインターと整数の変換、STL コンテナーとアルゴリズムは未対応です。

core v2 はソース型のサイズと ABI アラインメントを NeverC 自身のターゲットモデルと照合し、構造体のサイズとフィールドのオフセットも検証します。生成コードのコンパイル時アサーションで配置を再確認し、その情報をマニフェストに記録します。

Core v2 は、対応するレコード型の名前付き非仮想メンバー関数を扱えます。const オーバーロード、左辺値修飾メソッド、静的メソッド、`this` に対応し、元のオブジェクトの同一性を保ち、引数より先に呼び出し対象を評価します。

Core v2 は標準レイアウトで対応するコピー操作を持つレコード型の通常のユーザー定義コンストラクターにも対応します。ローカル変数、フィールド、配列要素は最終的な格納位置で直接構築し、フィールドは宣言順に初期化します。委譲コンストラクターと例外は未対応です。

Core v2 は値渡しのレコード引数ごとに独立したオブジェクトを作り、戻り値を呼び出し側の格納先に直接書き込みます。コンストラクターとメソッドにも同じ規則を適用し、必要なコピーと参照の別名関係を維持します。条件を満たす自明な型では、他の C++17 実装が引数や戻り値を追加でコピーする場合があります。

Core v2 は通常のユーザー定義デストラクターと、正常終了時の暗黙のメンバー破棄に対応します。ローカルオブジェクト、フィールド、配列要素は逆順に破棄し、一時オブジェクトは必要な値を保存してから完全式の終わりに破棄します。return、分岐、ループ、break、continue で必要な破棄を行います。値引数は呼び出された関数の終了時に破棄し、戻り値のオブジェクトは呼び出し側が管理します。明示的なデストラクター呼び出し、静的オブジェクトの破棄、例外の巻き戻しは未対応です。

Core v2 はソース引数が `R&` または `const R&` の通常のユーザー定義コピーコンストラクターとコピー代入演算子に対応します。実際の格納先でコピーし、副作用と返された参照を保持します。代入演算子の構文では右辺を先に評価し、明示的な `operator=` 呼び出しでは呼び出し対象を先に評価します。

Core v2 は、生成されたデフォルトコンストラクター、default 指定のデフォルトコンストラクターとデストラクターにも対応し、入れ子のレコードや配列メンバーも扱います。実際の格納先で宣言順に初期化し、値初期化では C++ が要求する場合だけゼロ初期化を行います。クラス外での default 指定に固有の初期化規則も保持します。未使用または未評価式だけに現れるコンストラクターに、余分な関数本体を要求しません。

Core v2 は暗黙および default 指定のコピーコンストラクターに対応し、入れ子のレコードや多次元配列も扱います。選択されたメンバーコピーを宣言順・要素順に実際の格納先で実行し、コピー元配列のアドレスは一度だけ評価します。自明なコピーでは格納済みポインターの値を保持します。値渡しと元のオブジェクトからの戻り値はコピーの副作用を保持し、純粋右辺値の直接転送では追加コピーを行いません。

Core v2 は暗黙および default 指定のコピー代入にも対応します。メンバーと配列要素は選択された代入と順序を保持し、生成された自明な配列コピーは外部のメモリーコピー呼び出しを使わず型付きの要素代入になります。自明な代入は格納済みポインターを保持し、実際の呼び出し対象への参照を返します。演算子構文ではソース参照を先に、明示的なメンバー呼び出しでは対象を先に確定し、その副作用の後でソース値を読みます。代入のために追加の構築や破棄を行いません。

Core v2 は対応フィールドのデフォルトメンバー初期化子をサポートし、先行メンバーの参照、通常の呼び出し、入れ子のレコードと配列を扱います。選択されたデフォルトの `this` は実際の所有オブジェクトを指し、明示的な集成体初期化節では呼び出し元の `this` を保ちます。明示的な初期化は対象メンバーのデフォルトを上書きします。暗黙または default 指定のコピーと代入はデフォルトを再実行しませんが、ユーザー定義コピーコンストラクターは省略メンバーのデフォルトを使えます。コンストラクターのメンバー初期化と集成体初期化はそれぞれの一時オブジェクト破棄境界を保ちます。テンプレートと STL 全般は開発中です。

Core v2 は既存の生存オブジェクトへの右辺値参照をサポートし、スカラー、ポインター、レコード、配列の別名、参照引数・戻り値、条件式の xvalue、通常の `&&` 修飾メソッドを扱います。`static_cast<R&&>(live)` は同じオブジェクトを保持し、名前付き右辺値参照変数は左辺値のままです。オーバーロードと既存のコピー動作は Clang の選択に従います。参照に追加の破棄所有者はありません。

Core v2 は生存する `R&&` または `const R&&` をソースとする通常のユーザー定義ムーブコンストラクターとムーブ代入を実行します。構築は実際の格納先を使い、代入はソースの変更、評価順序、返された `R&` の参照先を保持します。`&`／`&&` 修飾の代入も対応します。名前付き右辺値参照は左辺値のオーバーロードを選び、明示的コンストラクターは初期化規則に従います。ムーブ後もソースと格納先は通常どおり破棄されます。

Core v2 は暗黙および明示的に default 指定されたムーブ構築・代入にも対応し、入れ子のレコードと多次元配列を扱います。各メンバーは宣言順・要素順に C++ が選択したコピーまたはムーブを実行します。生成ムーブはデフォルトメンバー初期化子を再実行せず、トリビアルな操作は格納済みポインターを保持します。ソースは通常どおり破棄され、未使用またはトリビアルな生成操作に架空の本体は不要です。

Core v2 は解決済みの標準 `noexcept`、`noexcept(true/false)`、C++17 の `throw()` 宣言と、定数 `noexcept(expression)` クエリーに対応します。クエリーは選択された関数とデストラクターの例外仕様を保持し、オペランドを実行しません。未使用コードも含め、すべてのオペランドと記述された仕様をソース検査します。例外の送出・捕捉、スタックの巻き戻し、テンプレート、完全な STL は引き続き開発中です。

Core v2 は通常のメンバーおよび非メンバーの演算子オーバーロードに対応し、算術、比較、添字、間接参照、インクリメント、関数オブジェクト、一般的な代入シグネチャを扱います。選択された関数、参照エイリアス、オブジェクト結果を保持します。演算子記法は C++17 の評価順序に従い、オーバーロードされた論理演算子は両辺を評価します。非メンバー代入演算子の引数は右から左に初期化し、逆順に破棄します。テンプレート、メモリー確保、完全な STL は引き続き開発中です。

Core v2 は生存中のオブジェクトの通常の変換関数にも対応します。暗黙・明示の整数、列挙型、ポインター変換、条件内の明示的 `bool`、参照やオブジェクトの結果を扱います。選択したメンバー関数を変換ごとに一度呼び出します。参照は別名を保持し、オブジェクトの prvalue は実際の格納先を直接初期化します。参照から値への変換では選択されたコピー／ムーブを実行します。const／参照修飾、constexpr、noexcept は C++17 の選択規則に従います。

Core v2 は、一時オブジェクトをレシーバーとする呼び出しと、完全式の終わりまで生存するスカラー／レコードの一時参照引数に対応します。コンストラクター、メソッド、演算子、変換関数で利用できます。評価ごとに実体のある格納領域を使い、オブジェクト結果の最終格納先と参照の別名を保持します。呼び出しと仮引数の破棄後、一時オブジェクトを構築の逆順で破棄し、条件分岐やループの反復にも対応します。一時レコードの配列部分オブジェクトも扱えます。

Core v2 は通常の自動ローカル参照による一時オブジェクトの寿命延長に対応します。`const T& r{T{...}}` と `T&& r = T{...}` を含み、スカラー、列挙、ポインター、レコードに実際の格納領域を用います。C++ が寿命延長を認めるメンバーや配列要素への参照は、レコード全体を生存させます。波括弧と等号付き波括弧の初期化も同じオブジェクトを保持します。破棄は参照のスコープに従い、条件、ループ、早期終了にも対応します。初期化式内の他の一時値は各完全式の終わりに破棄されます。別名は所有者を増やさず、後続のコピーやムーブは選択された操作を保持します。静的・グローバル・スレッドローカル参照、参照フィールド、テンプレート、完全な STL は開発中です。

Core v2 は独立した固定長配列の一時値にも対応し、呼び出し、ポインターへの変換、添字アクセス、値を破棄する式、自動ローカル参照で利用できます。配列全体に一つの実際の格納先を設け、スカラーの代入、レコードの構築、省略要素のデフォルト初期化を各要素で順番に行います。要素ごとの余分な所有者は作りません。C++ が寿命延長を認める場合、多次元配列の行や要素への参照は配列全体を保持します。要素は完全式または参照スコープの終わりに逆順で破棄されます。型付きアドレスと既存の要素数・記憶域・展開制限を維持します。完全な C++／STL は開発中です。

Core v2 は空の標準レイアウトクラスと、状態を持たない関数オブジェクト・変換オブジェクトに対応します。空オブジェクトは C++ のサイズとアラインメント（各1バイト）、必要な独立した格納先、選択されたコンストラクターや演算子の呼び出し、通常の破棄を保持します。自明なコピーでもオペランドを評価し、配列や包含レコードでは空要素も格納量に数えます。生成 NC は内部の1バイトを使い、ソースのフィールド一覧は空のままです。継承、テンプレート、完全な STL は開発中です。

Core v2 は void へのキャスト、`void()`、`void{}` に対応し、対応済みの void 別名、呼び出し、return、コンマ式、条件分岐と組み合わせられます。非 volatile 左辺値を破棄する際は格納値を読み込まず、レシーバーや添字の副作用を保持します。一時オブジェクトは破棄する式でも構築され、元の完全式の終端で破棄されます。void 変数や値の格納先は生成しません。定数式や noexcept のオペランドも検査します。volatile オブジェクト、未対応の型、テンプレート、完全な STL はこの段階の対象外です。

Core v2 は対応済みの関数、メソッド、呼び出し演算子、ユーザー定義コンストラクターのデフォルト引数に対応します。コピー／ムーブコンストラクターの末尾のデフォルト引数も含みます。名前は宣言位置で解決し、引数を省略する呼び出しごとに評価します。参照と値の同一性および破棄規則を保持します。初期化子を省略した配列要素と生成された配列コピーでは、次の要素の前にデフォルト引数の一時オブジェクトを破棄します。明示的な配列初期化項は外側の完全式まで保持します。未使用や上書きされたデフォルト式も検査します。テンプレートと完全な STL は未完成です。

## 複数ファイルのプロジェクト

コンパイルデータベースから翻訳単位を明示的に選び、プロジェクトのルートディレクトリを指定します。内蔵フロントエンドは各単位を個別に解析し、マージ処理は定義の完全性、リンケージ、共有型を検査し、単一定義規則（ODR）への適合を保守的に検証します。

```sh
neverc translate --from cpp --profile cpp-project-v1 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/a.cpp src/b.cpp --out-dir generated
```

出力は `translated.nc` と `translated.h` です。そのルート内にあるプロジェクトのヘッダーだけを受け付けます。同じファイルに複数の構成がある場合は、`--compdb-entry src/a.cpp=4` でデータベースのゼロ始まりの番号を選択します。保存されたコンパイラコマンドはデータとして解析され、実行されません。

## 限定的な倍精度数学演算

`cpp-math-v1` はプロジェクトに `double`、記載された変換・比較、正確なシグネチャの `std::fabs(double)` と `std::floor(double)` を追加します。内蔵の Clang 20.1.8 / libc++ 200100 / macOS 15.5 ヘッダーセットを使い、macOS 15.0 ターゲット（arm64 または x86_64）の明示が必要です。一般的な浮動小数点算術は未対応です。例外トラップをマスクし、非正規化数のゼロ化を無効にする必要があります。標準の四つの丸めモードを検証済みです。

```sh
neverc translate --from cpp --profile cpp-math-v1 \
  --target arm64-apple-macosx15.0.0 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/math.cpp --out-dir generated-math
```

数学変換ではインストール済みの NeverC 数学ヘッダー、埋め込み実装の識別情報、実際のリンクも検証します。生成した数学モジュールは NeverC ランタイムを使用します。`-fno-builtin-std` 指定時は、最終出力に `fabs`／`floor` の対応付けが必要な場合だけ、ファイル出力前に失敗します。これらの対応付けが不要なコードは引き続き変換できます。

## 検証と出力

出力オプションの代わりに `--check` を使うと、同じ解析、生成、構文およびオブジェクト検証を実行し、生成ファイルを保持しません。`--report PATH` は構造化された診断を書き込みます。変換中に元のプログラムを実行することはありません。

出力と付随ファイルは上書きされません。`--out-dir` には既存の親ディレクトリ内の新しいディレクトリ、`-o` には新しい `.nc` パスが必要です。マニフェストはターゲット要件、入出力ハッシュ、コンパイル手順を記録し、ソースマップは生成行を元の位置に対応付けます。

CI の結果、実行・インストールの検証、スキップされたテストはプラットフォーム別に記録しています。ネイティブの macOS arm64 と Rosetta 上の macOS x86_64 は異なる検証環境として区別しています。完全な C++／STL、例外、テンプレート、文字列、`std::vector` は公開されたサポート範囲外です。[サポート表](../../utils/translate-frontends/docs/support-matrix.md)、[プロトコルと復旧規則](../../utils/translate-frontends/docs/protocol.md)、[プロジェクト例](../../tests/neverc/Inputs/translate/cpp/project)を参照してください。
