# Перевод C++ в NeverC

Core v2 поддерживает стандартную переадресацию sized delete: неявный глобальный sized delete/delete[] без повторных объявлений в исходном коде может вызвать соответствующий оператор unsized, определённый в исходном коде. Явные определения sized имеют приоритет; исходная разметка cookie массива сохраняется. Стандартный аллокатор и среда исключений не добавляются; нативная проверка требует CI этой ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#single-object-allocation-and-placement-reuse).

Core v2 также поддерживает проверенные `__array_rank` и `__array_extent` с неотрицательными целочисленными константными индексами, включая параметры шаблонов для фиксированных массивов. Оба операнда проверяются до свёртки. Неподдерживаемые типы массивов и индексы с неявным преобразованием класса исключены. Нативные результаты требуют CI реализующей ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#array-type-queries).

Core v2 добавляет проверенную встроенную классификацию типов, включая `__is_integral`, `__is_pointer` и `__is_same`. Запросы сохраняют идентичность типов C++ и проверяют записанные операнды до получения логического значения. Неподдерживаемые типы и остальные свойства типов по-прежнему ограничены. Проверки O0/O2 и переноса требуют CI реализующей ревизии; стандартные заголовки и полный C++/STL пока не завершены. Для поддерживаемых типов также доступны свойства агрегатов, пустых классов, стандартной компоновки, trivial, trivially-copyable и POD, полиморфность, абстрактность и отношение базового класса `__is_base_of`. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#builtin-type-classification).

Core v2 добавляет прямые вызовы `malloc/calloc/free` через точные глобальные объявления C в исходном коде. Собственные аллокаторы C++ могут использовать нативную кучу и обмениваться памятью с независимым вызывающим кодом на C, включая освобождение. Проверки разрядности, соглашения о вызовах, исходного кода и IR сохраняются. Проверка O0/O2 требует CI этой реализации. `realloc`, стандартное выделение C++ с исключениями, стандартные заголовки и полная поддержка C++/STL ещё не завершены. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#native-c-heap-calls).

Core v2 регистрирует разрушение допустимых статических объектов, массивов и временных объектов с продлённой жизнью после завершения их конструирования. Константные значения сохраняются; локальные объекты регистрируются при первом проходе, нелокальные — при нативном запуске. CRT сохраняет порядок завершения и выгрузки модулей. Тестам O0/O2, выгрузки и конкурентного первого доступа нужна CI этой реализации. TLS, раскрутка исключений, стандартная куча, заголовки и полный C++/STL ещё не завершены; ручная/DynCode-загрузка не поддерживается. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#static-destruction).

Core v2 теперь поддерживает нелокальную динамическую инициализацию допустимых объектов и ссылок, включая материализованные экземпляры шаблонов. Проверенный внутренний нативный конструктор выполняется до main в порядке определений после нулевой и константной инициализации; обычные временные объекты уничтожаются после каждого инициализатора. Локальные статические объекты сохраняют инициализацию при первом использовании. Тесты O0/O2 программы и отдельного C-клиента требуют CI этой ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#nonlocal-dynamic-initialization).

Динамическая длина new[] теперь допускается для определённых в исходном коде noexcept-аллокаторов класса без placement-аргументов. Неверная длина возвращает null до вызова аллокатора; допустимые элементы создаются в цикле с уничтожением временных аргументов по умолчанию после каждого элемента. Временные объекты явного начального списка и преобразования длины живут до конца полного выражения. Повторная инициализация агрегатов теперь записывает прямо в элементы без отдельных временных объектов, включая вложенные списки и ссылки на существующие объекты. Инициализация с дополнительными временными объектами, динамические выделения с исключениями или placement, стандартная куча и полный C++/STL остаются незавершёнными. Нативная проверка ожидает CI этой версии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#runtime-array-allocation).

Core v2 поддерживает new/delete для одного объекта через проверенные функции выделения памяти в исходном коде, включая placement-перегрузки классов и шаблонов, сохранение адресов и очистку аргументов. Явное уничтожение и повторное создание placement сохраняют обязательства последующей автоматической очистки. Нативная проверка требует CI этой реализации. Стандартная куча, длины new[] времени выполнения, исключения, стандартные заголовки и полный C++/STL ещё не завершены. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#single-object-allocation-and-placement-reuse).

Экспериментальная команда `neverc translate` создаёт проверяемый исходный код `.nc` с профилями `cpp-core-v1`, `cpp-core-v2`, `cpp-project-v1` и `cpp-math-v1`.

**Сейчас реализована только трансляция исходного кода C++.** Поддержка E Language (易语言, `.e`), Python, Go, Rust, TypeScript и JavaScript запланирована на будущее; трансляторы этих языков пока недоступны.

Объявления частичных специализаций сохраняют проверку аргументов первичного шаблона, включая копии переменных-членов с зависимыми внутренними аргументами. Исходный код уже разрешённых типов параметров проверяется даже без выбора специализации. Раскрытия пакетов неизвестной длины сохраняют проверенный префикс и фактический исходный код без выдуманных позиций аргументов. Зависимые полные специализации переменных-членов сохраняют те же проверки. Полный C++/STL ещё не завершён. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#partial-declaration-source-checks).

Сохранение проверки аргументов не делает частичную специализацию корректной: она должна оставаться более специализированной, а её параметры — выводимыми. Недопустимые шаблоны пакетов и объявление инстанцирования extern после определения инстанцирования по-прежнему вызывают диагностику C++ (`TR0202`).

Core v2 поддерживает обычные именованные вложенные классы в допустимых обобщённых классах, их конкретные копии и собственные явные специализации. Обычное тело не добавляет уровень параметров шаблона. Неиспользуемые тела остаются отложенными; созданные поля, выбранные методы, шаблоны членов, время жизни и скалярное статическое хранение сохраняют точный источник и владельца. Каждое явное инстанцирование проверяет записанный квалификатор, включая extern и повторения без эффекта. Наследование, выделение памяти и полный C++/STL ещё не завершены. Ввод реализован только для C++; E Language и Python запланированы. Встроенные библиотеки Clang не требуют внешнего исполняемого файла Clang. Нативные результаты требуют CI реализованной ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#ordinary-nested-classes-in-generic-owners).

Core v2 поддерживает скалярные шаблоны статических переменных-членов допустимых записей и конкретных классов: аргументы по умолчанию, ограниченные пакеты, частичные/полные специализации и внешние определения. Эквивалентные экземпляры разделяют хранилище; разные внутренние или внешние аргументы сохраняют отдельные объекты. Проверенные не-inline const-значения читаются без хранилища, но вычисляемым адресам и ссылкам нужно определение. Сохраняются проверки исходных объявлений и определений, побочные эффекты получателя и уничтожение временных объектов. Полные специализации внутри зависимых внешних классов сохраняют исходный код первоначальных и конкретных объявлений. Разрешённые аргументы, значения по умолчанию и типы параметров проверяются сразу; зависимые части — после инстанцирования. Другие результаты, полный C++/STL ещё не завершены. Используются встроенные библиотеки Clang без внешнего Clang. Реализован только ввод C++; E Language, Python и другие языки запланированы. Нативная проверка требует CI реализации. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-member-variable-templates).

Core v2 поддерживает шаблоны псевдонимов-членов допустимых обычных записей, включая вложенные, и экземпляров классов. Аргументы по умолчанию и ограниченные пакеты могут использовать внешние параметры класса и внутренние параметры псевдонима; их аргументы и подставленные исходные типы проверяются отдельно. Сохраняется семантика значений, ссылок, массивов и записей без объектов шаблонов во время исполнения. Независимые объявления проверяются даже без использования; зависимые типы откладываются до подстановки. Используются встроенные библиотеки Clang без внешней программы. Нативная проверка требует CI реализации. Полный C++/STL ещё не завершён. Реализован только ввод C++; E Language, Python и другие языки запланированы. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-member-alias-templates).

Core v2 поддерживает конкретные шаблоны функций-членов допустимых записей и экземпляров классов: обычные и статические методы, операторы, конструкторы и преобразования, ограниченные пакеты, аргументы по умолчанию, внешние определения и специализации. Внутренние и внешние аргументы имеют отдельные идентификаторы; эквивалентные вызовы разделяют код и статическое хранилище. Для выбранных вызовов, аргументов и созданных тел сохраняются проверки исходного кода и времени жизни. Перевод использует встроенные библиотеки Clang без запуска внешнего исполняемого файла Clang. Нативные результаты требуют CI реализации. Наследование, выделение памяти и полный C++/STL ещё не завершены. Реализован только ввод C++; E Language, Python и другие языки запланированы. Конкретные внешние квалификаторы объявлений шаблонов членов проверяются даже без инстанцирования тела. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-member-function-templates).

Core v2 поддерживает шаблоны переменных в пространствах имён с целочисленным, логическим или перечислимым результатом, включая выведенный auto, выбранные частичные и полные специализации, аргументы по умолчанию и ограниченные пакеты типов или скаляров. Признаки C++17 можно использовать в static_assert, if constexpr и аргументах других шаблонов. Эквивалентные экземпляры разделяют типизированное глобальное хранилище; разные экземпляры сохраняют отдельные значения и адреса. Запрос фиксированного типа не вынуждает инстанцировать неиспользуемый инициализатор или создавать хранилище. Фактические аргументы, выбранные значения по умолчанию, типы объявлений и определений и инстанцированные инициализаторы проверяются. другие типы результатов, полная поддержка C++/STL ещё не завершены; нативная проверка требует CI реализующей ревизии.

Прямой sizeof(T) или alignof(T) в записанном типе нетипового параметра может оставаться метаданными объявления, если T — именно параметр типа из того же списка. Выбранные подстановки по-прежнему требуют проверенных конкретных типов; другие зависимые запросы не входят в это исключение. Одно объявление extern template не предоставляет конкретное определение, требуемое текущим контрактом перевода замкнутой единицы исходного кода.

Core v2 разбирает шаблоны по стандартным правилам C++17 на всех поддерживаемых целевых платформах, включая Windows x64 и ARM64. Определения разбираются без отложенного анализа MSVC; повторные определения явного инстанцирования и несовместимые спецификации исключений остаются ошибками языка. Неиспользуемые зависимые тела по-прежнему инстанцируются только по мере необходимости. Полная поддержка C++/STL ещё не завершена. Явным специализациям функций по-прежнему требуется собственное определение в исходной единице; повторные объявления его не заменяют.

Core v2 поддерживает изменяемые глобальные переменные целых, логических и перечислимых типов в области пространства имён с нулевой или полностью проверенной константной инициализацией. Память и адрес сохраняются между вызовами; ссылки, указатели и аргументы по умолчанию обращаются к той же переменной. Объявление `extern` должно иметь определение в той же исходной единице. Глобальные константы остаются доступными только для чтения. Для глобальных записей/массивов/указателей/ссылок, локального хранилища потока и статических локальных переменных сохраняются отдельные ограничения.

Core v2 поддерживает циклы `for` по диапазону C++17 для допустимых фиксированных массивов и диапазонов, определённых в исходном коде, с разрешёнными вызовами методов или ADL-функций `begin/end`. Переменные по значению и ссылке, итераторы типа записи и отличающиеся типы ограничителей сохраняют обычные правила вызовов и времени жизни. Диапазон и `begin/end` инициализируются один раз; объекты итерации уничтожаются перед приращением или выходом, включая `continue`, `break` и `return`. Шаблоны, стандартные заголовки, контейнеры STL, структурированные привязки и инструкции инициализации C++20 пока не входят в это расширение. Нативная проверка требует CI реализующей ревизии.

Core v2 поддерживает закрытые и защищённые поля в классах со стандартным расположением, отвечающих остальным ограничениям. Встроенный Clang проверяет доступ до трансляции; разрешённые методы, конструкторы, фабрики, аргументы по умолчанию и операции копирования/перемещения используют ту же типизированную память полей. Недопустимый внешний доступ по-прежнему вызывает диагностику C++. Спецификаторы доступа являются правилами исходного языка и не обеспечивают секретность во время выполнения. Сохраняются ограничения для классов без стандартного расположения со смешанным доступом, шаблонов друзей, наследования и неподдерживаемых типов полей. Нативные результаты требуют CI реализующей ревизии.

Core v2 создаёт нешаблонные дружественные функции из допустимых шаблонов классов, частичных специализаций, шаблонов-членов и копий полных специализаций или обычных вложенных классов. ADL, закрытый доступ, свободные операторы, повторные объявления, локальные классы и статические скалярные переменные сохраняют идентичность без неявного получателя. Неподдерживаемые зависимые формы шаблонов дружественных классов, раскрытия дружественных типов, полный C++/STL остаются незавершёнными. Прежние правила независимых дружественных типов и членов сохраняются. Реализован только C++; E Language и Python запланированы. Используются встроенные библиотеки Clang без внешней программы. Нативная проверка требует CI реализующего коммита. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#instantiated-non-template-friend-functions).

Фильтр прямого связывания не отменяет вывод типа результата, необходимый при последующей косвенной инициализации; некорректное тело конкурирующего auto& сохраняет обычную диагностику C++.

Core v2 поддерживает конкретные пакеты типов и скалярных параметров в разрешённых шаблонах функций, операторов и классов пространств имён. Предел — 64 параметра первичного шаблона и 64 элемента каждого пакета. Развёрнутые параметры сохраняют отдельное хранилище; sizeof... создаёт типизированное количество. Разрешённые свёртки сохраняют порядок, короткое замыкание и очистку. Зависимое количество из того же списка может оставаться метаданными в записанном типе параметра. Образцы пустых свёрток не инстанцируются; начальные значения и созданные элементы проверяются. Полный C++17/STL не завершён; нативные результаты требуют CI реализации. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#concrete-parameter-packs).

Core v2 поддерживает шаблоны псевдонимов в собственных пространствах имён для разрешённых скалярных типов, void, указателей, ссылок, фиксированных массивов и классов, включая значения по умолчанию и конкретные пакеты параметров. Псевдонимы используют общие канонические типы и статическую память. Написанные аргументы, выбранные значения по умолчанию и подставленный исходный тип проверяются при фактическом использовании; невыбранные кандидаты и неинстанцированные зависимые тела остаются отложенными. Явные аргументы сохраняют контекст вызывающего кода при рекурсии и в выражениях this. Сохраняются пределы в 64 параметра, элемента пакета и уровня, а также общий бюджет исходников. Полный C++17/STL ещё не реализован; нативная проверка требует CI соответствующей ревизии. Реализован только ввод C++; E Language, Python и другие фронтенды запланированы. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#namespace-alias-templates).
Для выбранных нетиповых аргументов шаблона также сохраняется исходный код типа параметра, включая явно заданные аргументы шаблонов функций и выведенные пустые пакеты; неподдерживаемый код, скрытый свёрткой псевдонима, по-прежнему проверяется.

Независимые типы аргументов по умолчанию проверяются даже в неиспользуемых шаблонах. Квалифицированные вызовы шаблонов функций и конкретные определения функций преобразования сохраняют точный исходный текст, включая псевдонимы типов в определениях вне класса. Преобразование, возвращающее lvalue-ссылку, может создать временное значение расширенного типа для параметра с const-ссылкой; для параметра с rvalue-ссылкой сохраняется ограничение перегрузки C++.
Core v2 также поддерживает частичные специализации шаблонов классов в пространствах имён проекта. Выбранный шаблон специализации и выведенные параметры проверяются отдельно от аргументов первичного шаблона. Псевдонимы используют тот же конкретный тип и статическую память; поддерживаемые члены сохраняют вызовы, ссылки и время жизни. Ограничение остаётся равным 64 параметрам и 64 элементам в каждом пакете. Полная поддержка C++17/STL ещё не завершена; нативную проверку выполняет CI соответствующей ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#class-template-partial-specializations).

Core v2 поддерживает отдельный тип значения `decltype(nullptr)`: псевдонимы, ссылки, поля/массивы, сигнатуры обратных вызовов, а также скалярные статические объекты и шаблоны переменных с нулевой или константной инициализацией. Преобразования в указатель сохраняют побочные эффекты выражений и уничтожение временных объектов; разные объекты null сохраняют собственные адреса. Аргументы шаблонов типа `nullptr_t` поддерживают проверенные значения по умолчанию, пакеты и уже допустимые исходные контексты; их экземпляры отличаются от целого нуля и логического false. Аргументы null указательного типа и стандартные заголовки пока не поддерживаются. Нативная проверка требует CI соответствующей ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#null-pointer-values).

Core v2 поддерживает делегирующие конструкторы допустимых обычных и обобщённых классов, включая цепочки и выбранные шаблоны конструкторов. Цель и делегирующее тело используют один конечный объект; члены инициализируются один раз, а временные аргументы уничтожаются до выполнения делегирующего тела. Проверки выбора и определений сохраняются. Нативная проверка требует CI соответствующей ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#delegating-constructors).

Core v2 поддерживает const-члены допустимых скалярных типов, записей, указателей, обратных вызовов и массивов, в том числе в обобщённых и вложенных классах. Сохраняются конечное хранилище, выбранные копирование/перемещение, отдельные адреса и const-ссылки/указатели. Clang отклоняет недопустимые записи и удалённые присваивания. Это позволяет определять классы с постоянным ключом; стандартные заголовки и полная STL ещё не завершены. Нативная проверка требует CI соответствующей ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#const-data-members).

Core v2 принимает поддерживаемые удалённые функции и стандартные специальные функции, определённые как удалённые, включая допустимые шаблоны и friend-формы. Clang сохраняет выбор перегрузок и диагностику доступа; исполняемые определения для удалённых объявлений не создаются. Объекты только с перемещением, выбранное копирование вместо перемещения и гарантированное устранение копирования C++17 используют прежнюю обработку времени жизни. Требуется CI ревизии; полная C++/STL ещё не завершена. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#deleted-function-declarations).

Core v2 поддерживает IEEE `float` и `double`, арифметику и преобразования, ссылки, поля и массивы, обратные вызовы и статические скаляры с нулевой или константной инициализацией. Точные биты литералов и независимая проверка размещения сохраняют представление. Выполнение требует стандартной среды вычислений без fast math, избыточной точности и неявного объединения умножения со сложением. Требуется CI ревизии; `long double`, стандартные заголовки и полная C++/STL ещё не завершены. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#binary-floating-point-values).

Core v2 поддерживает узкие, UTF-8, UTF-16, UTF-32 и широкие строковые литералы с точными кодовыми единицами и статическим хранением только для чтения, инициализацию символьных массивов с заполнением нулями и константные массивы пространства имён. Ссылки, копирование полей и время жизни используют существующие типизированные операции. Требуется CI ревизии; стандартные заголовки, выделение памяти и операции `std::string` ещё не завершены. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#string-literals-and-constant-arrays).

Core v2 поддерживает нулевую или константную инициализацию изменяемых и константных массивов в пространствах имён, локальных статических переменных и статических членах классов, включая допустимые экземпляры шаблонов. Состояние и адрес сохраняются между вызовами; разные экземпляры имеют отдельное хранилище. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#fixed-array-static-storage).

Core v2 поддерживает нулевую и константную инициализацию статических указателей на глобальные объекты, литералы, элементы массивов и поля, включая допустимый указатель сразу за концом. Хранилище пространств имён, функций, классов и шаблонов сохраняет идентичность, изменяемость и правила const. Адреса объектов, определённых позже, становятся константами C23 без инициализации во время выполнения. Статические ссылки, выделение памяти и полная STL ещё разрабатываются. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#static-object-pointer-storage).

Статические ссылки могут связываться с существующими статическими объектами, подобъектами массивов или записей и строками, включая локальные и классовые статические ссылки и поддерживаемые экземпляры шаблонов. Чтение и запись сохраняют исходный объект и права const. См. [контракт статических ссылок](../../utils/translate-frontends/docs/cpp-core-v2.md#static-reference-bindings).

Core v2 поддерживает константно инициализированные временные скаляры, массивы и записи, время жизни которых продлевают статические ссылки. Сохраняются полные объекты, ссылки на подобъекты, указатели на себя, const и идентичность экземпляров шаблонов. Нативная проверка требует CI этой реализации. Константная инициализация этих временных объектов в C++17 по-прежнему требует тривиального разрушения; нетривиальные статические временные объекты используют динамическую инициализацию и регистрацию. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#static-reference-temporary-lifetime-extension).

Статические записи поддерживают константную инициализацию и общее изменяемое состояние, включая локальные и классовые статические объекты и поддерживаемые экземпляры шаблонов. Собственные адреса, constexpr-конструирование и статическая нулевая инициализация сохраняют идентичность объекта. См. [контракт статических записей](../../utils/translate-frontends/docs/cpp-core-v2.md#static-record-objects).


Core v2 поддерживает проверенные цепочки тривиальных пустых базовых классов, включая допустимые шаблоны, унаследованные методы, преобразования и статические значения. Каждая база хранится как реальное первое поле C с независимой проверкой размещения. Сохраняются нулевые указатели, идентичность ссылок, константные пути и побочные эффекты. Нетривиальное время жизни баз и стандартные заголовки ещё не завершены; нативная проверка требует CI соответствующей ревизии. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#trivial-empty-base-chains).
## Установка и скалярный перевод

Используйте обычную установку NeverC со стандартными ресурсами. Фронтенд C++ и одобренные заголовки SDK встроены; отдельно устанавливать Clang не нужно. Подробности — в [инструкции сборки фронтенда](../../utils/translate-frontends/cpp/README.md).

```sh
neverc translate --from cpp input.cpp -o output.nc
neverc output.nc -c -o output.o
```

Профиль `cpp-core-v1` принимает один самостоятельный файл C++17 без include. Поддерживаются `int`, `unsigned int`, `bool`, `void`, тривиальные агрегатные типы, свободные функции, пространства имён, перегрузки и описанный поток управления. Проверяются все входные объявления, включая неиспользуемый код.

Выберите `--profile cpp-core-v2`, чтобы добавить проверяемые псевдонимы `typedef`/`using`, перечисления с поддерживаемыми целочисленными базовыми типами, `static_assert`, а также ограниченную поддержку указателей на объекты и lvalue-ссылок. Параметры и результаты по ссылке сохраняют связь с исходным объектом; поддерживаются нулевые указатели и вложенные квалификаторы `const`. Ограничения на один исходный файл без include сохраняются. См. [контракт core v2](../../utils/translate-frontends/docs/cpp-core-v2.md).

Core v2 также добавляет локальные массивы фиксированного размера и поля-массивы, многомерную индексацию, указатели и ссылки на массивы. При частичной инициализации пропущенные скалярные элементы обнуляются, а записи используют выбранную инициализацию; порядок и связи с исходным хранилищем сохраняются. Размеры и объём развёртывания инициализации ограничены. Глобальные массивы и массивы переменной длины пока не поддерживаются.

Core v2 поддерживает `switch`/`case`/`default`, включая операторы инициализации C++17, переход к следующему case и проверенные аннотации `[[fallthrough]]`. Выражение выбора вычисляется один раз; вложенные switch и циклы сохраняют цели `break`/`continue`. Диапазоны case GNU и другие атрибуты операторов отклоняются.

Core v2 поддерживает знаковые и беззнаковые целые шириной 8, 16, 32 и 64 бита, символьные типы и литералы, а также константные запросы `sizeof`/`alignof`. Продвижение целых и выбор перегрузок выполняются до нормализации; `long`, `wchar_t` и тип размера зависят от целевой платформы. Базовые типы перечислений также могут быть узкими и широкими. Стандартная библиотека ещё разрабатывается.

Core v2 также поддерживает смещения и разность указателей на объекты, инкремент/декремент и составное присваивание, включая обход массивов и шаг многомерных массивов. Создаваемые вспомогательные функции сохраняют правила C++17 для прибавления и вычитания нуля из нулевого указателя и разности двух нулевых указателей. Сравнения порядка указателей на объекты используют независимо проверенное беззнаковое представление адресов на нативных x86/AArch64; результаты требуют CI соответствующей ревизии. Преобразования указатель/целое в исходном коде и полная STL ещё не завершены.

Core v2 сверяет размеры типов и выравнивание ABI с собственной моделью целевой платформы NeverC, включая размеры структур и смещения полей. Статические проверки в сгенерированном коде повторно проверяют размещение при компиляции; эти данные записываются в манифест.

Core v2 поддерживает именованные невиртуальные функции-члены поддерживаемых типов записей, включая const-перегрузки, методы с lvalue-квалификатором, статические методы и `this`. Вызов сохраняет идентичность исходного объекта и вычисляет объект-получатель до аргументов.

Core v2 поддерживает обычные пользовательские конструкторы записей со стандартной компоновкой и поддерживаемыми операциями копирования. Локальные объекты, поля и элементы массивов создаются в конечном хранилище; поля инициализируются в порядке объявления. Раскрутка стека при исключениях пока не поддерживается.

Core v2 создаёт отдельный объект для каждого параметра-записи, передаваемого по значению, и записывает результат в хранилище вызывающей стороны. Правила действуют и для конструкторов и методов; необходимые копии и связи ссылок сохраняются. Для подходящих тривиальных типов другие реализации C++17 могут добавлять копии аргументов или результатов.

Core v2 поддерживает обычные пользовательские деструкторы и неявное разрушение членов при нормальном выходе. Локальные объекты, поля и элементы массивов разрушаются в обратном порядке; временные объекты — в конце полного выражения после сохранения нужных значений. Возвраты, ветвления, циклы, break и continue выполняют нужную очистку. Параметры по значению разрушаются при выходе из вызываемой функции; возвращаемые объекты принадлежат вызывающей стороне. Раскрутка стека исключениями пока не поддерживается.

Core v2 выполняет обычные пользовательские конструкторы копирования и операторы копирующего присваивания с параметром-источником `R&` или `const R&`. Копирование использует реальный целевой объект и сохраняет побочные эффекты и возвращённую ссылку. Синтаксис присваивания сначала вычисляет правый операнд; явный вызов `operator=` сначала вычисляет объект-получатель.

Core v2 также поддерживает сгенерированные и явно default-конструкторы по умолчанию и default-деструкторы, включая вложенные записи и массивы полей. Конструирование использует реальное место объекта и порядок объявления полей; инициализация значением обнуляет их только по правилам C++. Отличия default-определений вне класса сохраняются. Неиспользуемым конструкторам и конструкторам только в невычисляемых выражениях не требуется искусственное тело.

Core v2 поддерживает неявные и явно default-конструкторы копирования для вложенных записей и многомерных массивов. Выбранные конструкторы полей работают в реальном месте назначения в порядке объявления и элементов; адрес исходного массива вычисляется один раз. Тривиальная копия сохраняет значения указателей. Передача по значению и возврат исходного объекта сохраняют эффекты копирования, а прямая передача prvalue не добавляет копий.

Core v2 также поддерживает неявное и явно default-присваивание копированием. Поля и элементы массивов сохраняют выбранные операции и порядок; сгенерированные тривиальные копии массивов становятся типизированными присваиваниями без внешнего вызова копирования памяти. Тривиальное присваивание сохраняет указатели и возвращает реальный объект-получатель. Синтаксис оператора сначала фиксирует ссылку на источник, явный вызов метода — получателя; значения источника читаются после этих эффектов. Присваивание не создаёт и не уничтожает дополнительные объекты.

Core v2 поддерживает инициализаторы полей по умолчанию для допустимых типов: обращения к предыдущим полям, обычные вызовы, вложенные записи и массивы. Выбранный инициализатор использует фактический объект как `this`; явные элементы инициализации агрегата сохраняют `this` вызывающего метода. Явная инициализация заменяет значение по умолчанию данного поля. Неявные/default копирование и присваивание не запускают его повторно; пользовательский конструктор копирования может выбрать его для пропущенных полей. Инициализация членов конструктора и агрегата сохраняет соответствующие границы уничтожения временных объектов. Шаблоны и полная STL остаются в разработке.

Core v2 поддерживает rvalue-ссылки на уже существующие живые объекты: псевдонимы скаляров, указателей, записей и массивов, ссылочные параметры и результаты, условные xvalue и обычные методы с квалификатором `&&`. `static_cast<R&&>(live)` сохраняет тот же объект; именованные переменные rvalue-ссылочного типа остаются lvalue. Перегрузки и существующее копирование следуют выбору Clang. Ссылки не создают дополнительной ответственности за уничтожение.

Core v2 выполняет обычные пользовательские конструкторы и операторы присваивания перемещения из живого источника `R&&` или `const R&&`. Конструирование использует конечное хранилище; присваивание сохраняет изменения источника, порядок вычисления и возвращённую ссылку `R&`, включая получателей с квалификатором `&`/`&&`. Именованные rvalue-ссылки выбирают lvalue-перегрузки, а явные конструкторы сохраняют правила инициализации. Перемещение не завершает жизнь источника: источник и результат уничтожаются обычным образом.

Core v2 также поддерживает неявные и явно default конструирование и присваивание перемещения для вложенных записей и многомерных массивов. Члены выполняют выбранное C++ копирование или перемещение в порядке объявления и элементов. Сгенерированные перемещения не повторяют инициализаторы полей; тривиальные операции сохраняют значения указателей. Источники уничтожаются обычным образом, а неиспользуемым или тривиальным сгенерированным операциям не требуется вымышленное тело.

Core v2 поддерживает разрешённые стандартные объявления `noexcept`, `noexcept(true/false)` и `throw()` из C++17, а также константные запросы `noexcept(expression)`. Запрос учитывает спецификации выбранных функций и деструкторов, не выполняя операнды. Все операнды и записанные спецификации проверяются и в неиспользуемом коде. Генерация и перехват исключений, раскрутка стека, шаблоны и полная STL остаются в разработке.

Core v2 поддерживает обычные перегруженные операторы-члены и свободные операторы: арифметику, сравнения, индексацию, разыменование, инкременты, функциональные объекты и общие сигнатуры присваивания. Сохраняются выбранные функции, ссылочные псевдонимы и объекты результатов. Операторная запись соблюдает порядок C++17; перегруженные логические операторы вычисляют оба операнда. Свободные операторы присваивания инициализируют параметры справа налево и разрушают их в обратном порядке. Шаблоны, выделение памяти и полная STL остаются в разработке.

Core v2 также поддерживает обычные функции преобразования живых объектов: неявные и явные целочисленные преобразования, перечисления и указатели, явный `bool` в условиях, ссылочные и объектные результаты. Каждое преобразование один раз вызывает выбранную функцию-член. Ссылки сохраняют псевдонимы; объектные prvalue напрямую инициализируют фактическое место назначения. Преобразование ссылки в значение сохраняет выбранное копирование или перемещение. Квалификаторы const и ссылок, constexpr и noexcept следуют C++17.

Core v2 теперь поддерживает временные объекты-получатели и временные скалярные/объектные аргументы по ссылке до конца полного выражения, включая конструкторы, методы, операторы и преобразования. Каждое вычисление использует реальное хранилище; объектный результат сохраняет конечное место назначения, а ссылка — свой псевдоним. После вызова и уничтожения параметров временные объекты уничтожаются в обратном порядке конструирования, в том числе в условиях и циклах. Поддерживаются массивы-подобъекты временных записей.

Core v2 теперь продлевает жизнь временных значений, связанных с обычными автоматическими локальными ссылками, включая `const T& r{T{...}}` и `T&& r = T{...}`. Скалярные значения, перечисления, указатели и записи получают реальное хранилище. Ссылки на поля или элементы массива сохраняют всю запись, если C++ предусматривает продление жизни. Инициализация фигурными скобками, в том числе после знака равенства, сохраняет тот же объект. Уничтожение следует области ссылки, включая условия, циклы и ранний выход; остальные временные значения инициализатора заканчивают жизнь вместе со своим полным выражением. Псевдонимы не создают владельцев, последующие копирования и перемещения сохраняют выбранные операции. [C++17](../../utils/translate-frontends/docs/cpp-core-v2.md#reference-members).

Core v2 также поддерживает отдельные временные массивы фиксированного размера в вызовах, преобразовании в указатель, индексации, отбрасываемых выражениях и автоматических локальных ссылках. Каждый массив имеет одно реальное место назначения; скалярные значения, конструкторы и общие инициализаторы по умолчанию заполняют элементы непосредственно и по порядку, без дополнительных владельцев. Если C++ продлевает жизнь, ссылки на строки или элементы многомерного массива сохраняют весь массив. Элементы уничтожаются в обратном порядке в конце полного выражения или области ссылки. Типизированные адреса и существующие ограничения размера, хранения и развёртывания сохраняются. Полная поддержка C++/STL остаётся в разработке.

Core v2 поддерживает пустые классы со стандартным размещением и объекты функций или преобразований без состояния. Пустые объекты сохраняют размер и выравнивание C++ по одному байту, отдельное хранение там, где оно требуется, выбранные конструкторы и операторы и обычное уничтожение. Тривиальные копии всё равно вычисляют операнды; пустые элементы массивов и содержащих записей учитываются в лимите хранения. Созданный NC использует внутренний байт, а список исходных полей остаётся пустым. Наследование, шаблоны и полная STL ещё разрабатываются.

Core v2 поддерживает преобразования в void, `void()` и `void{}`, допустимые псевдонимы void, вызовы, возвраты, выражения с запятой и условные ветви. Отбрасывание не-volatile lvalue сохраняет эффекты вычисления получателя и индекса без чтения хранимого значения. Временные объекты всё равно создаются и уничтожаются в конце исходного полного выражения. Переменные и значения void не генерируются. Операнды константных выражений и noexcept проверяются полностью. Объекты volatile, неподдерживаемые типы, шаблоны и полная STL остаются за рамками этого этапа.

Core v2 поддерживает аргументы по умолчанию для допустимых функций, методов, операторов вызова и пользовательских конструкторов, включая дополнительные параметры конструкторов копирования и перемещения. Имена разрешаются в месте объявления, а выражения вычисляются при каждом вызове с пропущенным аргументом. Идентичность и время жизни ссылок и значений сохраняются. Для элементов массива без инициализатора и сгенерированного копирования массива временные аргументы уничтожаются перед следующим элементом; явные инициализаторы сохраняют границу внешнего полного выражения. Неиспользуемые и заменённые явными аргументами выражения также проверяются. Шаблоны и полная STL ещё не завершены.

## Многофайловые проекты

Явно выберите единицы трансляции из базы данных компиляции и задайте корневой каталог проекта. Встроенный фронтенд анализирует каждую единицу отдельно; объединение проверяет определения, связывание, общие типы и соблюдение правила одного определения (ODR) с помощью консервативных проверок.

```sh
neverc translate --from cpp --profile cpp-project-v1 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/a.cpp src/b.cpp --out-dir generated
```

Проект создаёт `translated.nc` и `translated.h`. Допускаются только заголовки проекта внутри этого корневого каталога. Если у файла несколько конфигураций, выберите индекс базы, начиная с нуля, через `--compdb-entry src/a.cpp=4`. Сохранённые команды компилятора разбираются как данные и никогда не выполняются.

## Ограниченная математика двойной точности

`cpp-math-v1` добавляет к проектам `double`, документированные преобразования/сравнения и точные сигнатуры `std::fabs(double)` и `std::floor(double)`. Используются встроенные заголовки Clang 20.1.8 / libc++ 200100 / macOS 15.5; требуется явно указать цель macOS 15.0 (arm64 или x86_64). Общая арифметика с плавающей точкой пока исключена. Ловушки исключений должны быть замаскированы, а обнуление денормализованных чисел выключено; проверены все четыре стандартных режима округления.

```sh
neverc translate --from cpp --profile cpp-math-v1 \
  --target arm64-apple-macosx15.0.0 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/math.cpp --out-dir generated-math
```

Математическая трансляция также проверяет установленные заголовки NeverC, идентичность встроенных реализаций и фактическую компоновку. Полученные модули используют среду выполнения NeverC. С `-fno-builtin-std` трансляция завершается ошибкой до записи файлов только тогда, когда итоговому коду нужны сопоставления `fabs`/`floor`. Математический код, которому они не нужны, по-прежнему можно транслировать.

## Проверка и результат

Используйте `--check` вместо параметра вывода для того же анализа, генерации, проверки синтаксиса и объектного кода без сохранения созданных файлов. `--report PATH` записывает структурированную диагностику. Перевод никогда не запускает исходную программу.

Результаты и сопутствующие файлы не перезаписываются. `--out-dir` требует новый каталог с существующим родительским каталогом, а `-o` — новый путь `.nc`. Манифест содержит требования целевой платформы, хеши входов и выходов и порядок компиляции; карта исходников связывает созданные строки с исходными позициями.

Результаты CI, проверок выполнения и установки, а также пропущенные тесты указаны отдельно для каждой платформы. Нативная macOS arm64 и macOS x86_64 через Rosetta остаются разными средами проверки. Заявленный объём поддержки не включает полный C++/STL, исключения, шаблоны, строки или `std::vector`. См. [матрицу поддержки](../../utils/translate-frontends/docs/support-matrix.md), [протокол и правила восстановления](../../utils/translate-frontends/docs/protocol.md) и [пример проекта](../../tests/neverc/Inputs/translate/cpp/project).
