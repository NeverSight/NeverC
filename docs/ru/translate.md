# Перевод C++ в NeverC

Экспериментальная команда `neverc translate` создаёт проверяемый исходный код `.nc` с профилями `cpp-core-v1`, `cpp-core-v2`, `cpp-project-v1` и `cpp-math-v1`.

**Сейчас реализована только трансляция исходного кода C++.** Поддержка E Language (易语言, `.e`), Python, Go, Rust, TypeScript и JavaScript запланирована на будущее; трансляторы этих языков пока недоступны.

Core v2 поддерживает изменяемые глобальные переменные целых, логических и перечислимых типов в области пространства имён с нулевой или полностью проверенной константной инициализацией. Память и адрес сохраняются между вызовами; ссылки, указатели и аргументы по умолчанию обращаются к той же переменной. Объявление `extern` должно иметь определение в той же исходной единице. Глобальные константы остаются доступными только для чтения. Для динамической инициализации, глобальных записей/массивов/указателей/ссылок, локального хранилища потока и статических локальных переменных сохраняются отдельные ограничения.

Core v2 поддерживает циклы `for` по диапазону C++17 для допустимых фиксированных массивов и диапазонов, определённых в исходном коде, с разрешёнными вызовами методов или ADL-функций `begin/end`. Переменные по значению и ссылке, итераторы типа записи и отличающиеся типы ограничителей сохраняют обычные правила вызовов и времени жизни. Диапазон и `begin/end` инициализируются один раз; объекты итерации уничтожаются перед приращением или выходом, включая `continue`, `break` и `return`. Шаблоны, стандартные заголовки, контейнеры STL, структурированные привязки и инструкции инициализации C++20 пока не входят в это расширение. Нативная проверка требует CI реализующей ревизии.

## Установка и скалярный перевод

Используйте обычную установку NeverC со стандартными ресурсами. Фронтенд C++ и одобренные заголовки SDK встроены; отдельно устанавливать Clang не нужно. Подробности — в [инструкции сборки фронтенда](../../utils/translate-frontends/cpp/README.md).

```sh
neverc translate --from cpp input.cpp -o output.nc
neverc output.nc -c -o output.o
```

Профиль `cpp-core-v1` принимает один самостоятельный файл C++17 без include. Поддерживаются `int`, `unsigned int`, `bool`, `void`, тривиальные агрегатные типы, свободные функции, пространства имён, перегрузки и описанный поток управления. Проверяются все входные объявления, включая неиспользуемый код.

Выберите `--profile cpp-core-v2`, чтобы добавить проверяемые псевдонимы `typedef`/`using`, перечисления с поддерживаемыми целочисленными базовыми типами, `static_assert`, а также ограниченную поддержку указателей на объекты и lvalue-ссылок. Параметры и результаты по ссылке сохраняют связь с исходным объектом; поддерживаются нулевые указатели и вложенные квалификаторы `const`. Ограничения на один исходный файл без include сохраняются. См. [контракт core v2](../../utils/translate-frontends/docs/cpp-core-v2.md).

Core v2 также добавляет локальные массивы фиксированного размера и поля-массивы, многомерную индексацию, указатели и ссылки на массивы. При частичной инициализации пропущенные скалярные элементы обнуляются, а записи используют выбранную инициализацию; порядок и связи с исходным хранилищем сохраняются. Размеры и объём развёртывания инициализации ограничены. Глобальные массивы и массивы переменной длины пока не поддерживаются.

Core v2 поддерживает `switch`/`case`/`default`, включая операторы инициализации C++17, переход к следующему case и проверенные аннотации `[[fallthrough]]`. Выражение выбора вычисляется один раз; вложенные switch и циклы сохраняют цели `break`/`continue`. Диапазоны case GNU и другие атрибуты операторов отклоняются.

Core v2 поддерживает знаковые и беззнаковые целые шириной 8, 16, 32 и 64 бита, символьные типы и литералы, а также константные запросы `sizeof`/`alignof`. Продвижение целых и выбор перегрузок выполняются до нормализации; `long`, `wchar_t` и тип размера зависят от целевой платформы. Базовые типы перечислений также могут быть узкими и широкими. Строки времени выполнения и STL ещё разрабатываются.

Core v2 также поддерживает смещения и разность указателей на объекты, инкремент/декремент и составное присваивание, включая обход массивов и шаг многомерных массивов. Создаваемые вспомогательные функции сохраняют правила C++17 для прибавления и вычитания нуля из нулевого указателя и разности двух нулевых указателей. Сравнения порядка указателей, преобразования указатель/целое, контейнеры и алгоритмы STL пока не поддерживаются.

Core v2 сверяет размеры типов и выравнивание ABI с собственной моделью целевой платформы NeverC, включая размеры структур и смещения полей. Статические проверки в сгенерированном коде повторно проверяют размещение при компиляции; эти данные записываются в манифест.

Core v2 поддерживает именованные невиртуальные функции-члены поддерживаемых типов записей, включая const-перегрузки, методы с lvalue-квалификатором, статические методы и `this`. Вызов сохраняет идентичность исходного объекта и вычисляет объект-получатель до аргументов.

Core v2 поддерживает обычные пользовательские конструкторы записей со стандартной компоновкой и поддерживаемыми операциями копирования. Локальные объекты, поля и элементы массивов создаются в конечном хранилище; поля инициализируются в порядке объявления. Делегирование и исключения пока не поддерживаются.

Core v2 создаёт отдельный объект для каждого параметра-записи, передаваемого по значению, и записывает результат в хранилище вызывающей стороны. Правила действуют и для конструкторов и методов; необходимые копии и связи ссылок сохраняются. Для подходящих тривиальных типов другие реализации C++17 могут добавлять копии аргументов или результатов.

Core v2 поддерживает обычные пользовательские деструкторы и неявное разрушение членов при нормальном выходе. Локальные объекты, поля и элементы массивов разрушаются в обратном порядке; временные объекты — в конце полного выражения после сохранения нужных значений. Возвраты, ветвления, циклы, break и continue выполняют нужную очистку. Параметры по значению разрушаются при выходе из вызываемой функции; возвращаемые объекты принадлежат вызывающей стороне. Явные вызовы деструкторов, разрушение статических объектов и раскрутка стека исключениями пока не поддерживаются.

Core v2 выполняет обычные пользовательские конструкторы копирования и операторы копирующего присваивания с параметром-источником `R&` или `const R&`. Копирование использует реальный целевой объект и сохраняет побочные эффекты и возвращённую ссылку. Синтаксис присваивания сначала вычисляет правый операнд; явный вызов `operator=` сначала вычисляет объект-получатель.

Core v2 также поддерживает сгенерированные и явно default-конструкторы по умолчанию и default-деструкторы, включая вложенные записи и массивы полей. Конструирование использует реальное место объекта и порядок объявления полей; инициализация значением обнуляет их только по правилам C++. Отличия default-определений вне класса сохраняются. Неиспользуемым конструкторам и конструкторам только в невычисляемых выражениях не требуется искусственное тело.

Core v2 поддерживает неявные и явно default-конструкторы копирования для вложенных записей и многомерных массивов. Выбранные конструкторы полей работают в реальном месте назначения в порядке объявления и элементов; адрес исходного массива вычисляется один раз. Тривиальная копия сохраняет значения указателей. Передача по значению и возврат исходного объекта сохраняют эффекты копирования, а прямая передача prvalue не добавляет копий.

Core v2 также поддерживает неявное и явно default-присваивание копированием. Поля и элементы массивов сохраняют выбранные операции и порядок; сгенерированные тривиальные копии массивов становятся типизированными присваиваниями без внешнего вызова копирования памяти. Тривиальное присваивание сохраняет указатели и возвращает реальный объект-получатель. Синтаксис оператора сначала фиксирует ссылку на источник, явный вызов метода — получателя; значения источника читаются после этих эффектов. Присваивание не создаёт и не уничтожает дополнительные объекты.

Core v2 поддерживает инициализаторы полей по умолчанию для допустимых типов: обращения к предыдущим полям, обычные вызовы, вложенные записи и массивы. Выбранный инициализатор использует фактический объект как `this`; явные элементы инициализации агрегата сохраняют `this` вызывающего метода. Явная инициализация заменяет значение по умолчанию данного поля. Неявные/default копирование и присваивание не запускают его повторно; пользовательский конструктор копирования может выбрать его для пропущенных полей. Инициализация членов конструктора и агрегата сохраняет соответствующие границы уничтожения временных объектов. Шаблоны и полная STL остаются в разработке.

Core v2 поддерживает rvalue-ссылки на уже существующие живые объекты: псевдонимы скаляров, указателей, записей и массивов, ссылочные параметры и результаты, условные xvalue и обычные методы с квалификатором `&&`. `static_cast<R&&>(live)` сохраняет тот же объект; именованные переменные rvalue-ссылочного типа остаются lvalue. Перегрузки и существующее копирование следуют выбору Clang. Ссылки не создают дополнительной ответственности за уничтожение.

Core v2 выполняет обычные пользовательские конструкторы и операторы присваивания перемещения из живого источника `R&&` или `const R&&`. Конструирование использует конечное хранилище; присваивание сохраняет изменения источника, порядок вычисления и возвращённую ссылку `R&`, включая получателей с квалификатором `&`/`&&`. Именованные rvalue-ссылки выбирают lvalue-перегрузки, а явные конструкторы сохраняют правила инициализации. Перемещение не завершает жизнь источника: источник и результат уничтожаются обычным образом.

Core v2 также поддерживает неявные и явно default конструирование и присваивание перемещения для вложенных записей и многомерных массивов. Члены выполняют выбранное C++ копирование или перемещение в порядке объявления и элементов. Сгенерированные перемещения не повторяют инициализаторы полей; тривиальные операции сохраняют значения указателей. Источники уничтожаются обычным образом, а неиспользуемым или тривиальным сгенерированным операциям не требуется вымышленное тело.

Core v2 поддерживает разрешённые стандартные объявления `noexcept`, `noexcept(true/false)` и `throw()` из C++17, а также константные запросы `noexcept(expression)`. Запрос учитывает спецификации выбранных функций и деструкторов, не выполняя операнды. Все операнды и записанные спецификации проверяются и в неиспользуемом коде. Генерация и перехват исключений, раскрутка стека, шаблоны и полная STL остаются в разработке.

Core v2 поддерживает обычные перегруженные операторы-члены и свободные операторы: арифметику, сравнения, индексацию, разыменование, инкременты, функциональные объекты и общие сигнатуры присваивания. Сохраняются выбранные функции, ссылочные псевдонимы и объекты результатов. Операторная запись соблюдает порядок C++17; перегруженные логические операторы вычисляют оба операнда. Свободные операторы присваивания инициализируют параметры справа налево и разрушают их в обратном порядке. Шаблоны, выделение памяти и полная STL остаются в разработке.

Core v2 также поддерживает обычные функции преобразования живых объектов: неявные и явные целочисленные преобразования, перечисления и указатели, явный `bool` в условиях, ссылочные и объектные результаты. Каждое преобразование один раз вызывает выбранную функцию-член. Ссылки сохраняют псевдонимы; объектные prvalue напрямую инициализируют фактическое место назначения. Преобразование ссылки в значение сохраняет выбранное копирование или перемещение. Квалификаторы const и ссылок, constexpr и noexcept следуют C++17.

Core v2 теперь поддерживает временные объекты-получатели и временные скалярные/объектные аргументы по ссылке до конца полного выражения, включая конструкторы, методы, операторы и преобразования. Каждое вычисление использует реальное хранилище; объектный результат сохраняет конечное место назначения, а ссылка — свой псевдоним. После вызова и уничтожения параметров временные объекты уничтожаются в обратном порядке конструирования, в том числе в условиях и циклах. Поддерживаются массивы-подобъекты временных записей.

Core v2 теперь продлевает жизнь временных значений, связанных с обычными автоматическими локальными ссылками, включая `const T& r{T{...}}` и `T&& r = T{...}`. Скалярные значения, перечисления, указатели и записи получают реальное хранилище. Ссылки на поля или элементы массива сохраняют всю запись, если C++ предусматривает продление жизни. Инициализация фигурными скобками, в том числе после знака равенства, сохраняет тот же объект. Уничтожение следует области ссылки, включая условия, циклы и ранний выход; остальные временные значения инициализатора заканчивают жизнь вместе со своим полным выражением. Псевдонимы не создают владельцев, последующие копирования и перемещения сохраняют выбранные операции. Статические/глобальные/локальные для потока ссылки, ссылочные поля, шаблоны и полная STL остаются в разработке.

Core v2 также поддерживает отдельные временные массивы фиксированного размера в вызовах, преобразовании в указатель, индексации, отбрасываемых выражениях и автоматических локальных ссылках. Каждый массив имеет одно реальное место назначения; скалярные значения, конструкторы и общие инициализаторы по умолчанию заполняют элементы непосредственно и по порядку, без дополнительных владельцев. Если C++ продлевает жизнь, ссылки на строки или элементы многомерного массива сохраняют весь массив. Элементы уничтожаются в обратном порядке в конце полного выражения или области ссылки. Типизированные адреса и существующие ограничения размера, хранения и развёртывания сохраняются. Полная поддержка C++/STL остаётся в разработке.

Core v2 поддерживает пустые классы со стандартным размещением и объекты функций или преобразований без состояния. Пустые объекты сохраняют размер и выравнивание C++ по одному байту, отдельное хранение там, где оно требуется, выбранные конструкторы и операторы и обычное уничтожение. Тривиальные копии всё равно вычисляют операнды; пустые элементы массивов и содержащих записей учитываются в лимите хранения. Созданный NC использует внутренний байт, а список исходных полей остаётся пустым. Наследование, шаблоны и полная STL ещё разрабатываются.

Core v2 поддерживает преобразования в void, `void()` и `void{}`, допустимые псевдонимы void, вызовы, возвраты, выражения с запятой и условные ветви. Отбрасывание не-volatile lvalue сохраняет эффекты вычисления получателя и индекса без чтения хранимого значения. Временные объекты всё равно создаются и уничтожаются в конце исходного полного выражения. Переменные и значения void не генерируются. Операнды константных выражений и noexcept проверяются полностью. Объекты volatile, неподдерживаемые типы, шаблоны и полная STL остаются за рамками этого этапа.

Core v2 поддерживает аргументы по умолчанию для допустимых функций, методов, операторов вызова и пользовательских конструкторов, включая дополнительные параметры конструкторов копирования и перемещения. Имена разрешаются в месте объявления, а выражения вычисляются при каждом вызове с пропущенным аргументом. Идентичность и время жизни ссылок и значений сохраняются. Для элементов массива без инициализатора и сгенерированного копирования массива временные аргументы уничтожаются перед следующим элементом; явные инициализаторы сохраняют границу внешнего полного выражения. Неиспользуемые и заменённые явными аргументами выражения также проверяются. Шаблоны и полная STL ещё не завершены.

## Многофайловые проекты

Явно выберите единицы трансляции из базы данных компиляции и задайте корневой каталог проекта. Встроенный фронтенд анализирует каждую единицу отдельно; объединение проверяет определения, связывание, общие типы и соблюдение правила одного определения (ODR) с помощью консервативных проверок.

```sh
neverc translate --from cpp --profile cpp-project-v1 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/a.cpp src/b.cpp --out-dir generated
```

Проект создаёт `translated.nc` и `translated.h`. Допускаются только заголовки проекта внутри этого корневого каталога. Если у файла несколько конфигураций, выберите индекс базы, начиная с нуля, через `--compdb-entry src/a.cpp=4`. Сохранённые команды компилятора разбираются как данные и никогда не выполняются.

## Ограниченная математика двойной точности

`cpp-math-v1` добавляет к проектам `double`, документированные преобразования/сравнения и точные сигнатуры `std::fabs(double)` и `std::floor(double)`. Используются встроенные заголовки Clang 20.1.8 / libc++ 200100 / macOS 15.5; требуется явно указать цель macOS 15.0 (arm64 или x86_64). Общая арифметика с плавающей точкой пока исключена. Ловушки исключений должны быть замаскированы, а обнуление денормализованных чисел выключено; проверены все четыре стандартных режима округления.

```sh
neverc translate --from cpp --profile cpp-math-v1 \
  --target arm64-apple-macosx15.0.0 \
  --project-root "$PWD" --compdb build/compile_commands.json \
  src/math.cpp --out-dir generated-math
```

Математическая трансляция также проверяет установленные заголовки NeverC, идентичность встроенных реализаций и фактическую компоновку. Полученные модули используют среду выполнения NeverC. С `-fno-builtin-std` трансляция завершается ошибкой до записи файлов только тогда, когда итоговому коду нужны сопоставления `fabs`/`floor`. Математический код, которому они не нужны, по-прежнему можно транслировать.

## Проверка и результат

Используйте `--check` вместо параметра вывода для того же анализа, генерации, проверки синтаксиса и объектного кода без сохранения созданных файлов. `--report PATH` записывает структурированную диагностику. Перевод никогда не запускает исходную программу.

Результаты и сопутствующие файлы не перезаписываются. `--out-dir` требует новый каталог с существующим родительским каталогом, а `-o` — новый путь `.nc`. Манифест содержит требования целевой платформы, хеши входов и выходов и порядок компиляции; карта исходников связывает созданные строки с исходными позициями.

Результаты CI, проверок выполнения и установки, а также пропущенные тесты указаны отдельно для каждой платформы. Нативная macOS arm64 и macOS x86_64 через Rosetta остаются разными средами проверки. Заявленный объём поддержки не включает полный C++/STL, исключения, шаблоны, строки или `std::vector`. См. [матрицу поддержки](../../utils/translate-frontends/docs/support-matrix.md), [протокол и правила восстановления](../../utils/translate-frontends/docs/protocol.md) и [пример проекта](../../tests/neverc/Inputs/translate/cpp/project).
