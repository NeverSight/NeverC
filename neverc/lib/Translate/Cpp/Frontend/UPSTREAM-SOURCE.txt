NeverC builtin C++ frontend: upstream source and modifications

Release: LLVM/Clang 20.1.8 (llvmorg-20.1.8)
Source archive: llvm-project-20.1.8.src.tar.xz
URL: https://github.com/llvm/llvm-project/releases/download/llvmorg-20.1.8/llvm-project-20.1.8.src.tar.xz
SHA256: 6898f963c8e938981e6c4a302e83ec5beb4630147c7311183cf61069af16333d

The archive is fetched and verified during the NeverC build. An offline copy
can be selected with CMake's NEVERC_CPP_LLVM_SOURCE_ARCHIVE option; the same
SHA256 is required. No upstream executable or shared library is installed.

A checked private ASTConsumer.h/SemaTemplate.cpp/SemaTemplateDeduction.cpp patch
preserves source evidence for explicit function/static-member directives and
successfully converted scalar template defaults. Default no-op callbacks retain
each selected declaration, written type/arguments/name/qualifier/location and
attribute presence as applicable. Directive evidence precedes no-effect returns.
Default evidence follows successful CheckTemplateArgument in both argument-list
and deduction paths, preserving original and converted expressions plus the
canonical argument. Failed substitution/conversion keeps normal SFINAE behavior.
The three sources must all be pristine or fully rewritten, with duplicate,
partial, missing and drifted states rejected before any group member is changed.
NeverC bounds shared source evidence before retaining it and checks it after
semantic analysis without changing declarations, overload selection or flags.

A checked SemaInit.cpp patch resolves potentially lvalue-reference placeholder
conversion results before the reference-only candidate filter. It handles bare
decltype(auto) and unqualified bare auto&&, preserving lazy value-returning
template bodies, the existing reference filter and normal overload diagnostics.
The complete original or rewritten block must occur exactly once; missing,
partial, duplicate and drifted states fail before this file is changed. Independent
literal fixtures and paired semantic/runtime regressions cover the correction.

A separate checked SemaOverload.cpp patch applies the same ordering to fresh
reference arguments in FindConversionForRefInit. Result deduction precedes the
compatibility filter. Its direct reference-candidate search excludes written
non-function lvalue results from direct rvalue-reference binding. Later full
initialization still deduces results needed for indirect standard conversions;
an invalid competing auto& body retains its normal diagnostic. All original
category, explicitness, access and candidate-selection checks remain active.
Independent literal source fixtures cover exact output, idempotence and drift;
paired source/protocol and native O0/O2 cases cover fresh argument conversions.

The isolated build renames namespace llvm and selected global C/C++ symbols.
IsolateSymbols.py applies checked, idempotent changes to the extracted
IntrinsicInst.cpp, Debugify.h, and LoopUtils.cpp to isolate otherwise global
identifiers.
Six calls in Signals.cpp, APFixedPoint.cpp, and ConstantFolding.cpp explicitly
perform the same double promotions as the integer/mixed cmath overloads. This
avoids emitting shared global MSVC math templates while preserving getter
evaluation, integer negation, and the existing outer float/half conversions.
All three math sources are checked before any of those files is rewritten.
The same checked patch step corrects SemaAccess.cpp's effective-context walk
for friend functions declared in nested classes. C++17 [class.nest]/4 gives
these functions no implicit enclosing-class access; canonical function grants
still permit explicit friendship from their own or enclosing classes. Ordinary
nested member access and non-nested friend contexts are unchanged. The patch
checks original/rewritten source states and rejects partial or duplicate edits.
The supplemental declaration check keeps immediate nominated-name access
validation before redeclaration merging and rechecks only completed friend
functions with their canonical grants. A private DelayedDiagnostic flag leaves
type-friend and existing diagnostic behavior unchanged. Late-parsed nested
friend defaults use a matching temporary function scope/context, preserving
lexical lookup and restoring parser/Sema state afterwards. SemaAccess.cpp,
DelayedDiagnostic.h and ParseCXXInlineMethods.cpp are validated as one source
group before any supplemental rewrite; mixed or partial groups are rejected.
A checked DeclCXX.h/DeclCXX.cpp pair also propagates later namespace default
arguments through existing using declarations, as required by C++17
[dcl.fct.default]/9. It selects only a later declaration of the same non-template
function in the same semantic namespace with additional defaults. Lexical
block/friend declarations and different namespace default sets remain excluded;
new overloads are not imported. Both source states are validated before either
file is rewritten, with idempotent complete pairs and rejected partial pairs.
Other symbol changes use compilation definitions. NoCrashReporter.h disables
the private PrettyStackTrace.cpp Darwin process annotation; NeverC owns it.
On Windows, RewriteSetupCoffSymbols.py isolates five Setup COM GUID identities
in the aggregated COFF archive. It replaces each 42-byte GUID identifier with
an equal-length private ASCII name, including the exact observed MSVC template
and local metadata spellings listed in SetupGuidSymbols.py. The first linker
index keeps its order; the second index stably reorders name/member-index pairs.
Original member selection and duplicate multiplicity are preserved. Object
records, auxiliary slots, code, data, relocations and member offsets are compared
byte for byte; only the authorized name bytes and paired index ordering may
change. Unknown spellings, conflicting shared strings and changed GUID values
are rejected. The same private LLVM 20.1.8 nm/readobj independently inspect the
result, and the full no-host ABI audit runs before the final archive is replaced.
This is a build-time Python transformation, with no external Clang executable
or COFF writer required by the installed NeverC translator. Internal Clang
libraries remain statically included. The Windows CI contract retains separate
baseline/isolated SDK smart-pointer and deterministic COM runtime evidence;
it does not claim to test COM activation, VS discovery or private LTO behavior.
The exact scripts and compilation rules are part of the NeverC source tree at
neverc/lib/Translate/Cpp/Frontend and neverc/cmake/modules/BuiltinCppFrontend.cmake.

LICENSE.TXT contains LLVM's Apache 2.0 license with LLVM exceptions and legacy
notice. BLAKE3/LICENSE and NeverCCppThirdPartyNotices.txt retain the additional
notices for the statically included Support sources. The separate cpp-sdk
directory contains the exact header source snapshot, hashes, provenance,
generation script, and notices for the embedded C++ header distribution.
